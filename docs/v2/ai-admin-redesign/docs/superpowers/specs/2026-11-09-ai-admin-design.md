## 2. 全局工程与交互边界

- 沿Vue 3／TypeScript／Vite／Pinia／TanStack Vue Query、现有UI／CSS变量，保持蓝紫色、亮暗主题、清晰字体、轻边框与表格层级，不引入另一套设计系统或大型框架。
- 八页使用显式wide布局；安全／个人表单仍限制阅读宽度。不全局改main宽度，不重做已合并首页及其他页面。
- 保留当前导航、全局创建、模块宿主、深链接、SSE失效、CSRF、乐观并发、幂等、角色与workspace隔离；不把效果图中折叠的侧栏组固定为全站新缺省。
- 账户资料／会话是当前用户级；其他数据查询键带user/workspace/筛选/对象ID。切用户、换空间、失权及迟到响应不串数据。
- 保存按实体进行，表单draft与最近保存值分开。SSE／后台刷新不能覆盖未保存输入；发生version冲突提示重新载入／核对，不自动覆盖别人修改。
- loading、真空数据、error、stale、未配置、需要重连、MODULE_DISABLED分开；未知不是0，首屏数字不能用已加载第一页长度冒充全量。
- 密码、Token、客户端密钥、Webhook和密钥值只在输入时进入组件内存，提交／关闭／换对象清空；不入URL、缓存、浏览器持久化、日志或错误input。已保存值仅显示设置状态。
- 复制仅用于公开回调地址、资源ID等；存量凭证无回显／复制能力。外部文字按文本，JSON安全格式化，禁止innerHTML／执行远端指令。
- 刷新不等于测试连接、同步、测试推送、生成早报、发送邀请或批准；这些动作由用户明确触发，并按现有角色和状态校验。
- 390/768/1280/1440/1920，键盘、焦点归还、移动详情抽屉、亮暗与可读对比度均验证。

## 4. AI审批

### 4.1 首屏与详情
- 左侧待处理表，右侧详情；视图为待审批、全部调用、执行异常（failed/unknown）。工具、智能体、类型筛选用服务端全量条件。
- 新汇总为待审批、3分钟内到期、高危待审批、执行异常。默认范围最近24小时发起的调用，范围可选24h/7d/全部；卡片标明范围，重叠计数不相加。
- 只有pending_approval且expires_at>服务端当前时间才算有效待审批；即将到期与critical都是其子集。待审批按expires_at升序，活动按创建时间倒序。
- 提交参数只读，显示平台生成summary与脱敏arguments；无AI申请理由／前后值快照时不编造。支持工具专属可读字段和原始参数折叠，未知工具降级安全JSON。
- 展示发起智能体、acting身份、触发者、IM来源与inferred标志。来源推断不伪装成确定聊天证据；旧记录／被删实例保持历史名称与ID，不跳错对象。
- 链接目标信息若另行读取，只显示当前可读内容并标“当前信息”，不是申请时快照。参数摘要／哈希不是客户端已完成完整性校验的证明。

### 4.2 决策与结果
- 保留15分钟TTL与服务端最终判定，过期不延长；页面倒计时按summary.as_of校正时钟，归零禁用并重新读取，不在前端篡改状态。
- 批准使用If-Match及固定action_id，执行仍以实例原登记身份及原权限，不借审批人的高权限；参数不在审批页编辑。
- critical密码长度1–128，只写、每次尝试后清空；拒绝原因可选且≤500字符，拒绝不验证密码。规则说明只读，不增加批量通过或永久信任开关。
- 批准后展示executing/succeeded/failed/unknown真实结果；批准不等于执行成功。VERSION_CONFLICT／已处理／失权先刷新，不重复执行。
- 网络未知先GET同一记录，executing/unknown不提供盲目重试；可链接对应任务／日历页核实。read/knowledge/direct在全部调用中查看，不强制进入审批。
- 保持/ai?id=...与/approvals?id=...、IM审批卡片和通知跳转；IM回复“同意”仍不算批准。

## 5. 设置

- 个人资料：登录邮箱只读，显示名可改；头像用现有首字母，不新增未实现上传入口。
- 工作空间：改名称、显示本人角色，单独保存；不新增删除工作空间／转移owner。
- 成员表展示真实邮箱与角色，添加已存在账户或显式“同时创建账号”。创建账户需要原有显示名／初始密码规则；不把添加成员说成已发邀请邮件。
- owner不可修改／移除，admin不得变更admin；错误USER_NOT_FOUND、角色冲突、失权保持具体反馈。
- 右侧快捷入口指向原安全、导航、应用中心、首页布局导入／导出，不重复实现这些功能。

## 6. 集成设置

- 当前以GitHub为主，不新增虚假第三方连接卡，不恢复n8n。细粒度Token、仓库选择、启停、测试／同步按现有API。
- 最多20仓库，大小写去重；Token只接受现有github_pat_约束，留空保留原值，过期时间来自用户录入／服务端字段，不猜Token内容。
- 四项Metadata/Issues/Pull requests/Actions必须来自逐仓库实际核验结果或已有权限快照。复用已合并#179的GET developer/repos/{id}/permissions，不能从Repo.access=ok推导四项通过。
- 从未核验／只核验metadata的其他项显示未核验；标checked_at，Token／清单／启停变更按现有机制失效。
- sync.reason=rate_limited显示retry_at和合法缓存；unauthorized提示重连并清掉无权内容。测试连接、普通刷新、手动同步分别表达，不暗中替换动作。
- GitHub V1周期同步、Webhook不支持作为说明，不能画成一项全局连接故障。读API与修改连接权限保持。

## 7. 安全设置

- 当前用户改密码与自己的会话分栏。新密码12–128字符；确认新密码是前端校验，不改变后端请求shape。
- 修改成功撤销其他会话，当前会话保持登录。会话撤销按ID；撤销当前会话明确退出，不能多删或错误清掉另一用户缓存。
- SessionOut只有ID、created_at、last_seen_at、expires_at、current。显示当前／其他会话及时间，不能编造设备、操作系统、城市、IP或在线状态。
- 不新增MFA、安全评分、批量退出所有设备端点；本轮改善现有能力。账户级会话不因切工作空间混成管理别人的会话。

## 8. 邮件设置

- 多Gmail账户列表、需重连提示、所选邮箱详情、智能体分配与署名；新邮箱默认不分配任何实例。
- OAuth callback使用MailSettingsOut.redirect_uri，允许复制；client_secret只显示是否设置，不从示例URL／ID硬编码。client_secret留空保持原值。
- 每邮箱的can_read/can_send是实际授权范围，不能给需要重连的账号贴全部正常；status/last_error分别处理。
- 分配给实例后仍受该实例查询／发信开关约束，不能自动打开发送。署名与分配分别提交各自PATCH／PUT及当前account.version，冲突不覆盖其他设置。
- reconnect仍走Google选择账户与原回调；disconnect撤销授权、保留发件记录。切换邮箱清掉前一账号草稿，不把登录提示当发送身份。
- 只请求现有gmail.readonly＋gmail.send，不新增IMAP／Outlook或Gmail归档／删除／标已读；设置页不读正文／附件，不把邮件内容缓存到配置分析中。

## 9. 新闻早报设置

- 留在news模块与/settings/news，保留宿主停用导航／路由／事件行为；admin只读，owner写，模块停用与早报enabled是两层状态。
- 分组展示计划、来源、兴趣、模型与渠道、学习偏好。1–3推送时刻，半小时步长；timezone来自部署、只读。
- 保留TrendRadar汇总与智能体写早报两种方式；实例不存在／停用时提示，不偷选第一个智能体。高级模型设置不能误称在此修改了所选OpenClaw自身模型。
- 热榜选实际platform_choices，RSS、关键词／必含词／排除词、AI过滤失败回退、模型／翻译与所有原渠道设置保持。
- config_rev是文件生成次数，version是并发版本，不混用。图中“运行中的v12”改为“最近写入配置#12”；rendered_at不证明下一次任务已经用新配置运行。
- 保存成功／配置文件写失败／未部署／taken_by_other／连通未知分开；设置保存后按原下一次运行规则生效，不擅自抢占其他工作空间。
- 渠道“已配置”不等于发送已成功；测试推送与现在生成均是owner显式动作。dirty时先保存再测试／生成，防止使用旧收件设置；刷新只GET，不生成、不推送。
- learned是最近60天收藏／不感兴趣形成的偏好，保持原计算／建议，建议关闭来源不自动执行。敏感模型Key／Webhook只写不读。

## 10. 密钥库

- 表格＋详情＋取用记录，名称／说明服务端搜索、按三种kind过滤，跨所有分页匹配。匹配总数来自服务端，图中5不是第一页长度生成的全局统计。
- 保持model_api_key/api_token/generic；创建后类型不乱改。展示value_version、last_rotated_at、grants与ref_id，不显示／复制存量原值或历史值，不编造有效期。
- 轮换仍传新值＋当前version；value_version和乐观version区分，旧值按现有销毁／下发规则处理，不实现历史密钥恢复。
- 取用记录已有secret_id/instance_id/result服务端筛选，直接复用；not_found不区分未授权与不存在。source_ip只在原owner可见范围显示，不带入审计导出。
- 管理授权跳到对应智能体入口，不用“替换全部grants”顺手抹掉其他密钥授权。删密钥提示受影响实例，按原version保护。
- 密钥库仍保留模型密钥／API令牌功能，前一份服务器SSH密钥退役需求不适用于删除这里的全局密钥库。

## 11. 审计日志

- owner/admin的全空间时间线，按事件、操作者、对象与元数据看详情；新增服务端时间／操作者／事件／资源／关键词过滤和受控CSV导出。
- 所有筛选在分页前执行，不能仅搜索当前已加载页。未提供全量总数时显示“已加载N条”，不伪造总量。
- 审计没有通用执行结果字段，不能把“部署已发起”标成成功，也不能给所有记录贴成功／失败。未知事件保留原action。
- actor_id为空表示系统；解析不到当前可见成员则退回ID。对象名称只能在当前资源可读权限内补充并标“当前名称”，不当历史快照；admin不能借审计读取owner专属密钥信息。
- 详情复用存下的脱敏metadata。轮换只有新value_version时不补前后值；IP只存哈希且当前DTO不含它，不提供原IP／ip_hash／地理位置或完整业务payload。
- 导出与列表相同过滤／scope、同一截止时点；限制范围与行数，CSV防公式注入，No-store，不产生公开下载链接。见契约。
- 保持只追加存储与现有UPDATE保护；不提供删日志／改日志，不把数据库追加保护宣传成密码学不可篡改。
