# MCP 管理器优化：查看平台额度、额度用完后自动续跑（优化方案）

> 人类 2026-11-14 的两条新要求（T-0237）：
>
> 1. 某个会话的任务因为 5 小时的 token 限额被临时中断、停止时，MCP 管理器要能在额度重置后发送“继续意外中断的任务”，把这个任务重新启动起来。
> 2. 在 MCP 管理器上能看到各大模型平台的剩余额度和重置时间。
>
> 本文是方案，代码按它落实。它接在 `LLM_BRIDGE_QUEUE_PLAN.md`（限流、落库、队列、插入）之后，用的是那里的队列。

## 1. 各平台能拿到什么（锁定版本，2026-11-14 核对）

| 程序 | 额度信息从哪来 | 给出什么 | 核对到什么程度 |
|---|---|---|---|
| Codex 0.169.0（ChatGPT 与 Codex 共用） | `account/rateLimits/read`（随时可查）、通知 `account/rateLimits/updated` | 每个窗口的 `usedPercent`、`resetsAt`、`windowDurationMins`（主窗口通常是 5 小时，次窗口是一周）；套餐类型；额度用完时的错误类型 `usageLimitExceeded` | 生成的接口定义 |
| Claude Code 2.1.323 | 回合输出里的 `rate_limit_event`（带 `rate_limit_info`） | 状态（允许 / 快用完 / 被拒绝）、哪个窗口、重置时间、使用比例 | 只在程序文件里看到这两个名字；字段和取值没有账号、不能实测 |
| CodeBuddy Code 2.184.0 | **拿不到**（2026-11-15 更正，T-0242） | 类型定义里的 `SessionRateLimit`（`kind`、`percentUsed`、`resetsAt`）只在程序内部的扩展钩子里能读，`-p --output-format stream-json` 的回合输出里没有 `rate_limit_event`，本机服务也没有查额度的接口；它按积分计费，回合结果里只有 `usage`（token 数） | 锁定版本的程序文件；用真实账号跑过回合，页面上确实没有额度 |

两点要先说清楚：

- **三家给的都是“已用百分比 + 重置时间”，没有“剩余多少 token”这个数。** 页面如实显示“已用 62%，14:30 重置”；另外用管理器自己记的用量显示“最近 5 小时经这个管理器用了多少 token”作参考。
- **CodeBuddy 不给额度。** 页面照实写“官方程序不提供剩余额度和重置时间”，只显示经管理器用掉的 token（接口里 `reports_quota=false`）。
- **只有 Codex 能随时查。** Claude 的额度只在跑回合时由官方程序顺带报出来，所以页面上是“上一次回合时看到的”，带着时间；很久没跑回合时会标成“可能已过期”。

## 2. 查看额度

管理器新表 `quota_windows`：`platform`、`kind`（`five_hour` / `weekly` / 其他原样）、`used_percent`、`resets_at`、`status`（`ok` / `warning` / `exceeded`）、`plan`、`source`、`observed_at`。每个平台每个窗口一行，后来的盖掉先前的。

- Codex：打开页面、每个回合结束、收到更新通知时刷新；页面上有“刷新”。
- Claude / WorkBuddy：每个回合的输出里出现额度事件就记下来。
- 重置时间已经过去的窗口显示成“已重置（等下一次回合确认）”，不再显示旧的百分比。

接口：管理器 `GET /admin/quota`（`?refresh=true` 时向 Codex 实查一次）；状态里也带一份。工作台 `GET /api/v1/llm_bridge/bridges/{id}/quota`（owner / admin）。智能体的 `llm_bridge_status` 结果里多一段 `quota`（只读，方便它自己避开快用完的平台）。

页面：“管理器与账号”里每个平台的账号卡片上显示各窗口的进度条、重置时间（本地时间和“还有多久”）、数据是什么时候看到的；额度用完时标红并写“已暂停，HH:MM 自动继续”。聊天页的会话信息里显示这个会话所在平台的额度。

## 3. 额度用完后自动续跑

### 3.1 怎么认出“是额度用完”

一个回合失败时，满足下面任一条就算**额度中断**（新的失败种类 `quota_exceeded`，和普通失败分开）：

- Codex：错误类型是 `usageLimitExceeded`。
- Claude / WorkBuddy：回合里出现状态为“被拒绝”的额度事件；或者失败信息匹配官方程序的额度用语（“usage limit”“rate limit reached”“resets at …”“5-hour limit”等一组固定的模式）。
- 重置时间：优先用额度事件 / 接口给的；没有就从失败信息里解析“resets at / 重置于”后面的时间；都没有就按“5 小时后”估计，并在页面上标“估计”。

认不出来的失败照旧是普通失败，不会自动重发。

### 3.2 认出来之后

1. 这个回合记成 `interrupted`（中断，不是失败），带 `resume_at`（重置时间 + 60 秒的余量）。
2. **这个平台进入暂停**：到 `resume_at` 之前不再开始新的回合。排队中的消息留在队列里等，不会一条条去撞限额。别的平台不受影响。
3. 到时间后：
   - 先确认额度真的回来了（Codex 实查；Claude / WorkBuddy 直接试）。
   - 给**每个被中断的会话**发一条固定的消息（默认“继续意外中断的任务”，管理员可以改），排在这个会话队列的**最前面**；发送者记成“系统（自动续跑）”。然后恢复这个平台的队列，照常受“每个平台同时进行的会话数”和起跑间隔限制，不会一起冲出去。
   - 续跑的回合又被额度打断：重新算时间再等，同一次中断最多自动续 3 次（可调），超过后停下并在页面上标出来，等人处理。
4. 整个过程写进数据库，管理器重启后接着等、到点照样续。

### 3.3 人可以做什么

- 会话上显示“额度用完，14:31 自动继续”；可以点“现在就试”或“不要自动继续”。
- 中断期间手动往这个会话发消息：照常进队列，等平台恢复后按顺序处理；自动续跑的那一条仍然排在最前面。
- 设置（管理器的“设置”里）：“额度用完后自动继续”开关（默认开）、续跑时发的那句话、最多自动续几次。
- 关掉开关时：只暂停平台、到点恢复队列，不替人发“继续”。

### 3.4 不做的和边界

- 只处理**额度**造成的中断。超时、平台报错、人点的停止，都不自动重发。
- 不代替人回答模型提出的问题：续跑只发那一句固定的话。
- 周额度用完（重置在几天后）同样处理，但页面会明确写出日期；超过 24 小时的等待，到点前不占任何资源。
- 智能体发起的会话被中断：同样自动续跑；智能体用 `llm_bridge_turn_get` 看到的是 `status=interrupted`、`resume_at`，以及续跑回合的编号，它不需要自己重发。

## 4. 数据与接口小结

- 管理器：`quota_windows`（新表）；`turns` 加 `resume_at`、`resume_attempt`、`resumes_turn_id`；`platform_pauses`（平台、到什么时候、原因）。启动时自动迁移。
- 管理器接口：`GET /admin/quota`、`POST /admin/turns/{id}/resume`（现在就试）、`DELETE /admin/turns/{id}/resume`（不要自动继续）、设置里三项。
- 工作台：对应的三个接口（owner / admin，写操作带 CSRF、记审计）、状态里的额度、聊天页和管理页的显示。
- 智能体：`llm_bridge_status` 带额度；回合状态多 `interrupted`。没有新的写工具。

## 5. 安全

- 自动续跑发的是管理员定好的固定文字，不拼接任何模型输出；记审计（`chat_auto_resumed`），会话里能看到是系统发的。
- 自动续跑不绕过检查：账号一致性、会话是否已归档、管理器是否停用、平台是否还被勾选，任何一项不满足就不发，并标出原因。
- 额度信息里没有凭据；套餐类型只给 owner / admin 看，不给智能体。

## 6. 测试与验收

- 管理器：仿真驱动和仿真命令行加“额度用完”的两种表现（错误类型、额度事件 + 文字），测认出、暂停平台、到点续跑、续跑顺序、次数上限、关掉开关、重启后继续、手动“现在就试 / 不要继续”；额度窗口的记录与过期。
- 工作台接口与页面测试；浏览器验收：额度卡片、会话上的“自动继续”提示。
- **需要真实账号才能验收的**：Claude / WorkBuddy 额度事件的真实字段、三家“额度用完”的真实表现。实现里把解析做成宽松的（认字段名的几种写法），认不出时退回“普通失败 + 页面上手动继续”，不会误发。

## 7. 取舍

- 显示的是百分比，不是剩余 token 数——平台不给这个数，我不编。
- Claude / WorkBuddy 的额度是“最近一次看到的”，不是实时的。
- 自动续跑默认打开：这是你要的行为；它只在明确认出额度中断时才发，一次中断最多续 3 次。
- 平台暂停期间排队的消息会一直等到重置；等不及可以取消。
