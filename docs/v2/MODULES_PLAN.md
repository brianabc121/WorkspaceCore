# 插拔式扩展方案（T-0158 ~ T-0162）

> 依据：人类 2026-11-08 的设计文档《工作台插拔式扩展设计》（Claude Docs，https://claude.ai/artifact/AqLi7VYg8UaQVmpWxfibmj）
> 与指令「给我根据这份方案进行落实代码。同时给我补充好文档，方便未来的 agent 新增功能的时候能够直接读文档进行插拔操作」。
> 架构决定见 `docs/decisions/2026-11-08-feature-modules.md`；**新增功能的操作步骤见 `docs/modules/README.md`**。

## 1. 目标

1. 新增一个功能只加两个文件夹（后端、前端）并在注册表里各登记一行，不再改一堆公共文件。
2. 每个功能按工作空间启用、停用、配置，都在网页上完成；部署只管“外部服务装没装”。
3. 功能的界面可以放在五个位置：工作空间里的页面、“应用”或自定义分组下的二级页、设置里的子页、首页小组件、
   只给智能体的工具（没有界面）。人类说的“插件”和“二级分类页”是同一个模块选了不同的位置。
4. 停用不丢数据，再启用就恢复；删数据是单独的、要二次确认的操作。
5. 安全规则不因插拔放松：工作空间范围 + 角色校验、智能体审批、脱敏、出站策略都由宿主统一执行。

明确不做：运行时从网上下载代码装进 API 进程的“插件市场”；微前端与微服务拆分；改第三方产品的数据库；
一次性把所有现有功能都改成模块。

## 2. 三种扩展方式

| 方式 | 适合 | 状态 |
| --- | --- | --- |
| 内置模块（代码在仓库里，进程内运行） | 绝大多数新功能 | 已实现（T-0159），新闻早报已迁成模块（T-0160） |
| 零代码页面（外部链接、站内页面、知识库笔记、仪表盘、嵌入页） | 只是聚合已有信息或放一个入口 | 已实现（T-0161） |
| 外部应用（独立容器，按权限申报接入） | 别人写的、别的语言写的、不想放进仓库的服务 | T-0162，等第一个真实需求再做 |

新闻早报是“内置模块 + 外部服务”：模块代码在仓库里，TrendRadar 照旧在独立的 Compose 项目里。

## 3. 业内参考（方案文档第 2 节的结论）

VS Code（`contributes` 贡献点、`activationEvents` 按需加载、`engines` 兼容版本）、Backstage（扩展挂在宿主的附着点、
在配置里逐个开关）、Grafana（`plugin.json` 声明页面与角色）、Home Assistant（`manifest.json` + 网页配置流程 + hassfest 校验）、
Odoo（`depends` 与桥接模块）、Atlassian Forge 与 Saleor（外部应用的权限申报、挂载点、权限变更要重新确认）、
Shopify（模块化单体 + CI 检查边界）。共同点：清单先行、扩展点归宿主、开关不改代码、两档信任、兼容范围写进清单、CI 守门、
先模块化单体再谈拆分。

## 4. 人类没有填写的决定（按方案建议执行）

方案文档第 12 节的 D1~D7，人类在要求落实时没有另行决定，按当时的建议执行；以后要改，告诉 claude 即可。

| # | 决定 | 执行的做法 |
| --- | --- | --- |
| D1 | 启用的粒度 | 按工作空间 |
| D2 | 停用后的数据 | 保留；删数据是单独、要二次验证的操作（尚未实现，见第 6 节） |
| D3 | 谁能启用、停用模块 | 只有 owner；admin 在应用中心只读 |
| D4 | 外部应用什么时候做 | 等第一个真实需求（T-0162 未认领） |
| D5 | 外部应用的界面 | 界面描述为主、允许带沙箱的 iframe（T-0162 时实现） |
| D6 | 外部应用的智能体写工具 | 默认走审批；免审批由人类逐条批准，写成 V2 规则的“例外” |
| D7 | 侧栏新增“应用”分组、允许 owner 自定义分组 | 同意（“应用”分组在 T-0159，自定义分组在 T-0161） |

与方案原文的一处差别：**部署前提只提示、不阻止启用**（原文是“满足后才能启用”），原因见 ADR 第 6 条。

## 6. 已知的后续工作

- 应用中心的“清除数据”（D2）：需要每个模块声明自己的数据表与导出方式，等第一个需要它的模块一起做。
- 智能体实例上按模块的权限开关（方案里的 `agent_permission`）：现在模块工具按“模块启用 + `tools_visible`”控制，
  邮件、运行服务器等实例级开关仍是各自的字段；迁移这些功能时再统一。
- 模块的设置还放在模块自己的表里（新闻早报的 `news_settings`）；通用的“按 JSON Schema 自动生成设置页”等第二个需要它的模块。
