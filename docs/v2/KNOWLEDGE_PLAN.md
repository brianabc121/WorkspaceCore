## 0. 一句话

工作台自建一个 Markdown 知识库：
- 按“公共 / 项目 / 智能体”分库，人和智能体都能直接编辑；
- 笔记之间用 `[[链接]]` 连成知识图谱；
- 智能体通过工作台的 MCP 工具读、写、改、删，**不用审核**。代价由下面几道保护承担：每次改动留版本、可以一键撤销；删除进回收站；发现密钥直接拦下；删除过多自动暂停。

## 2. 现状

### 2.1 知识库
- 现在只有 **AFFiNE 书签**，没有正文：
  - 表：`knowledge_sources`、`bookmarks`、`resource_links`，迁移 0007 建立；
  - 代码：`app/models/knowledge.py`、`app/domain/knowledge.py`；
  - 前端：`apps/web/src/pages/KnowledgePage.vue`，页面上写着“工作台只保存书签元数据，不抓取文档正文”。
- 深链接只做字符串校验，从不请求 AFFiNE（`app/domain/deeplinks.py`）。

### 2.2 项目
- `projects` / `tasks` 由工作台自管（T-0082）。
- 单人版：**没有项目成员**，角色按工作空间算（viewer / member / admin / owner）。
- 项目和 OpenClaw 实例之间**没有任何关联**。

### 2.3 智能体
- **一个 OpenClaw 实例就是一个智能体**（`agent_instances`）。
- 智能体通过 `POST /mcp` 调用工作台工具，用实例令牌认证，外网实例还要双向证书。
- 工具分 `read` / `write` / `critical` 三级（`app/schemas/ai_tools.py`）：
  - **写和高危工具现在一律先建一条待审批记录**，15 分钟过期，每个实例最多 20 条；
  - 高危的还要人输入密码（`app/domain/ai_tools.py`）。
- 每次调用都记进 `ai_tool_executions`。

### 2.4 搜索
- `search_documents` 由数据库触发器维护：英文用 `tsvector`，中文用 `ILIKE` 按字面包含，标题有 `pg_trgm` 索引。
- 没有中文分词，没有向量检索（Postgres 镜像是 `postgres:16.15-alpine3.24`，没有 pgvector）。

### 2.5 OpenClaw 自己的记忆（来自 2026.9.36 文档，未在实例上核验）
- 记忆是 OpenClaw 工作区里的 Markdown 文件：
  - `MEMORY.md`：长期记忆；
  - `USER.md`：用户偏好；
  - `memory/YYYY-MM-DD.md`：每日笔记。
- 相关工具：`memory_search` / `memory_get`。
- 后台的 dreaming 定时整理记忆，有来源分级：owner / agent / untrusted / system。
- 自带的 `memory-wiki` 插件能编出一个兼容 Obsidian 的 wiki。
- 这些都在各自的服务器上。按 `TRANSFORMATION_PLAN.md`：
  - 工作台**不调用** OpenClaw 的 hooks 或 OpenAI 兼容接口；
  - OpenClaw 的会话和记忆由它所在的服务器自己备份；
  - 实例检查清单要求不装其他插件和技能。

## 3. 设计

### 3.1 三类知识库（即“分组”）

| 类型 | 什么时候建 | 人 | 智能体 |
|---|---|---|---|
| 公共知识库 | 每个工作空间一个，迁移时建 | viewer 读；member 及以上编辑 | 所有智能体默认读写，可以改成只读 |
| 项目知识库 | 建项目时自动建（已有项目在迁移时补建） | 同上 | 只有“参与的智能体”能读写（3.2） |
| 智能体知识库 | 登记 OpenClaw 实例时自动建（已有实例在迁移时补建） | 同上 | 它自己读写；其他智能体默认只读，可以关 |

补充规则：
- 项目归档时，知识库变成只读。删除项目时，知识库**不跟着删**：转为“已归档的知识库”，由人决定是否删除。
- 删除实例时同样处理：知识库保留为只读归档。
- 知识库里面用文件夹和标签再分组，例如“决策”“操作手册”。
- 知识库设置（智能体权限、开关）只有 owner / admin 能改。

### 3.2 项目与智能体的关系（新增）

- 新表 `project_agents`：`project_id`、`instance_id`、`access`（`read_write` | `read`）、`added_by`、`created_at`。
- 在项目知识库页的“参与的智能体”里由 owner / admin 添加或移除。
- 这张表决定三件事：
  - 哪些智能体能读写这个项目的知识库；
  - 工作台要把哪个项目的简报交给谁（3.10）；
  - 以后可以用来给任务分派智能体。

### 3.3 笔记

**正文**
- Markdown（UTF-8）。单篇上限：人写 256 KB，智能体每次写入 20 KB。

**属性**：存在表的列里，不写在正文里。
- 标题、别名；
- 类型：概述、项目简报、决策、规范、流程、操作手册、经验、复盘、偏好、术语、记录、计划、风险、设计、模板；
- 标签、文件夹、复核日期、置顶；
- “人已确认”标记，以及确认人和时间。

**来源**：由服务端写，正文里的文字改不了它。
- 谁建的、谁最后改的，分人和智能体（哪个实例）。
- 智能体写入时**必须给原因**。
- 依据：任务、项目、其他笔记的 id，或 IM 会话 id + 消息 id。**只存 id，不存对话正文**，符合规范 1.2“工作台不保存对话正文”。
- 智能体声明的来源类型：观察、任务结果、对话、外部资料。“外部资料”在检索时降权，并带“外部来源”标记（3.8）。

**版本**
- 每次保存一个新版本，存全文快照、改动行数、作者和原因。
- 同一个人 10 分钟内连续保存，合并成一个版本。
- 并发用乐观锁：人改带 `If-Match`，智能体改带 `base_version`；版本不对返回 409 和最新版本。

**链接**
- 保存时解析下面这些写法，存进 `knowledge_links`：
  - `[[标题]]`；
  - `[[知识库/标题]]`；
  - `[[标题|显示文字]]`；
  - `[[标题#小节]]`。
- 指向不存在的笔记也记下来，显示为“未建立的笔记”，点一下就能新建。
- 也能链接工作台里的任务、项目和 AFFiNE 书签（用 `/` 菜单插入）；它们在图谱里是灰色节点。
- 改名时旧标题自动变成别名，已有链接不会断；编辑器会提示“把 N 处链接改成新标题”。

**图片**
- 粘贴即上传，沿用 IM 图片的对象存储与校验（类型、大小）。
- 外部图片不自动加载。

**删除与撤销**
- 删除只是放进回收站，30 天后由 worker 彻底删除。
- 恢复时，链接一起恢复。
- “撤销”就是把某次改动退回上一版：生成一个新版本，不改写历史。
- 清空回收站只有人能做。

### 3.4 笔记编辑器

**格式**
- 存储格式定为 Markdown：智能体读写最方便，也能整库导出给 Obsidian 用。
- 编辑器只用来编辑这份 Markdown 源码，不另存一份富文本。

**编辑器**
- 首选 CodeMirror 6（加 Markdown 语言包）。
- 三种模式（效果图“笔记编辑器”）：
  - 编辑：源码，带语法高亮；
  - 分屏：左源码，右预览；
  - 阅读：渲染后的页面。
- Obsidian 式“边写边渲染”可以作为第二步。

**渲染**
- 用 markdown-it 转成 HTML，再用 DOMPurify 消毒。
- 笔记可能是智能体写的，一律按**不可信内容**渲染：
  - 不允许原始 HTML；
  - 不允许 `javascript:` 链接；
  - 外链图片不自动加载。

上面提到的库，版本和许可证在 K-0 核验，写进 `docs/versions.md`。

**功能**
- 工具栏和快捷键：标题、粗体、斜体、删除线、列表、任务列表、引用、代码、表格、链接、图片、撤销。
- 补全：
  - `[[`：在你能看到的所有知识库里搜标题和别名；
  - `#`：标签；
  - `/`：插入任务、项目、书签、表格、图片。
- 右侧属性栏：知识库、类型、标签、复核日期、“人已确认”。另有大纲和字数。
- 保存：
  - 停顿后自动保存，草稿先存在浏览器里；
  - 点“完成”或按 ⌘S 保存一个版本；
  - 关页面前有未保存的内容，会提醒。

**并发**
- 你编辑时，别人或智能体保存了新版本，顶部出现横幅：“ops-claw 保存了第 5 版……”，可以选“查看差异”或“合并它的改动”。
- 合并按共同的基础版本做三方合并；合并不了就并排显示，让人选。

**移动端**
- 以阅读为主。
- 编辑用 Markdown 文本框加简化工具栏。

**不做**
- 多人实时协同编辑（规范 1.3 仍不做）；
- 块编辑器；
- 数据库视图。

### 3.5 知识图谱

**节点**
- 节点是笔记，大小按链接数。
- 颜色按知识库类型：项目蓝、智能体橙、公共绿。
- 配色用 dataviz 的检查脚本在亮色和暗色背景上都测过；颜色旁边总有文字图例，不只靠颜色区分。
- 可以打开标签节点，以及任务、项目、书签节点（灰色）。

**边**：`[[链接]]`；可以加上“同标签”的连线。

**交互**
- 悬停高亮相连的笔记，其他的变淡；点一下在右侧看详情。
- 筛选：按知识库、笔记类型、作者（人 / 哪个智能体）、修改时间。
- 搜索定位、孤立笔记开关、缩放平移。
- 局部图谱：一篇笔记周围 1–2 层。

**实现**
- 接口：`GET /api/v1/knowledge/graph`。
  - 按调用者的读权限过滤；
  - 一次最多 2000 个节点，超过时按最近修改和链接数截断，并提示用户。
- 前端用 d3-force 算力导向布局（版本在 K-0 核验）：
  - 放在 Web Worker 里算，结果按知识库缓存；
  - 节点少时用 SVG 画，节点多时用 Canvas。
- 可访问性：图谱旁边有同样筛选条件的**列表视图**；键盘可以逐个节点浏览。

### 3.6 检索（给人和智能体用）

**第一期**
- 沿用 `search_documents` 的触发器方式，把笔记的标题、别名、正文加进去。
- 中文继续按字面包含匹配，标题用 `pg_trgm`。
- 排序：
  1. 人已确认的；
  2. 当前项目的；
  3. 自己的；
  4. 公共的；
  5. 最近修改的。
- 返回命中片段。

**以后**
- 中文分词（规范 5.3 提到 PGroonga 或应用层分词）和语义检索（pgvector + 嵌入模型）先不做，见第 12 节第 6 条。
- 语义检索要换数据库镜像，还要一个嵌入模型和它的密钥（放在工作台密钥库）。

### 3.7 智能体工具（MCP）

在现有的 `myworkspace` MCP 服务上增加：

| 工具 | 作用 | 等级 |
|---|---|---|
| `knowledge_search` | 在它能访问的知识库里检索：关键词、知识库、类型、标签、条数 | 读 |
| `knowledge_get` | 读一篇：按 id 或“知识库 + 标题”。返回正文、属性、版本号、链接、反向链接、来源标记 | 读 |
| `knowledge_list` | 列出知识库、文件夹、最近修改的笔记 | 读 |
| `knowledge_brief` | 取某个项目的简报，并记下它读到的版本（3.10） | 读 |
| `knowledge_write` | 新建或修改。参数：知识库、标题、正文、类型、标签、原因（必填）、依据；修改时必填 `base_version`；幂等键必填 | 知识库写（新等级） |
| `knowledge_delete` | 删除，进回收站。参数：笔记、原因、`base_version`、幂等键 | 知识库写（新等级） |

**新等级“知识库写”**
- **不进审批队列**，由工作台直接执行。
- 但每次调用照样过下面这些检查：
  - `AiToolService.check`：实例 scope 要 `read_write`，有效角色要 ≥ member；
  - 知识库访问规则（3.1、3.2）；
  - 限流、密钥扫描（3.8）；
  - 记录：`ai_tool_executions`、`audit_logs`、笔记版本。

**幂等**
- 同一个幂等键重复调用，返回第一次的结果。
- 智能体遇到超时、不知道写没写成功时，用同一个键重试，不会写两次。

**读工具的结果**
- 正文按“不可信数据”交给智能体：OpenClaw 已对 MCP 结果做不可信包装，见 OC-0 核验 M3。
- 带上来源标记：人写 / 智能体写、人已确认、有冲突、外部来源。

**不给智能体的操作**
- 彻底删除、清空回收站、恢复；
- 改知识库设置、改参与的智能体、改别的智能体的开关。

**其他工具**
- 任务、日历、自动化等**其他写工具的审批规则不变**。
- 不放宽 OpenClaw 的工具限制：只是在工作台的 MCP 服务上多了几个工具，不开 exec，不挂 Docker socket。

### 3.8 不审核之后的保护

人类决定智能体改知识库不再审核。审核原来承担的安全作用，改由下面这些措施承担：

1. **权限边界不变**
   - 工作台仍是唯一的权限来源。
   - 每次调用都校验工作空间、实例 scope、有效角色、知识库访问规则。
   - 别的工作空间的知识库查不到，也不会出现在图谱里。
2. **都能退回**
   - 每次修改留一个版本，“撤销”一键回到上一版。
   - 删除进回收站，保留 30 天。
   - 彻底删除只有人能做。
3. **密钥直接拦下**
   - 写入前做扫描：复用现有脱敏规则，再加常见格式（各类访问令牌、云密钥、私钥块、JWT、`password=` 之类）。
   - 命中就拒绝保存：原文不入库，也不出现在日志里。
   - 返回的错误提示智能体：改写成密钥库里的密钥名。
   - 依据：AGENTS.md 第 8 节第 6 条。
4. **限流与自动暂停**
   - 默认上限，每个实例：每小时写 20 次、删 5 篇，每篇 20 KB；每个知识库还有总量上限。
   - 删除超过上限时，自动暂停这个实例的删除（写和读不受影响），并通知管理员：通知中心 + IM 工作台通知。
   - 每个智能体都有“允许写入和删除”开关，关掉后只能读。
5. **来源看得见**
   - 智能体写的笔记标“智能体写入”；人确认后标“人已确认”。
   - 检索时人已确认的排在前面。
   - 图谱和列表都能按来源筛选。
6. **冲突与重复只提醒、不阻止**
   - 写入后后台检查：同名、标题高度相似、和“决策”“规范”类笔记明显矛盾。
   - 第一期只查同名和标题相似。矛盾检测要用模型，放到以后（第 13 节）。
   - 发现问题就在变更记录里提醒，两篇都带“有冲突”标记，直到有人处理。
7. **防“记忆污染”**：笔记是数据，不是指令。
   - 读工具的结果按不可信内容包装。
   - 来源是外部资料的，检索时降权。
   - 工作台不会把笔记自动塞进智能体的提示词。唯一的例外是人写的项目简报，而且也是由智能体用工具主动去取。
8. **全部可查**
   - “变更记录”页按时间列出每次改动：谁、什么时候、改了什么、为什么，能直接撤销或恢复。
   - 同时写进 `audit_logs`。

这偏离了 `docs/AGENTS.md` 第 8 节第 9 条和 V2 补充规则“写操作必须经工作台审批”，要按第 11 节修订条文。

### 3.9 智能体的“自我感知”与自我提升

先说清楚：智能体没有真正的自我意识。工作台能做的，是让它**在对的时机检索和写入**，并且**把人的反馈交还给它**。按下面这个循环做（效果图“智能体知识库”）：

**1. 接任务前先查**
- MCP 服务的说明和 `knowledge_*` 的工具描述里写明规则：
  - 处理某个项目的任务前，先调 `knowledge_brief` 和 `knowledge_search`；
  - 处理任何任务前，先查自己的知识库。
- 智能体用 `get_task` 读到一个有知识库的项目里的任务时，结果里附上简报的最新版本号；它还没读过这一版，就提示它去读。
- **K-0 核验结果**：OpenClaw 2026.9.36 不把 MCP 服务的说明（`instructions`）交给模型；工具描述会交给模型，但先清洗，超过 1200 个字符就截断。
  所以规则写进 `knowledge_*` 的工具描述，每条不超过 1200 个字符；完整的写入准则写进每晚复盘任务的提示词（下一条）。不改智能体工作区里的说明文件。

**2. 做完复盘，有三种触发方式**
- 智能体按工具说明，在完成任务、发出结果后自己复盘；
- 每天 22:00 的 OpenClaw 定时任务，提示词让它回顾当天、整理知识。
  K-0 核验结果：智能体自己不能建定时任务（接入包的工具策略禁用了 `group:automation`）；定时任务要由运维身份用 `openclaw automations add` 命令建，`--session isolated --message <提示词>`。
  所以由工作台的 SSH 部署在安装、升级时建好（已有同名任务就跳过），手工部署的照 CHECKLIST 执行同一条命令；
  在 CI 的真实 OpenClaw 上验证；
- 人在 IM 里对它说“复盘一下”。

工作台不调用 OpenClaw 的 hooks，也不调它的 OpenAI 兼容接口（`TRANSFORMATION_PLAN.md` 的“不做”清单）。

**3. 写入准则**：放进工具说明，按 OpenClaw 记忆文档里“什么值得记”的思路整理。
- 写：
  - 验证过的事实和操作步骤；
  - 做过的决定和原因；
  - 踩过的坑和解决办法；
  - 人的偏好（附上原话的来源）；
  - 项目约定。
- 涉及“什么时候能做、要谁批准、什么时候失效”的，写清楚条件。
- 不写：
  - 密钥、个人信息、闲聊、对话全文；
  - 没验证的猜测（要写就标“待确认”）。
- 写之前先检索，已有就改原来那篇，不重复新建。
- 适合大家用的，写进项目或公共知识库。

**4. 把纠正交还给它**
- 人修改或撤销智能体写的内容时，工作台把改动和原因写进这个智能体知识库里的《收到的纠正》（系统维护的笔记）。
- 它下一次调用知识库工具时，结果里会提示有新的纠正。
- 复盘时它先读这一篇。

**5. 指标**（智能体知识库页）
- 自己的笔记数；
- 写进项目和公共的次数；
- 接任务前查了知识库的次数；
- 检索后读取的笔记数；
- 被其他智能体读取的次数；
- 被人修改或撤销的次数；
- 过了复核日期的笔记数。

**和 OpenClaw 自带记忆的关系**
- OpenClaw 的 `MEMORY.md`、每日笔记、dreaming 保持不变，作为它在本机的私有工作记忆。
- 工作台知识库是**跨服务器共享、人能编辑、可审计**的那一层。
- 两边不同步：工作台从不主动连 OpenClaw，也不装 `memory-wiki` 之类的插件。
- 哪些结论值得共享，由智能体自己判断，再用工具写进工作台。

### 3.10 项目认知对齐

**项目简报**
- 每个项目知识库有一篇置顶的“项目简报”。模板：目标、已定的事、规矩、分工、别做。
- 推荐**只有人能改简报**（第 12 节第 2 条）。它是所有参与智能体的共同出发点。

**谁读过最新简报**
- 智能体调 `knowledge_brief` 时，工作台记下它读到的版本。
- 简报更新后，项目知识库页显示谁还没读最新版（效果图里的 doc-claw）。
- 点“现在发给它”，工作台通过 IM 给它发一条提醒，只带链接和标题，内容仍由它用工具去取。
- K-0 核验结果：接入包里 IM 渠道的 `inboundWhitelist` 只放行管理员的 IM 账号，工作台通知账号发的私聊会被忽略。
  所以这条提醒由管理员点按钮、**以管理员自己的 IM 账号**发出（和他在消息页里手动发一样）；工作台从不自动替管理员发消息。

**决策笔记**
- 类型为“决策”的笔记用固定结构：背景、决定、原因、日期、谁定的。
- 冲突提醒以它为准。

**共用一个知识库**
- 同一个项目的所有智能体共用这个项目知识库。
- 每个智能体做了什么，在“变更记录”和项目页的“最近的变化”里都看得到。

### 3.11 页面

**独立页面**
- `/knowledge` 改为独立页面，和 `/im` 一样不显示工作台侧栏和顶栏。
- 左侧功能条：返回工作台、笔记、知识图谱、项目知识库、智能体知识库、变更记录、设置。

- 颜色沿用工作台的主题变量，亮暗两套；文字对比度不低于 4.5:1。

## 4. 数据模型（迁移 0024 起，全部新增表，不改已有数据）

| 表 | 主要字段 |
|---|---|
| `knowledge_spaces` | `workspace_id`、`kind`（public / project / agent）、`project_id`、`instance_id`、名称、说明、智能体默认权限、`archived`、`version`。约束：每个工作空间一个公共库；每个项目、每个实例最多一个 |
| `project_agents` | `project_id`、`instance_id`、`access`、`added_by`、`created_at`，联合唯一 |
| `knowledge_notes` | `space_id`、文件夹、标题、别名、正文、类型、标签、复核日期、置顶、人已确认（人、时间）、创建者与最后修改者（人或实例）、来源类型、冲突标记、`version`、`deleted_at` / `deleted_by` / `purge_after`、时间戳。唯一：同一知识库里未删除笔记的标题（忽略大小写） |
| `knowledge_note_revisions` | `note_id`、`version`、标题、正文、属性快照、作者（人或实例）、原因、依据（只存 id）、改动类型（create / update / delete / restore / revert / rename）、`created_at` |
| `knowledge_links` | 源笔记、目标笔记（可空）、目标文字（未建立的笔记）、目标资源（任务 / 项目 / 书签，可空）、种类 |
| `knowledge_attachments` | `note_id`、对象存储键、类型、大小、上传者 |
| `knowledge_brief_reads` | `project_id`、`instance_id`、最近读到的简报版本、时间 |
| `knowledge_read_stats` | 按天汇总的读取次数：实例、笔记、次数（不逐条记录读取） |
| `knowledge_guard_events` | 被拦下的写入、自动暂停、限流：实例、种类、说明（不含密钥原文）、时间 |

- 笔记加进 `search_documents` 的触发器。
- 迁移时补建：每个工作空间的公共库，已有项目的项目库，已有实例的智能体库。
- 降级迁移删除新表。
- 数据在 Postgres 和对象存储里，现有的备份和恢复校验都覆盖到；`restore-verify` 增加笔记数和版本数的核对。

## 5. 接口（`/api/v1/knowledge/...`）

沿用现有约定：会话 + CSRF；修改带 `If-Match`；写操作有幂等键；每个接口都校验工作空间和角色。

- 知识库：
  - 列表、详情、设置；
  - 参与的智能体：增删改；
  - 智能体写入开关。
- 笔记：
  - 列表与筛选、详情、新建、修改、删除；
  - 版本列表、版本差异、撤销到某一版；
  - 改名（旧标题留作别名）；
  - 反向链接、局部图谱。
- 回收站：列表、恢复、彻底删除（owner / admin）。
- 图谱：`GET /knowledge/graph`，按知识库、类型、作者、时间筛选。
- 变更记录：`GET /knowledge/changes`；“标为人已确认”。
- 附件上传。
- 导出：一个知识库导出成 Markdown 压缩包，可以直接用 Obsidian 打开。
- 现有的书签接口不变。
