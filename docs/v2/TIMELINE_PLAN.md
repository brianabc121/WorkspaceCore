# 任务时间轴看板与知识库升级方案（T-0101）

> 状态：**已批准**。人类 2026-11-04 提出下面四点要求，并说“给我根据以上要求做一个升级计划方案。之后按照推荐的来，给我全面落实”：
> 本文的推荐做法即为批准的做法。实施任务见第 6 节。核验结果见 `docs/decisions/2026-11-04-timeline-kb-upgrade-verification.md`。
>
> 效果图：https://claude.ai/artifact/CHuDA9DsafbAudwxB6A61y（人类确认“这个设计效果可以”）。
>
> **需求来源**（人类 2026-11-04）：
> 1. 设计效果可以；任务页面也要有这个看板的入口。
> 2. 看板能看所有任务的执行情况，也能按项目看这个项目下所有任务的执行情况。
> 3. 知识图谱按类型着色；取消“人是否确认过”这个功能（以后数据量大，看不过来）。
> 4. 知识图谱要能上传图片；图片存到 Cloudflare R2 和阿里云 OSS；没有配置就存本地。

## 1. 结论

| 需求 | 推荐做法 |
|---|---|
| 时间轴看板 | 独立页面 `/tasks/timeline`，按效果图做（暗色、亮色跟随工作台主题）。每个执行者一条轨道，每个任务的每段执行是一个片段，颜色按项目；最下面一条是 token 用量 |
| 入口 | 任务页“显示方式”加“时间轴”；项目页每个项目加“时间轴”；看板顶部可以切换“全部项目 / 某个项目”，地址里带上项目，能收藏、能分享 |
| 开始、结束与执行者 | 任务新增计划开始时间、执行者（人或 OpenClaw 实例）和执行记录；人点“开始 / 暂停”，智能体由管理员点“交给它执行”（以管理员自己的 IM 账号发消息），完成走原有的审批 |
| token | 接入包新增每分钟一次的用量上报：在 OpenClaw 容器里调网关的 `sessions.usage`（已在锁定版本上实测），把累计 token 报给工作台；工作台按分钟算增量，再按时间归到正在执行的段。没上报就显示“未上报”，不编数字 |
| 知识图谱着色 | 16 种类型分 6 组上色（第 3 节），图例列出每组的类型，可按单个类型筛选；“着色”选项改为 类型（默认）/ 知识库 / 作者 |
| 取消“人已确认” | 删掉接口、界面、工具结果里的确认字段和检索加权；迁移删掉两列（第 3.2 节） |
| 图片 | 编辑器可插入、粘贴、拖入图片；笔记里显示；图谱侧栏显示缩略图，可选“显示图片”节点。存储：主存储（本地 / R2 / OSS）+ 可选副本，都没配置就存本地；图片一律经工作台读取，桶保持私有 |

## 2. 时间轴看板

### 2.1 页面与入口

- **页面**：`/tasks/timeline`，在工作台的布局里（左侧主导航）。布局照效果图：
  - 工具条：今天、前后翻页、日期；刻度 小时 / 天 / 周；分组 按执行者 / 按项目；“只看执行中”“超时”；跟随当前时间。
  - 概况：正在执行、今天完成、今天消耗的 token、超过截止时间。
  - 时间轴：刻度尺、播放头（现在）、每个执行者一条轨道、token 用量轨道、全天概览与缩放。
  - 右侧：选中任务的详情（执行者、开始、截止、已运行、token 与每 10 分钟用量、执行记录、打开任务、在消息里看会话）。
  - 手机：上面是“正在执行”卡片，中间是紧凑时间轴（左右滑动），下面是选中任务的底部面板。
- **看全部 / 按项目**：顶部“项目”下拉，默认“全部项目”；选了项目后只显示这个项目的任务，概况和 token 也只算这个项目。地址 `/tasks/timeline?project=<id>&date=2026-11-04&scale=day`。
- **入口**：
  - 任务页“显示方式：列表 / 看板 / 时间轴”，点“时间轴”进入看板，带上任务页当前选的项目；
  - 项目页每个项目的操作里加“时间轴”，进入后已选好这个项目；
  - 任务详情里加“在时间轴中查看”，定位到这个任务。
- **权限**：viewer 只能看；member 以上可以拖动“计划中”的片段改计划时间、开始 / 暂停人的任务；“交给智能体执行”要 owner / admin（发 IM 消息只有管理员能做）。所有接口都按工作空间和角色校验。

### 2.2 新增的数据（迁移 0027）

| 表 / 字段 | 内容 |
|---|---|
| `tasks.planned_start_at` | 计划开始时间（可空）。计划中的片段从这里画到截止时间 |
| `tasks.started_at` | 第一次开始执行的时间（可空，由执行记录维护） |
| `tasks.assignee_user_id` / `tasks.assignee_instance_id` | 执行者：工作空间成员或 OpenClaw 实例，二选一，都空表示“未分配” |
| `task_runs` | 一段执行一行：任务、执行者、开始、结束、结束原因（`done` 完成 / `paused` 暂停 / `interrupted` 中断 / `cancelled` 取消）、谁开始的。一个任务可以有多段 |
| `agent_usage_minutes` | 每个实例每分钟的输入 / 输出 / 缓存 token 增量，保留 90 天 |
| `agent_usage_cursors` | 每个实例、每天、每个会话最后一次上报的累计值，用来算增量 |

等待审批不另存：从 `ai_tool_executions` 推出来（这个实例的写操作从“待审批”到“已决定”的时间），落在某段执行里就画成灰色斜线。

### 2.3 一段执行怎么开始、怎么结束

- **人的任务**：任务详情里点“开始”开一段；“暂停”结束这段（`paused`）；标为完成时结束这段（`done`）。
- **智能体的任务**：
  - 管理员把执行者设成某个实例，点“交给它执行”：工作台用**管理员自己的 IM 账号**给它发一条固定格式的消息，同时开一段。消息包含任务标题、`task_id`、截止时间，请它用 `get_task` 读详情、完成后用 `update_task` 标为完成。接入包的 IM 渠道只放行管理员，所以不能由工作台代发。
  - 智能体用 `update_task` 标完成，**照旧要审批**；批准、任务完成后这段结束。
  - 实例被停用、删除，或离线超过 10 分钟，正在跑的段记为中断。
  - 管理员也可以手动“结束这段”（中断或取消）。
  - **不新增 MCP 写工具**：开始、结束都由人或已有的审批流程触发，不放宽审批规则。
- **计划中**：有计划开始时间或截止时间、还没开始的任务。从计划开始画到截止；只有截止时间的，画一个截止标记。
- **超时**：正在执行且已过截止时间，过了的部分画琥珀色斜线，旁边写超了多久。

### 2.4 token 从哪来

已在锁定的 OpenClaw 2026.9.36 上用真实网关和假模型实测（核验 ADR 第 2 节）：

- OpenClaw 在会话记录里保存每次模型调用的 token。网关 RPC `sessions.usage` 返回每个会话的汇总，要 `operator.read` 权限，接入包的网关令牌有这个权限：
  - 字段有 `input`、`output`、`cacheRead`、`cacheWrite`、`totalTokens`，以及 `firstActivity`、`lastActivity`；
  - 刚启动或缓存刷新时某个会话的 `usage` 会暂时是 `null`，`cacheStatus.status` 为 `refreshing`。
- **上报**：接入包新增 `bin/usage-report.mjs`，由宿主机 crontab 每分钟运行一次（和 `secrets reload` 一样，SSH 部署自动写入，手动部署照 CHECKLIST）。它做两件事：
  - 在容器里调 `openclaw gateway call sessions.usage`，参数是 `mode: "specific"`，起止日期都是今天（UTC）；
  - 把每个会话今天的累计值发到工作台 `POST /agent-api/v1/usage`（实例凭证，经接入入口）。刚过零点的 10 分钟内，昨天的也再报一次，免得丢掉最后一分钟。
- **工作台**：
  - 按（实例、日期、会话）记住上次的累计值，增量 = 新值 − 旧值；
  - 值变小（会话被删除或压缩）就以新值为准，不算负数；`usage` 为 `null` 的会话这次跳过；
  - 增量记到收到上报的那一分钟。
- **归属**：一段执行用的 token = 这个实例在这段时间里每分钟增量之和。
  - 同一实例同时有几段在跑，就平均分，界面标“≈”；
  - 这一时段里它的其他对话（例如闲聊、每晚复盘）也会算进去，详情里说明“按时间归属”。
- 人的任务不计 token。实例没上报（旧接入包、上报失败）时显示“未上报”。

### 2.5 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/tasks/timeline?from&to&project_id&group&scale` | 时间范围内的轨道、片段（计划、执行段、等待审批、超时）、token 用量分桶、概况 |
| PATCH | `/api/v1/tasks/{id}` | 增加 `planned_start_at`、执行者 |
| POST | `/api/v1/tasks/{id}/runs` | 开始一段：人的任务开始；`dispatch: true` 时交给实例执行（发 IM，`Idempotency-Key`） |
| POST | `/api/v1/tasks/{id}/runs/{run_id}/stop` | 结束一段：`paused` / `interrupted` / `cancelled` |
| GET | `/api/v1/tasks/{id}/runs` | 执行记录（含 token、等待审批） |
| POST | `/agent-api/v1/usage` | 实例上报用量（实例凭证；限流；只收数字） |

SSE 的 `tasks` 主题刷新看板；正在执行的段每分钟随上报更新。

### 2.6 任务详情

任务编辑器增加：
- 执行者（成员或实例）；
- 计划开始；
- 执行记录：每段的时间、结束原因、token，等待审批；
- 按钮：开始 / 暂停（人的任务），交给它执行（实例），结束这段，在时间轴中查看。

## 3. 知识图谱：按类型着色，取消“人已确认”

### 3.1 按类型着色

16 种类型按用途分 6 组，一组一个颜色。6 种颜色在亮色、暗色下都跑过 dataviz 的配色检查，色觉障碍下也能分开：

| 组 | 类型 | 亮色 | 暗色 |
|---|---|---|---|
| 规范与流程 | 规范、流程、操作手册、模板 | `#2a78d6` | `#3987e5` |
| 决策与计划 | 决策、计划、设计 | `#eb6834` | `#d95926` |
| 经验与复盘 | 经验、复盘、收到的纠正 | `#1baf7a` | `#199e70` |
| 项目 | 项目简报、风险 | `#eda100` | `#c98500` |
| 知识 | 概述、术语、记录 | `#e87ba4` | `#d55181` |
| 偏好 | 偏好 | `#6250d6` | `#9085e9` |

- 为什么分组：超过 8 种颜色时，人眼分不清哪个是哪个，图例也没法用。所以颜色只区分 6 组。
- 图例：按组列出每组包含的类型。
- 侧栏可以按单个类型勾选筛选。
- 悬停提示、所选笔记、列表视图都显示具体类型。
- 任务、项目、书签节点保持灰色。
- 亮色下有 4 个颜色对底色的对比度低于 3:1，用图例文字、节点标签和列表视图补足，不只靠颜色。
- “着色”选项改为 **类型（默认）/ 知识库 / 作者**，去掉“是否人已确认”。

### 3.2 取消“人已确认”

- **删掉**：
  - 接口 `POST /api/v1/knowledge/notes/{id}/confirm`；
  - `NoteOut` 的 `confirmed_by` / `confirmed_at`，`NoteSummary`、`GraphNode` 的 `confirmed`；
  - 图谱的“只看人已确认”筛选，笔记页的“标为人已确认”按钮与标记；
  - `knowledge_*` 工具结果里的 `origin.confirmed` 及工具描述里的相关说明；
  - 检索排序里的确认加权。
- **迁移 0025** 删除 `knowledge_notes.confirmed_by`、`confirmed_at`。降级时加回空列，已有的确认信息不保留：人类要求取消这个功能。
- “有冲突”标记保留（与确认无关）。

## 4. 知识库图片

### 4.1 怎么用

- 编辑器：
  - 工具栏“插入图片”、粘贴、拖进编辑区，都会上传；
  - 上传时显示占位，完成后插入 `![说明](/api/v1/knowledge/files/<id>)`；
  - 失败时提示原因（类型、大小、配额）。
- 阅读页：显示图片，点击放大；外部网址的图片仍然不自动加载（只显示链接）。
- 图谱：
  - 所选笔记的侧栏显示它引用的图片缩略图；
  - 选项“显示图片”默认关闭，打开后每张图片是一个小节点，连到引用它的笔记（类似 Obsidian 的附件）。
- 智能体：`knowledge_get` 返回的正文里照样有图片链接；智能体不能上传图片，没有新工具。

### 4.2 存储

| 配置 | 含义 |
|---|---|
| `FILE_STORAGE`：`local` / `r2` / `oss` | 主存储。默认 `local` |
| `FILE_STORAGE_REPLICA`：`none` / `local` / `r2` / `oss` | 副本，默认 `none`。主存储写成功就返回；副本由 Worker 异步复制，失败重试；读主存储失败时读副本 |
| `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` / `R2_JURISDICTION` | Cloudflare R2（S3 兼容接口） |
| `OSS_REGION` / `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET` / `OSS_BUCKET` / `OSS_ENDPOINT` | 阿里云 OSS（S3 兼容接口，虚拟托管风格） |

- “存到 R2 和 OSS”：两个都配置时，一个做主存储、一个做副本，两边都有一份。
  - 推荐：用户主要在国内时，主存储 OSS、副本 R2；否则反过来。
  - 只配一个就只用一个；都没配就存本地。
- **本地**：卷 `kb-files`，api 与 worker 挂载。纳入 `make backup` 与 `make restore-verify`，恢复后核对数量和校验和。
- **R2 / OSS**：都走 S3 兼容接口，自己实现 SigV4 签名，不引入 SDK。
  - 桶保持私有；
  - 外部请求有超时、错误分类、最多重试 3 次；
  - 对象 key 是 `kb/<workspace_id>/<sha256>`：同一工作空间、同一内容只存一份，PUT 天然幂等，结果不确定时用 HEAD 核对；
  - 启动时和运维页可以做一次自检：写一个探测对象、读回、删除。
- 图片**一律经工作台读取**：`GET /api/v1/knowledge/files/<id>`，按工作空间与角色校验，带 `Cache-Control: private`、`nosniff`。浏览器不直连 R2 / OSS，CSP 不用改。
- `deploy.sh connect` 增加“图片存储（R2 / OSS）”一步。运维页显示主存储、副本、待复制数量、已用空间。

### 4.3 限制与安全

- 只收 PNG / JPEG / GIF / WebP：按文件头判断，不信任文件名和 Content-Type，拒绝 SVG。
- 单张最大 10 MB；每个工作空间默认 2 GB（`FILE_QUOTA_MB`）。
- JPEG 去掉 EXIF（里面可能有拍摄地点）。
- 上传要 member 以上；读取 viewer 以上；跨工作空间返回 404。
- R2 / OSS 的密钥只在 `.env`（`SecretStr`），日志里只记录 key 的哈希前缀，不记密钥。

### 4.4 引用与清理

- 保存笔记时记录它引用了哪些图片（`knowledge_file_refs`），历史版本也算引用，保证版本历史里的图片不丢。只能引用本工作空间的图片。
- Worker 每天清理一次：没有任何笔记引用（包括回收站里的笔记和历史版本）、且上传超过 24 小时的图片，从主存储和副本删除。
- 笔记被彻底删除后，它的引用随之消失，图片在下一次清理时删除。

## 5. 核验情况

- **OpenClaw 用量**：已在锁定镜像上实测，见核验 ADR 第 2 节：
  - 随版本文档 `concepts/usage-tracking.md`、`gateway/protocol/rpc-system-and-channels.md`、`gateway/opentelemetry/spans-and-events.md`；
  - 真实网关 + 假模型调用 `sessions.usage`，`range` 只接受 `7d` / `30d` / `90d` / `all` 这类常量，`mode: "specific"` 加起止日期可用。
- **R2 / OSS**：本环境的网络策略拦截了 `developers.cloudflare.com` 与 `help.aliyun.com`，只能读到官方文档的搜索摘要，摘要来源都是官方域名，见 ADR 第 3 节。
  - 实现按“通用 S3 兼容接口 + 部署时自检”：endpoint、region、寻址方式都可配置，R2 与 OSS 的默认值来自官方文档摘要，并在 ADR 里注明。
  - CI 用已锁定的 Garage（S3 兼容）验证路径风格的读写删；虚拟托管风格的签名用 AWS 官方测试向量做单元测试。
  - **真实 R2 / OSS 账号上的验收**要等人类提供测试桶，或在环境设置里放开上述两个域名后补读文档。在那之前，T-0103 的这一条验收标准不勾选，写明原因。

## 7. 风险

- **token 是按时间归属的近似值**：一段执行的 token 包含这个实例同一时段的其他对话。界面注明，平均分时标“≈”。
