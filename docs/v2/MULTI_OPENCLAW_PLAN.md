# 多实例服务器方案：一台服务器部署多个 OpenClaw，服务器管理页看整机与每个智能体的负载

> 状态：方案（T-0142），等人类批准第 14 节的 D1 ~ D7 后再拆实施任务。
> 人类 2026-11-07 的要求：
> 1. OpenClaw 是部署在 Docker 上的，一台服务器要可以部署多个 OpenClaw；
> 2. 服务器管理页面要能查看这台服务器上的多个智能体：除了整台服务器的负载，还能分别查看每个智能体的负载。
>
> 相关：`docs/v2/OPENCLAW_PLAN.md`（实例与接入包）、`docs/v2/AGENT_OPS_PLAN.md` 第 5、6 节（服务器状态、远程运维）、
> `docs/decisions/2026-11-03-openclaw-ssh-provisioning.md`（SSH 自动部署）、`docs/decisions/2026-11-04-agent-ops-verification.md`（容器里读宿主机指标）。
> 运行服务器（`docs/v2/RUNNER_PLAN.md`）是另一类服务器，不在本方案范围内，保持不变。

## 1. 现状：为什么一台服务器只能放一个实例

现在的模型是“一个实例 = 一台服务器”。下面这些都是写死的，第二个实例部署到同一台服务器会把第一个顶掉：

| 位置 | 现在的值 | 同一台服务器上第二个实例会怎样 |
|---|---|---|
| 安装目录（`app/agent_provisioning/__init__.py`） | `~/myworkspace-openclaw` | 同一个账号下，覆盖第一个实例的文件和凭证 |
| Compose 项目名（`app/agent_bundle/files/compose.yaml`） | `name: myworkspace-openclaw` | 项目名对整个 Docker 生效：换账号也会把第一个实例的容器替换掉 |
| 网络 | `network_mode: host`；外网模式的本机隧道、内网模式的取图代理监听 `127.0.0.1:18443` | 端口冲突；OpenClaw 网关自己的监听端口也会冲突。而且各实例的回环服务互相看得到 |
| 定时任务（crontab） | 所有行都带同一个标记 `# myworkspace-openclaw`，更新时先删掉带标记的行 | 第二个实例写定时任务时删掉第一个的 |
| SSH 目标（`agent_ssh_targets`） | 每个实例一行，专用密钥、主机指纹、安装目录都挂在实例上 | 同一台服务器要确认两次指纹、装两把密钥；也没有任何地方拦“两个实例填了同一台服务器” |
| 服务器状态（`agent_host_samples` / `agent_host_state`） | 按实例存；容器里读 `/proc`，读到的是整台服务器的值 | 同一台服务器的整机数据每个实例各存一份；看不到单个智能体用了多少 |
| 运维动作（`app/domain/agent_ops.py`） | 都挂在实例上；其中“清理无用镜像”（`docker image prune`）其实是整台服务器的操作 | 在一个实例上点清理，影响整台服务器 |

## 2. 总体设计

引入**服务器**这一层：

```
工作空间
 └─ OpenClaw 服务器（新）：地址、SSH 账号、主机指纹、专用密钥、整机负载
     ├─ 实例 甲：一个 Compose 项目 + 一个目录 + 自己的网络 + 自己的负载
     ├─ 实例 乙
     └─ ……
```

- **服务器**：一台装了 Docker 的机器。主机指纹只确认一次，工作台的专用密钥只装一次，整机负载只存一份。
- **实例**：服务器上的一个 Compose 项目，有自己的目录、网络、定时任务和资源上限。部署、卸载、运维都只碰自己的项目。
- 实例可以不属于任何服务器（手动下载接入包部署、工作台还不知道它在哪台机器上），这时页面上显示在“未归属的实例”里（第 4.4 节）。

## 3. 服务器上的布局

### 3.1 每个实例一套，互不重叠

| 项 | 新的做法 |
|---|---|
| 目录 | `~/myworkspace-openclaw/<实例短号>/`（实例 ID 前 8 位，例如 `~/myworkspace-openclaw/d06d9d48/`），里面结构不变（`bin/`、`state/`、`myworkspace.env`、`compose.yaml`） |
| Compose 项目名 | `myworkspace-openclaw-<实例短号>` |
| 容器名 | 由 Compose 按项目名生成，不写死 |
| 定时任务标记 | `# mw-openclaw:<实例短号>`；写入、删除只匹配自己这一行的标记（见 3.4） |
| 网络 | 见 3.2（D1） |
| 资源上限 | 可选的内存、CPU 上限，见 3.3（D2） |

服务器上共享的只有：Docker、镜像缓存（同一个锁定 digest 的 OpenClaw 镜像只下载一次）、SSH 账号、crontab。

### 3.2 网络（D1）

**推荐 A：每个实例自己的网络命名空间。**

- OpenClaw 容器用 Compose 默认的项目网络（bridge），不再用 `network_mode: host`；
- 外网模式的本机隧道、内网模式的取图代理用 `network_mode: "service:openclaw"`，和 OpenClaw 共用这个实例的网络命名空间。
  所以它们仍然监听 `127.0.0.1:18443`，接入包里的地址都不用改；
- 每个实例的回环地址只属于它自己：端口不会冲突，一个实例也连不到另一个实例的网关和隧道（第 11 节）；
- 出站连接（接入入口、模型服务商、npm）照常，经 Docker 的 NAT 出去。

代价：

- 容器里读 `/proc/net/dev` 看到的是这个实例自己的网卡，看不到整台服务器的网速。整机网速改成“所有实例的网速之和”，页面上写明这一点；
- 好处是每个智能体的网速可以单独看到（第 5.2 节）。
- 要在锁定版本上重新核验（第 13 节）：IM 长连接、MCP、隧道、取图代理、`wakeup.mjs` / `stop-runs.mjs` 调网关，都要在这种网络下实测。

**备选 B：继续用宿主网络，给每个实例分配端口。** 工作台给同一台服务器上的每个实例分配隧道端口和网关端口，写进接入包。

- 改动小，整机网速仍然能读到；
- 但所有实例共用宿主机的回环地址，一个实例能连到另一个实例的网关和隧道，只能靠网关自己的认证挡住；
- 每个实例的网速也看不到。

### 3.3 每个实例的资源上限（D2）

在 `compose.yaml` 里给 OpenClaw 容器加 `mem_limit` 和 `cpus`。

- **推荐**：默认不设上限。部署时页面按服务器剩余资源给建议值，管理员可以为每个实例单独设、随时改，改了重新部署这个实例生效；
- 设了上限的实例，页面显示“已用 / 上限”，接近上限时提醒（第 9 节）；
- 不设上限时，单个智能体的内存显示“已用 / 整机总量”。

### 3.4 定时任务

每个实例仍然是同样的几行：每分钟上报用量与服务器状态、领取唤醒与终止令，每 10 分钟取密钥，每周一重启。差别是：

- 每行末尾的标记带实例短号：`# mw-openclaw:<实例短号>`；
- 写入时只删“行尾正好是这个标记”的旧行（用 `grep -v` 匹配行尾，不再用子串匹配），不会误删别的实例；
- 旧标记 `# myworkspace-openclaw` 只在迁移旧部署时删一次（第 12 节）。现在的子串匹配不能留：新标记里如果包含旧标记，旧实例重写定时任务时会把新实例的行一起删掉。

## 4. 部署（全部在页面上完成）

### 4.1 服务器

在“OpenClaw 服务器”页添加：

1. **填地址**：IP 或域名、SSH 端口、账号（root，或能用 sudo 的账号）；
2. **读主机公钥并核对指纹**：和现在一样，不登录、只读公钥，勾选“已核对”后确认；
3. **准备服务器**：输入一次登录密码。工作台装锁定版本的 Docker、把账号加入 docker 组、装上工作台的专用密钥，密码用完即丢。这一步和现在 SSH 部署的前几步相同，只是挪到服务器上做一次。

之后在这台服务器上部署、卸载、运维实例都用专用密钥，不再输密码（D7）。

### 4.2 部署实例

在实例卡片上点“部署到服务器”，选一台已添加的服务器，然后：

1. **容量预检**：页面显示这台服务器的剩余内存、剩余磁盘，以及上面已有实例的用量。
   - 剩余内存不到建议值（R0 实测一个空闲 OpenClaw 的内存后定，先按 1.5 GB）或剩余磁盘不到 5 GB 时，给出警告，但不阻止（D4）；
2. **部署步骤**：连接 → 上传接入包到自己的目录 → 装插件、打补丁 → 启动自己的 Compose 项目 → 写自己的定时任务 → 等实例上线。
3. **同一台服务器上已有这个实例**（重新部署）：只替换它自己的目录和项目，会话与记忆在 `state/` 里保留。

### 4.3 卸载与移除

- **卸载实例**：`docker compose -p myworkspace-openclaw-<短号> down`，删掉自己的定时任务行，可选删除自己的目录。不碰别的实例；
- **清理无用镜像**改成服务器级动作，只删没有任何容器在用的镜像；
- **移除服务器**：上面没有部署着的实例才能移除。会先吊销专用密钥：登录服务器删掉那一行公钥，再删工作台保存的私钥。

### 4.4 手动部署的实例归属哪台服务器（D3）

手动下载接入包部署的实例，工作台不知道它在哪台机器上。

**推荐**：自动识别，管理员可以改。

- 服务器状态上报带上 `boot_id` 的哈希。`boot_id` 来自 `/proc/sys/kernel/random/boot_id`：同一个内核相同，各容器读到的都一样，机器重启后会变；
- 哈希用工作空间密钥做 HMAC，不报原值；
- 两个实例的哈希相同，就是同一台服务器（同一时刻同一个内核）。没归属的实例会自动归到这台服务器，或者新建一个“手动部署的服务器”；
- 机器重启后，这台机器上所有实例的哈希一起变。工作台按“同一台服务器上的实例一起换了新哈希”来跟着更新，不会拆成两台；
- 管理员可以在页面上手动改归属。手动改过的以手动为准。

## 5. 负载采集

### 5.1 整台服务器

和现在一样，由容器里的 `host-report.mjs` 读 `/proc` 和文件系统统计：CPU 使用率、1/5/15 分钟负载、内存、Swap、两个分区、开机时长。差别有三点：

- **去重**：同一台服务器上的每个实例都会报整机数据，每分钟只存一份（服务器 + 分钟 唯一，先到的写入，后到的忽略）。
  CPU 使用率仍然用“同一个实例两次上报的累计值之差”算，所以先到的那份本身就是对的；
- **网速**：D1 选 A 时，整机网速是“这台服务器所有在线实例的网速之和”。选 B 时仍读宿主网卡；
- **离线**：服务器上所有实例都 3 分钟没上报，整机数据显示“数据过期”。

### 5.2 每个智能体

`host-report.mjs` 同时读**自己容器的 cgroup**，只报数字：

| 指标 | 来源（cgroup v2；v1 有对应文件） | 页面显示 |
|---|---|---|
| CPU | `cpu.stat` 的 `usage_usec`（v1：`cpuacct.usage`），用两次之差算 | 占用几个核，以及占整台服务器的百分比 |
| 内存 | `memory.current`，以及 `memory.stat` 的 `anon` / `file`（v1：`memory.usage_in_bytes`、`memory.stat`） | 已用（不含可回收的缓存），以及已用 / 上限（没设上限时是 / 整机总量） |
| 进程数 | `pids.current` | 数字 |
| 数据目录大小 | 遍历 `state/`（会话、记忆、插件）累加文件大小，每 10 分钟一次，最多遍历 20 万个文件，超过就记“超过” | 已用多少，以及在分区里的占比 |
| 网速 | 这个实例的网卡收发累计字节（只有 D1 选 A 才有） | 上传、下载速率 |

页面上再加两项已有的数据：

- 最近一小时的 token 用量（用量上报，T-0104）；
- 正在执行的任务（时间轴上没结束的一段）。

两点说明：

- 隧道、取图代理两个辅助容器很小，不单独统计。“实例的负载”就是 OpenClaw 容器的负载；
- cgroup 文件在锁定镜像、三个支持的发行版（Ubuntu 22.04 / 24.04、Debian 12）上的路径和含义都要实测，第 13 节。

### 5.3 上报接口

`POST /agent-api/v1/host-metrics` 增加两个可选块：`container`（上表的累计值）和 `host_key`（`boot_id` 的 HMAC）。

- 字段仍然严格校验，数值有上下限，每个实例每分钟最多 2 次；
- 旧接入包不带这两块，照样接受：只记整机数据，单个智能体的负载显示“重新部署后才有”。

## 6. 存储与迁移

| 表 | 内容 |
|---|---|
| `agent_servers`（新） | 工作空间、名称、地址、端口、账号、主机公钥与指纹、专用密钥（引用密钥库）、`host_key` 哈希、版本号、时间 |
| `agent_instances`（加列） | `server_id`（可空，删服务器时置空）、`server_assigned`（手动指定 / 自动识别）、`mem_limit_mb`、`cpus` |
| `agent_ssh_targets` → `agent_deployments`（改名改结构） | 每个实例在服务器上的部署：`instance_id`、`server_id`、目录、项目名、部署时间、接入包版本。密钥、指纹从这里挪到 `agent_servers` |
| `agent_ssh_jobs` | 加 `server_id`。准备服务器、吊销密钥是服务器级任务，部署、卸载是实例级任务 |
| `agent_server_samples`（新） | 服务器 + 分钟唯一：整机的 CPU、负载、内存、Swap、两个分区、网速。保留 30 天 |
| `agent_instance_samples`（新） | 实例 + 分钟唯一：CPU 核数与百分比、内存已用与上限、进程数、数据目录大小、网速。保留 30 天 |
| `agent_host_state`（保留） | 每个实例上一次的累计值，加 cgroup 的累计值 |
| `agent_host_samples`（旧） | 迁移后只读保留 30 天，到期在下一次迁移里删表（D6） |

迁移步骤：

1. 每个现有的 SSH 目标建一台服务器。现有数据里不可能有两个实例在同一台服务器上（会互相顶掉），所以一一对应；
2. 实例的 `server_id` 指向这台服务器。没有 SSH 目标的实例先不归属，按第 4.4 节自动识别；
3. 旧的按实例样本复制到 `agent_server_samples`。
4. 升级、降级都要有测试。

## 7. 页面

### 7.1 OpenClaw 服务器列表（新）

位置：“连接与工具 → OpenClaw 实例”页（`/agents`）改成两个标签：“实例”（现在的页面）和“服务器”（`/agents?tab=servers`，地址里记着标签，和运行服务器页一样）。
权限与现在的实例页相同，只有 owner（智能体接口只给 owner，OC-1 契约第 3 节）。

每台服务器一张卡片：

- 名称、地址，在线 / 离线；
- CPU、内存、磁盘三个占用条（超过阈值标红）、15 分钟负载；
- 上面有几个实例、几个在线；
- 正在提醒的告警。

列表最后是“未归属的实例”，以及“添加服务器”按钮。

### 7.2 服务器详情（新）

- **整机当前值**：沿用现在实例页“服务器状态”的卡片。CPU（核心数、使用率、三个负载值）、内存、两个分区、网速、开机时长、最后上报时间；
- **整机趋势**：最近 24 小时、7 天、30 天；负载与 CPU、内存、磁盘、网络四张图，有悬停提示和表格视图（沿用现有组件）；
- **这台服务器上的智能体**：一张表，每个实例一行。名称、在线状态、CPU（核数与占整机百分比）、内存（已用 / 上限）、进程数、数据目录大小、网速、最近一小时 token、正在执行的任务；可以按任意一列排序；
- **占用对比**：CPU 和内存各一张堆叠条，显示每个实例各占整台服务器多少，剩下的是“其他进程”（整机已用减去所有实例）；
- **单个智能体**：点表里的一行展开它自己的趋势图（CPU、内存、网速，24 小时 / 7 天 / 30 天）和它的运维按钮（第 8 节）；
- **服务器级操作**：在这台服务器上部署实例、查看全部容器、清理无用镜像、更换地址、吊销密钥、移除服务器；
- 手机宽度可用：表格改成每个实例一张小卡片，没有横向滚动。

### 7.3 实例卡片的变化

- 显示所在的服务器（点击跳到服务器详情），以及自己的 CPU、内存两个小指示；
- “通过 SSH 自动部署”改成“部署到服务器”（选服务器，或者先去添加一台）；
- “服务器状态”区域改成“这个智能体的负载”，整机数据去服务器详情看。

## 8. 运维动作拆分

| 级别 | 动作 | 说明 |
|---|---|---|
| 实例 | 查看状态、查看日志、重启 OpenClaw、重新拉起、立即上报一次、重新部署、卸载 | 只作用于这个实例的 Compose 项目（`-p myworkspace-openclaw-<短号>`），命令写死，在它自己的目录里执行 |
| 服务器 | 查看全部容器（这台服务器上所有工作台项目的 `docker compose ls` 与 `docker stats`）、清理无用镜像、吊销密钥、移除服务器 | 清理镜像、吊销、移除要二次认证（与现在一样） |

两条规则：

- 同一个实例同一时间只跑一个动作，不变；
- 服务器级动作和这台服务器上的实例级动作互斥，避免清理镜像时正好在部署。

## 9. 告警

- **服务器级**（每台服务器一份，不再按实例重复提醒）：磁盘可用低于 10%、内存可用低于 5%、15 分钟负载持续 15 分钟超过核心数的 2 倍、30 分钟没有任何实例上报；
- **实例级**（新）：
  - 设了内存上限的实例，用量超过上限的 90% 持续 10 分钟；
  - 一小时内重启 3 次以上（按开机时长与上报间隔判断）；
  - 单个实例持续 15 分钟占用超过整台服务器 80% 的 CPU。
- 恢复前同一类只提醒一次，和现在一样。

## 10. 智能体读自己的状态（`get_host_status`）

仍然只返回调用它的实例能看的东西，现在分成两块：

- **自己所在服务器的整机当前值与 24 小时概况**；
- **自己容器的用量**。

不提供看同一台服务器上其他实例的工具，智能体也看不到别的实例的名字和用量。

## 11. 安全与隔离

- **会话、密钥不跨实例**：每个实例的凭证（`myworkspace.env`）、OpenClaw 状态（`state/`）在自己的目录里，只挂进自己的容器。
  两个 OpenClaw 容器都以 uid 1000 运行，但各自只看得到自己挂载的目录；
- **网络隔离**：D1 选 A 时，各实例的回环地址互相隔离，一个实例连不到另一个实例的网关和隧道。选 B 时只能靠网关认证，这是推荐 A 的主要原因；
- **工作台不变的限制**：不开 exec、不挂 Docker socket、去掉全部 capability、`no-new-privileges`（`docs/AGENTS.md` 第 8 节）；
- **SSH**：每台服务器一把专用密钥（D7）。部署账号在 docker 组，等同 root，这一点与现在相同，所以要求是专用服务器；
- **审计**：添加、准备、移除服务器，部署、卸载实例，所有运维动作，都写审计，带服务器和实例。

## 12. 旧部署的升级

- **SSH 部署过的旧实例**：迁移后会自动有一台对应的服务器，旧实例照常运行（旧目录、旧项目名、宿主网络）。
  页面提示“重新部署后可以在这台服务器上再加实例”。下一次重新部署时自动迁移：
  1. 停掉旧项目（`-p myworkspace-openclaw down`）；
  2. 把旧目录的 `state/` 移到新目录（会话、记忆、插件都在这里）；
  3. 用新布局启动；
  4. 删掉旧标记的定时任务行，写入新的；
  5. 确认上线后再删旧目录。中途失败就回到旧项目，页面显示日志。
- **旧实例还没迁移时**，同一台服务器上不允许部署第二个实例。页面说明原因，并给出“先迁移这个实例”的按钮（D5）；
- **手动部署的旧实例**：下载新的接入包，按 CHECKLIST 的“迁移”一节做（同样的五步）。不迁移也能继续用，只是看不到单个智能体的负载；
- **工作台升级本身**：迁移是普通的 `make migrate`，不需要在服务器上做任何事。

## 13. 核验（在锁定版本上实测，不按文档猜）

| 项 | 做法 |
|---|---|
| OpenClaw 2026.9.36 在项目网络（bridge）里运行 | IM 长连接、MCP、密钥领取、用量上报、`wakeup.mjs` / `stop-runs.mjs` 调网关都正常；隧道和取图代理用 `service:openclaw` 共用网络命名空间后，`127.0.0.1:18443` 照常可用 |
| 两个实例在同一台机器上 | 两个 Compose 项目同时运行、互不影响；卸载一个，另一个不受影响；一个实例的容器连不到另一个的回环端口 |
| cgroup 指标 | 锁定镜像以 `node` 用户、去掉全部 capability 运行时，能读 `cpu.stat`、`memory.current`、`memory.stat`、`pids.current`（v2）以及 v1 的对应文件；在 Ubuntu 22.04 / 24.04、Debian 12 的默认 Docker 上实测 |
| `boot_id` | 容器里读到的与宿主机相同，两个容器相同，重启后变化 |
| 一个空闲 OpenClaw 的内存与磁盘占用 | 用来定容量预检的建议值（第 4.2 节） |
| 旧部署迁移 | 宿主网络的旧实例迁移到新布局后，会话与记忆还在，定时任务只有新的一份 |

结果写进新的核验记录 `docs/decisions/2026-11-xx-multi-openclaw-verification.md`。CI 里用同一台 runner 上的两个真实 OpenClaw 实例做端到端验收：

- 经本机 sshd 部署到同一台“服务器”；
- 验证两个实例各自的负载、卸载一个不影响另一个、旧部署迁移。

## 14. 需要人类决定的事项

| 编号 | 问题 | 推荐 | 备选 |
|---|---|---|---|
| D1 | 实例的网络 | **A：每个实例自己的网络命名空间**（端口不冲突、回环隔离、能看每个智能体的网速） | B：宿主网络 + 按实例分配端口（改动小，但实例之间回环互通、看不到单个智能体的网速） |
| D2 | 每个实例的资源上限 | **默认不限，部署时按剩余资源给建议值，管理员可单独设** | 默认把服务器内存按实例数均分 |
| D3 | 手动部署的实例归属哪台服务器 | **按 `boot_id` 哈希自动识别，管理员可改** | 只能手动指定 |
| D4 | 一台服务器最多几个实例 | **不设硬上限，资源不够时警告** | 固定上限（例如 10 个） |
| D5 | 旧部署 | **重新部署时自动迁移；旧实例没迁移前，这台服务器不能加第二个实例** | 旧实例永远保持旧布局 |
| D6 | 旧的按实例样本表 `agent_host_samples` | **迁移后只读保留 30 天，再删表**（删表不可逆，按 D-0004 要人类同意） | 永久保留 |
| D7 | SSH 专用密钥 | **每台服务器一把，所有实例共用** | 每个实例一把（同一台服务器装多把公钥） |

## 16. 风险

| 风险 | 对策 |
|---|---|
| 一个智能体把服务器的内存或 CPU 吃满，影响同一台的其他智能体 | 每个实例可设上限（D2）；实例级告警；服务器详情里一眼看出是谁占的 |
| 换成项目网络后，OpenClaw 某项功能不正常 | M0 先在锁定版本上实测；不行就退回 D1 的 B |
| 旧部署迁移中途失败 | 先停旧项目、复制 `state/`，确认新项目上线后才删旧目录；失败就回到旧项目 |
| 定时任务互相误删 | 新标记按行尾精确匹配；旧标记只在迁移时删一次；CI 验收两个实例的定时任务都在 |
| `boot_id` 自动归属认错服务器 | 只在两份哈希完全相同时归到一起；手动指定优先；页面能改 |
| cgroup 在某些发行版或 Docker 配置下读不到 | v2、v1 都支持；读不到时这一项显示“无法获取”，不影响其他指标 |
