## 1. 人类需求与交付范围

用户明确要求：
1. 拆成两个独立页面：“智能体服务器”和“OpenClaw 智能体”。
2. 服务器通过IP、SSH端口、账号、密码添加，取消SSH密钥登录；可在服务器页初始化基础运行环境。
3. 智能体页选择已添加的服务器，平台自动创建Docker容器、部署OpenClaw并接入工作台。
4. 一台服务器部署多个OpenClaw；服务器页能看到自己机器上已部署的智能体。

## 2. 已有能力与本次变化

| 现状（已核对主干） | 本次落实 |
|---|---|
| `/agents`内“实例／服务器”两个标签 | 两个侧栏入口、两个独立页面，保留旧链接跳转 |
| 一台服务器多个实例、独立Compose项目／目录／网络已经实现 | 复用并增强展示，不再开发另一套多实例引擎 |
| 一次性密码安装专用SSH公钥，后续用加密私钥 | 保存加密登录密码，全生命周期密码认证，不生成／安装／使用新的SSH客户端密钥 |
| prepare可安装Docker，deploy可顺便prepare | 初始化独立完成；部署只选可部署服务器，不在智能体页索要SSH密码 |
| 服务器详情已有关联智能体和整机指标 | 改成清晰服务器表＋详情＋部署清单，保留真实指标 |
| 现有运行服务器Runner复用部分Installer／SSH代码 | 只改OpenClaw服务器认证，不改变Runner功能 |

本次不是删除所有“密钥”：**SSH客户端登录密钥退役；SSH主机身份校验、工作台加密主密钥、OpenClaw的mTLS证书／实例令牌／密钥库与授权保持。** 服务器登录密码不能授权给智能体、进入接入包或注入容器。

## 3. 页面与导航

### 3.1 智能体服务器
- 地址 `/agent-servers`；详情使用 `?server=<server_id>`，保留有效range参数。
- 侧栏名称“智能体服务器”，仅owner可见、可读写，保持现有接口权限。运行服务器`/runner`是另一个功能，不合并。
- 标题、说明、刷新、添加服务器；统计为服务器数、已就绪数、已部署智能体数、待初始化数。数字来自完整服务端范围，不能从实例第一页或筛选后的可见行猜总数。
- 服务器列表展示名称、IP／SSH端口、系统／资源（未知显示—）、初始化状态、智能体数量、查看／初始化入口。
- 详情展示连接状态、环境状态、最近检查时间、真实CPU／内存、初始化记录及“已部署OpenClaw”表格。
- 每个智能体可跳到`/agents?instance=<id>`；“前往部署智能体”跳`/agents?deploy=1&server_id=<id>`并预选当前服务器。
- 自动识别的`kind=auto`服务器保留，与用户添加的`kind=ssh`明确区分；auto没有SSH凭证时不提供初始化／自动部署，不能把已有归属记录丢掉。手动登记／归属能力继续保留。

### 3.2 OpenClaw 智能体
- 保留地址`/agents`，侧栏改名“OpenClaw 智能体”；移除服务器标签。
- 全部智能体列表支持服务器、名称、状态筛选与分页；展示所属服务器链接、连接状态、部署进度、资源上限和最近心跳。
- 新主动作“部署智能体”，次动作保留“手动登记／接入”，继续支持原接入包方式，不强制重建已有实例。
- 详情保留配置、权限、接入凭证、运维、负载、任务、唤醒、发件箱、停用／启用及原有入口。列表重排不能删除这些业务能力。
- 全局创建入口和历史页面链接随拆页同步；自定义导航不丢用户配置，新入口按现有合并规则补入。
- `/agents?tab=servers&server=...`使用replace跳到新服务器页；`/agents?tab=instances`清理旧tab并保留有效实例参数。`/agents/secrets`保持不变。

### 3.3 与效果图的有意调整
- 图中“运行中／已停止”不能由消息在线、心跳中断或停用状态推断。首期列表采用真实“连接状态”：待接入／消息在线／离线／已停用；部署任务状态另列。
- 智能体统计采用总数、消息在线、部署中、需关注；说明部署中与连接状态可能重叠，不伪造互斥总和。容器状态只在有真实检测证据的详情中显示，否则未知。
- 图中`oc-dev-01`等是示例。没有真实Docker容器名称就显示平台确定的部署项目标识／目录，不猜容器名或ID。
- 图中的“平台推荐版本”显示当前锁定且经过验证的版本；本期不提供任意镜像／latest／远程安装脚本输入。
- 资源上限汇总与实际内存占用分别标注；图中GB概数可作为显示值，接口内存上限仍为MiB。
- 添加表单里的初始化项目使用待执行样式；新服务器尚未初始化时不能画成全绿已完成。

## 4. 连接与凭证

### 4.1 添加／更新
- 仅需IP、SSH端口（默认22）、登录账号、登录密码；名称可选，缺省用host:port生成，不能新增必填密钥／证书字段。兼容既有域名记录与IPv6。
- 密码是只写字段，不裁剪有意义空格，使用现有CredentialBox加密，绑定目标记录；API只返回password_set、凭证版本和检查状态，不返回明文或密文引用。
- 创建先探测并保存主机指纹。首次登录前沿用既有“核对服务器身份”确认步骤；这是服务器身份验证，不是密钥登录方式，不要求用户上传任何密钥。
- “测试并保存”可串联保存、身份确认、连接测试；尚未确认／尚未检测时准确提示，不显示测试成功。确认前不把密码发给远端。
- 测试连接只验证登录与权限／环境，不安装Docker、不创建容器、不写authorized_keys。初始化是独立显式动作。
- 更新密码不重建服务器、不停止实例、不清空已成功初始化记录；重新验证后恢复部署。更换地址／端口／账号须重新核对身份与检测环境，不能把新机器冒充原有部署位置；有部署记录时沿用现有约束，不做隐式迁移。
- 同一服务器有初始化／部署／卸载／运维任务时拒绝改连接信息，避免中途换密码／换目标；服务器version与凭证revision均校验。

### 4.2 密码边界
- 不进URL、日志、审计metadata、SSE、队列payload、幂等响应正文缓存、浏览器持久化或错误详情；后台任务只存目标ID与凭证版本，临登录时在内存中解密。
- SSH连接关闭ssh-agent／默认私钥／配置文件回退；OpenClaw链路不尝试publickey。sudo复用该登录密码，通过stdin提供，不进命令行。需其他独立sudo密码或交互式MFA的环境明确提示不支持，不假装初始化成功。
- 保留目标地址检查、固定主机指纹、超时、速率限制、CSRF、幂等、审计及现有运维敏感动作的工作台账号二次认证。**SSH密码与工作台登录密码是两个不同用途。**
- SSH主机指纹变化时停止连接并提示核对；不自动接受新指纹，不改用户sshd配置以强行开启密码登录。
- 凭证加密轮换、无法解密、连接拒绝、密码错误分别有稳定错误码；失败不无限重试。

## 5. 服务器初始化

仅owner显式点击“初始化”，后台执行并显示步骤：
1. 验证身份与密码登录；检查系统、架构、sudo权限、磁盘与网络。
2. 检测Docker／Compose；缺失时按既有已核验脚本安装锁定版本，已有兼容版本直接复用。
3. 准备平台管理的部署根目录、必要权限与基础依赖；docker组变化后重新用密码建立会话确认生效。
4. 验证Docker可用、部署目录可用、平台接入地址可达；成功后记录prepared_at及初始化结果。

- 初始化不创建OpenClaw实例、容器或接入凭证，不安装工作台SSH公钥，不执行全局prune或停其他容器。
- 重复初始化幂等；不覆盖机器原有Docker配置、不强制升级正在使用的Docker、不更改SSH认证方式／开放无关端口。
- 有冲突／系统不支持／缺权限时显示具体步骤与可操作原因，保留已有正常实例，不自动“清空重装”。
- 服务器“已就绪”指环境可用，不等于当前在线。没有实例上报整机指标时显示“暂无上报”，不能伪造CPU=0／健康。

## 6. 自动部署与多实例隔离

### 6.1 表单与操作
- 智能体名称、部署服务器、CPU／内存上限；版本为平台推荐锁定版本。高级权限沿用现有缺省read/member，不能默认打开邮件发送、项目管理等权限。
- 自动部署使用现有public网络模式与接入入口；入口未配置时明确引导配置。保留手动接入的intranet实例，不改其不可变网络模式。
- 只允许选择kind=ssh、密码已设置、身份已确认、初始化已就绪、无冲突任务的服务器。最近连接检测明确失败时先修复；未知／过旧数据做真实预检，不当作绿色。
- 默认不限制资源，沿用现有D2；可配置cpus=0.1–256、mem_limit_mb=256–1048576，null代表不限制。图中的2核／4GB只是示例，不能悄悄改变全平台缺省。
- 新增统一部署命令，内部复用登记实例、设置资源与启动部署的既有业务；稳定request_id关联唯一实例与任务，响应丢失可查询收据。创建与任务接纳在一致事务中，接纳失败不留半个新实例；任务执行失败保留该instance_id供继续，不创建替代实例。
- 页面刷新／响应丢失先按request_id查询收据和已有任务，再继续；状态未知时不盲目重发新意图。幂等记录不存凭证明文；原部署任务失败后用现有实例deploy接口重试，不重发新建命令。详见接口约定的重试策略。

### 6.2 后台部署
- 环境预检→生成实例自己的接入包→拉取锁定镜像→创建独立项目、目录、网络、卷／挂载→安装插件与任务→启动→等待真实心跳／接入验证。
- 复用已验证net占位服务持有网络命名空间、每实例独立隧道／代理的方案。一个逻辑智能体可能包含辅助容器，界面不能要求恰好一个物理容器。
- 不使用host网络、privileged、Docker socket挂载或通用宿主目录挂载来方便部署；不改变OpenClaw的工具边界。
- 不同实例的名称相同也必须按UUID隔离。沿用项目唯一标识／受控目录生成方式，禁止用户输入任意部署路径或Compose脚本。
- 同一台服务器同时一个有副作用任务；不同服务器可独立执行。多实例运行不等于多部署任务必须并行。
- 容量不足沿用D4提示，不新增武断硬上限；物理／权限前置条件确实不满足时失败。无限额实例不以0计入已分配汇总，标记“含无限额”。
- Docker启动不代表接入成功；等待超时显示部署失败／等待接入及真实原因，不把IM离线直接认定容器已停止。

### 6.3 重试与管理
- running／succeeded／failed／interrupted复用既有任务状态；API重启后恢复检查并标明中断，用户可继续同一实例。
- 重试只操作当前实例项目，执行前检查已有容器／部署／凭证状态；成功实例不因UI刷新被重新部署、重新签发凭证。
- 卸载／重新部署／运维均用已保存密码；不能在这些分支偷偷回退旧私钥。
- 停用实例的接入权限与停止容器是不同操作，保留原语义。卸载默认保留数据；删除会话／记忆仍沿用现有明确提示与权限。
- 删除服务器必须无部署记录、无进行中任务；不能连带删除智能体。迁移服务器不在本轮自动实现。
- 服务器详情对成功部署、失败待恢复、手动归属和自动识别来源明确标记，计数不会把已登记未部署算成部署成功。

## 7. 旧服务器迁移

旧密码从未保存，**无法从旧SSH私钥还原登录密码**。迁移应做到：
- 加法DDL保留server_id／instance_id／部署目录与全部既有业务数据；旧记录password_set=false，提示“补充服务器登录密码”。
- 现有OpenClaw继续运行、连接、执行已有许可任务，不为本次UI改造强制重装。缺密码期间只阻止需要SSH的新操作。
- 新应用从上线起不生成、安装或使用OpenClaw服务器的SSH客户端密钥；旧密文暂留兼容列，不作为登录回退。
- owner补密码、核对已固定的主机身份并验证密码后，显式完成旧连接迁移：以密码登录，精确移除本工作台那一条公钥；其他用户／Runner的authorized_keys保持。
- 清理成功才清空对应旧私钥引用／公钥记录并审计。离线／拒绝写authorized_keys时标pending或manual_required，显示真实待处理状态，不报告清理完成。
- 本期不在数据库迁移中直接DROP旧列或批量清除私钥；不可逆清理由上述显式退役动作完成，原ADR保留历史，补新ADR记录用户最新决定。
- 禁止一键把旧auto服务器、未知物理主机或另一台服务器的实例强行合并；保持既有指纹归属与手动指定规则。

## 8. 验收与范围外

必须通过：
- 两独立页面、两侧栏入口、旧链接／自定义导航／全局创建／角色守卫不回归。
- 四项连接信息足够，密码只写不读，修改／轮换／失效和旧记录补密码完整。
- 初始化确实装好所需环境，重复执行不创建实例、不影响原容器。
- 一机部署两个真实OpenClaw，均接入；重试／卸载其中一个不改变另一个容器ID、目录、任务与接入状态。
- 服务器页实时查询到部署归属与真实数量，跨服务器／用户／工作空间切换无串数据。
- 所有OpenClaw SSH操作均密码认证，旧公钥定向清理、主机身份校验和Runner回归通过。
- 390/768/1280/1440/1920、亮暗主题、键盘、loading／空／错误／过期／权限变化均验证。

不在本期：批量迁移实例到别的服务器、任意镜像商城、修改第三方数据库、通用SSH终端、自动修改sshd、Kubernetes／集群调度、扩权到admin、删除工作台密钥库或mTLS、重做首页／上一批页面、重新引入n8n。
