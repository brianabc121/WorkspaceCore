# 运行服务器方案（T-0134）：一台高配服务器，给所有智能体跑容器

> 状态：**已批准，实施中**（T-0135 ~ T-0141）。人类 2026-11-06 看过草案后决定：
> **D1** 改为“管理员给实例打开一个运行环境权限，智能体就能在运行服务器上直接执行命令、操作容器”（不再逐项审批）；
> **D2** 按推荐（runner-agent 主动连工作台）；**D11** 不预先设计场景（比如需要安卓端的任务），由智能体按任务要求决定，
> 容器这边配合，而不是拒绝智能体的决定；其余事项“按照推荐的来”。本版已按这些决定改写，第 14 节是最终的决定表。
> 这是 2026-11-06 对话里的“方案 A”：智能体不碰 Docker，经工作台的工具建容器、执行命令，由工作台在运行服务器上执行。
> 核验：Docker Engine 29.9 的接口已在本会话自己的 Docker 上实测（第 9.1 节），gVisor 在 CI 的运行服务器验收里实测，
> 记录见 `docs/decisions/2026-11-06-runner-verification.md`。
>
> **决定原文**（人类 2026-11-06）：
> 1. D1（最重要）= 这里改为智能体可以在容器服务器开启 exec / 操控容器，只需要给一个开启权限就可以；
> 2. D2 按推荐的来；
> 3. D11 不要提前去设计，因为有些场景可能就是需要运行安卓端的，这些需求可以由智能体自行根据任务要求来决定。容器这边只需要配合就可以了，而不是去拒绝智能体的决定。
> 给我根据以上决定，重新优化一下设计方案。之后按照推荐的来给我全部落实方案。
>
> **需求原文**（人类 2026-11-06）：
> 给我按照 A 的方案来设计。有些细节需要调整：未来我会单独开一台服务器，这台服务器将用来跑所有智能体的任务 / 测试等需求，
> 如：1. 智能体 1 号需要安装小红书进行抓取特定博主的内容；2. 智能体 2 号新写了一个项目需要跑测试流程；
> 3. 智能体 3 号需要对智能体 2 号写的项目进行实际跑一遍并作项目评估。
> 还需要创建一个页面能够对这台运行服务器的容器进行管理。之所以这样设计是因为，我只需要一台高配置服务器就可以，
> 而不是为每个智能体的服务器都是高配置。
> 这里跑容器的时候还需要设计好方案，要进行容器区分，有些容器跑完就可以删了，有些容器可能下一次还需要用。
> 为了提高效率，这里需要进行区分，智能体通过 workspace 平台调用并新建容器的时候，需要先考虑好这些事情。
> 同时还需要考虑好什么情况下容器会被回收：1. 创建容器的耗时，越耗时的容器需要尽可能发挥其价值；
> 2. 长时间不调用的容器，可能会出现占用资源的情况，可以先把它们删除掉，但是需要记录容器配置信息，方便下次智能体需要调用的时候能够快速创建容器；
> 3. 其他智能体创建的时候设置的删除回调机制，一旦触发也可以删除掉对应容器。
> 先调研看看业内专家是怎么做的，再根据我们项目的情况，写一份设计方案。

## 0. 一页看懂

```
智能体 1 / 2 / 3 号（各自的 OpenClaw 服务器，低配；OpenClaw 本身仍然不开 exec、不挂 Docker socket）
   │  MCP 工具：runner_templates / runner_template_save / env_create / env_exec / env_files / env_release …
   │  （管理员给实例打开“运行环境权限”后直接执行，不逐项审批）
   ▼
工作台（服务器 A）：权限、限额、模板、环境记录、回收策略、审计、执行记录、管理页面
   ▲  runner-agent 主动连进来（运行服务器凭证，外网再加客户端证书；长轮询领指令、回报结果、每分钟对账）
   │
运行服务器（高配，一台）：runner-agent + Docker + gVisor
   ├─ 环境 A：1 号 · 常驻 · 小红书抓取（登录态和抓取进度在数据卷里）
   ├─ 环境 B：2 号 · 一次性 · 跑测试（跑完就删，只留输出）
   └─ 环境 C：3 号 · 会话 · 评估 2 号的项目（评估 Issue 关闭就删）
```

- **三层东西分开存**：模板（怎么造，长期保留）→ 环境（一个容器加它的数据卷）→ 运行（在环境里执行的一次命令）。
  删容器不丢模板和配置，下次能按记录快速重建。
- **容器分三类**：一次性、会话、常驻。智能体建容器时必须说清用途、类别、复用键和删除条件；工作台先找能复用的，找不到才新建。
- **回收分四种**：空闲到点（运行 → 停止 → 归档 → 删除记录，逐级释放）、删除条件触发（创建时登记的“回调”）、
  资源紧张时按“保留分”从低到高回收（重建越费时的分越高，越晚回收）、管理员手动。
- **智能体自己决定环境**：用哪个镜像、装什么、用哪种运行时（默认 gVisor，需要时选 runc 或带 KVM 的 runc，比如跑安卓模拟器）、
  要不要 root、网络（没有 / 指定域名 / 全部外网）。工作台照做并记下来，不拒绝；只守几条宿主保护（第 8.1 节）。
- **默认值偏安全**：没说的时候按 gVisor、非 root、去掉全部 capability、没有网络；内存 / CPU / 进程数按限额。
- **页面**：智能体 → 运行服务器：总览、环境、模板、运行记录、设置；实例卡片上加“运行环境权限”。全部设置都在网页上完成。

## 1. 目标与边界

- 一台高配运行服务器承担所有智能体的重活：浏览器抓取、跑测试、把项目实际跑起来做评估。OpenClaw 服务器保持低配。
- 智能体不接触 Docker、SSH 密钥和运行服务器本身，只调工作台的 MCP 工具；工作台是唯一的权限来源。
- **一个开关**：管理员在实例卡片上打开“运行环境权限”，这个智能体就能直接建、用、停、删自己的环境，在里面执行任意命令，
  自己定义模板（镜像、安装步骤、运行时、网络、设备）。不逐项审批；管理员随时可以关掉，关掉后它的环境全部停止。
- **按智能体的决定配合**：不预先限定场景。需要安卓端就选带 KVM 的运行时和模拟器镜像；需要装软件就选 root；需要外网就选全部外网。
  运行服务器做不到的（比如没有 `/dev/kvm`）返回清楚的原因，而不是拒绝。
- 同一份方案里回答三件事：容器怎么分类、怎么复用、什么时候回收。
- V1 不做：多台运行服务器的调度（表结构留好 `host_id`）、GPU、Kubernetes、网页终端；
  也不提供会让一个环境接管整台运行服务器的东西：特权容器、挂 Docker socket、挂宿主目录（第 8.1 节）。

## 2. 调研：业内怎么做

### 2.1 各家的做法

| 做法 | 是什么 | 我们借鉴什么 |
|---|---|---|
| **E2B**（AI 智能体沙箱） | 模板由 Dockerfile 定义；构建时先运行启动命令，等就绪检查通过，再给整个沙箱做快照，以后从快照建沙箱。沙箱超时后默认销毁，也可以设成**暂停**：保留文件系统和内存（含运行中的进程），暂停的沙箱不过期，可以自动恢复；暂停耗时约每 GiB 内存 4 秒 | 把费时的准备工作挪到“构建模板”时做一次；“停止但保留”是独立的一档 |
| **Daytona**（AI 代码沙箱） | 三段式自动回收：不活动 15 分钟自动**停止**（0 表示不停）；连续停止 7 天自动**归档**（移出本机）；自动**删除**默认关闭，设成 0 表示停止后立刻删 | 停止 → 归档 → 删除逐级释放资源，每级时长可配；一次性用途就是“停止后立刻删” |
| **Coder**（云开发环境） | 模板 + 工作区；工作区不活动超过阈值变为**休眠**（停止），休眠超过期限自动删除；每次活动把自动停止时间往后推（默认 1 小时） | “活动续期”：每次使用都重新计时；休眠和删除是两个不同的期限 |
| **OpenHands**（编程智能体） | 每个会话一个沙箱容器，会话结束清理容器；远程运行时支持暂停和恢复 | 按工作单元（会话）划分容器，单元结束就回收 |
| **GitHub Actions 自托管 runner** | 官方建议自动扩缩时用**一次性** runner：每个 job 一个全新环境，跑完就销毁，日志在销毁前送出。runner 主动用 HTTPS 长轮询（每次 50 秒）连 GitHub 领任务，GitHub 不需要连进 runner | 测试类任务每次用干净环境；runner-agent 主动连工作台，运行服务器不开入站端口 |
| **Kubernetes** | Job 的 `ttlSecondsAfterFinished`：完成或失败后过 N 秒自动删除（级联删除）。对象之间用 ownerReferences 记录“谁拥有谁”，拥有者没了，垃圾回收自动删掉它拥有的对象 | “跑完 N 秒后删”；删除条件挂在“拥有者”上（任务、Issue、项目），拥有者结束就回收 |
| **Modal**（无服务器沙箱） | 沙箱的文件系统快照就是一个镜像，可以用来建新沙箱；目录快照在最后一次使用 30 天后回收；内存快照（预览功能）7 天过期 | 归档时把关键目录做快照，重建时恢复；快照本身也按“最后一次使用”过期 |
| **Fly Machines** | 空闲时自动停止或**挂起**（suspend 保留内存、恢复更快，但不是所有程序都支持）；有请求自动启动；可设最少保持运行的数量 | “停止”和“挂起”的取舍；V1 只做停止，挂起留到以后 |
| **《Serverless in the Wild》**（微软 Azure Functions，ATC 2020） | 统计每个应用两次调用之间的空闲时长分布，据此决定保活多久、何时预热；比固定保活时长（例如 10 分钟）冷启动明显更少、浪费的内存也更少 | 保活时长不应该一刀切；V1 按“启动耗时”调整，V2 按每个环境的使用间隔自动调整 |
| **GreedyDual-Size**（Cao & Irani 1997，网页缓存） | 缓存淘汰时按“重新获取的代价 ÷ 占用大小”打分，再加上随时间推移的老化；GDSF 再乘上访问频率。分数最低的先淘汰 | 直接对应“越耗时的容器越要发挥价值”：重建越贵、用得越勤、占得越少，越晚回收 |
| **隔离方案** | 普通容器（runc）与宿主共享内核，不适合跑不可信代码；gVisor（runsc）是用户态内核，大多数现有镜像能直接跑，开销小，但不是 runc 的完全替代，有兼容性限制；Kata / Firecracker 是轻量虚拟机，隔离更强、开销更大 | 默认 gVisor；个别不兼容的模板由管理员明确改用 runc |
| **Docker 自身** | 资源限制（`--memory`、`--memory-swap`、`--cpus`、`--pids-limit`）；可写层限额 `--storage-opt size` 只在 overlay2 + XFS（`pquota` 挂载）上可用；`docker checkpoint`（CRIU）仍是实验功能，不支持带终端的容器 | 资源参数由 runner-agent 固定生成；磁盘限额依赖 XFS，部署时准备；V1 不依赖 checkpoint |

### 2.2 共识，以及我们怎么用

1. **先有配方，再有实例**（E2B 模板、Coder 模板、Daytona 快照）。配置和容器分开存，删容器不丢配置 → 第 3 节的“模板 / 环境 / 运行”。
2. **逐级回收**：运行 → 停止（保留磁盘）→ 归档（只留配置和快照）→ 删除（Daytona、Coder）→ 第 5、6.1 节。
3. **一次性的工作用完即删**（GitHub 一次性 runner、Kubernetes TTL、OpenHands）→ “一次性”类别。
4. **保活时长看重建代价和使用规律**（Serverless in the Wild、GreedyDual-Size）→ 第 6.1、6.2 节。
5. **删除挂在拥有者上**（Kubernetes ownerReferences）→ 第 6.3 节的删除条件。
6. **把费时的准备挪到构建时**（E2B、Modal）→ 模板构建；常用的环境可以“做成模板”。
7. **不可信代码要更强的隔离**（gVisor / Kata）→ 第 8 节。
8. **执行端主动连控制端**（GitHub runner 长轮询）→ 第 9 节。

## 3. 三层：模板、环境、运行

| 层 | 是什么 | 谁建 | 保留多久 | 重建代价 |
|---|---|---|---|---|
| **模板** | 怎么造这个容器：基础镜像（拉取后记下 digest）、安装步骤（Dockerfile 里 `FROM` 之后的部分）、启动命令、要保存的目录、默认类别与回收时长、资源、网络与放行域名、用到的密钥名称、运行时（gVisor / runc / KVM）、用户（非 root / root）。每改一次版本号加 1；构建结果是运行服务器上的一个镜像 | 打开了运行环境权限的智能体直接建、改（`runner_template_save`）；管理员也可以在页面上建 | 长期；旧版本的镜像没人用就清理 | 最高：装依赖、下载浏览器，常常要几分钟 |
| **环境** | 从模板（或直接给一个镜像）建出来的一个容器，加上它自己的数据卷：挂在 `/workspace`，`HOME` 也指向这里，所以缓存、浏览器配置、登录态都在卷里。属于创建它的智能体，可以共享给项目成员 | 智能体经 `env_create` | 按类别和回收规则（第 6 节） | 停止的：几秒；归档的：从镜像重建 + 重放初始化步骤 + 恢复快照 |
| **运行** | 在环境里执行的一次命令（如 `npm test`）：命令、超时、退出码、输出、耗时 | 智能体经 `env_exec`；一次性环境建好就跑 | 记录保留 30 天；输出保留 7 天 | — |

每个模板都记下实测耗时：**构建耗时**、**启动耗时**（建容器到就绪）、**初始化耗时**（重放环境自己的初始化步骤）、**恢复耗时**（恢复快照）。
工作台用它们估算每个环境“重新唤起要多久”，显示在页面上，也返回给智能体。

## 4. 容器分三类

| 类别 | 用在 | 例子 | 跑完 / 空闲后 | 数据卷 |
|---|---|---|---|---|
| **一次性** | 跑一次就完，结果是输出或文件 | 2 号跑一遍测试；转一次格式 | 运行结束、取回输出后**立刻删除**；失败的保留 30 分钟（只停止，方便查看），然后删除 | 跟容器一起删 |
| **会话** | 接下来一段时间要反复用，但没有要长期保存的东西 | 3 号把项目跑起来做多轮评估；调试一个问题 | 空闲 15 分钟停止；停止 24 小时归档（不做快照）；删除条件触发时删除 | 停止时保留，归档时删除 |
| **常驻** | 里面有重建很贵或者重建不出来的东西 | 1 号的小红书抓取（登录态、抓取进度）；2 号开发中的项目 | 空闲 30 分钟停止（只释放内存和 CPU）；14 天没用归档：先把要保存的目录做快照，再删容器和数据卷 | 停止时保留；归档时做快照后删除 |

“空闲”的意思是：没有正在执行的运行，也没有被调用。每次调用都重新计时（Coder 的活动续期）。
各档时长是默认值，管理员可以在设置里改，也可以按模板改。

### 4.1 智能体建容器前必须回答的问题（`env_create` 的必填参数）

| 问题 | 参数 | 说明 |
|---|---|---|
| 做什么 | `purpose` | 一句话，显示在页面上 |
| 用完就扔，还是还要用 | `lifetime`：`once` / `session` / `persistent` | 按下表选 |
| 同一件事下次怎么认出来 | `reuse_key` | 同一件事用同一个键，如 `xhs:博主A`、`project:<项目>:dev`。一次性可以不填 |
| 什么时候可以删 | `delete_when` | 至少一个条件（第 6.3 节）；一次性默认“这次运行结束” |
| 要多少资源 | `resources` | 不超过模板上限；不填用模板默认 |
| 给谁用 | `share` | 只有自己（默认）/ 项目成员 / 指定的智能体 |

工具说明里给智能体的选择规则：

| 情况 | 选 |
|---|---|
| 跑一次就完 | 一次性 |
| 接下来几小时要反复用，没有要长期保存的东西 | 会话 |
| 里面有登录态、抓取进度、开发中的代码、很大的缓存 | 常驻 |

工作台的把关：
- **先复用**：同一个智能体（或共享给它的）已经有同模板、同 `reuse_key` 的环境，`env_create` 直接返回它（停止的会启动，归档的会重建），
  并说明“已复用”；只有传 `new: true` 并写明理由才另建。
- **提示改类别**：24 小时内用同一个 `reuse_key` 建了 3 次以上一次性环境，返回提示建议改用会话；常驻环境 7 天没用，提醒创建者确认还要不要。
- **超限额**不建，返回原因（第 8.4 节）。

## 5. 生命周期

| 状态 | 占用 | 怎么来 | 再次使用要多久 |
|---|---|---|---|
| `creating` 创建中 | 磁盘 | `env_create` | — |
| `running` 运行中 | 内存 + CPU + 磁盘 | 创建完成、启动、有人调用 | 立即 |
| `stopped` 已停止 | 磁盘（可写层 + 数据卷） | 空闲到点、管理员停止、资源紧张 | 几秒（`docker start` + 启动命令） |
| `archived` 已归档 | 只有工作台里的配置记录，加上对象存储里的快照（常驻才有） | 停止到点、资源紧张、管理员归档 | 镜像还在：启动耗时 + 初始化耗时 + 恢复耗时；镜像被清了：再加构建耗时 |
| `pending_delete` 待删除 | 同上一个状态 | 删除条件触发 | 宽限期内可以撤销 |
| `deleted` 已删除 | 只有记录（30 天） | 删除完成 | 不能恢复；同一个 `reuse_key` 再建是新的环境 |
| `failed` 失败 | 视情况 | 构建、创建或启动失败 | 管理员看日志处理 |

调用一个停止或归档的环境（`env_exec`、`env_files`）会自动唤起它；返回里带“唤起用了多久”。

## 6. 回收

### 6.1 空闲到点（逐级释放）

| 类别 | 空闲 → 停止 | 停止 → 归档 | 归档 → 删除 |
|---|---|---|---|
| 一次性 | 运行结束立刻删除（失败的停止 30 分钟后删除） | — | — |
| 会话 | 15 分钟 | 24 小时 | 归档后 30 天删记录 |
| 常驻 | 30 分钟 | 14 天 | 不自动删除；配置记录一直保留，直到创建者或管理员删除 |

**启动越慢，停得越晚**：空闲 → 停止的时长取 `max(类别默认, 启动耗时 × 20)`，最多 2 小时。
例如启动要 3 分钟的服务（加载模型、预热缓存），会话类空闲 60 分钟才停。
V2 按每个环境实际的使用间隔自动调整（《Serverless in the Wild》的做法：间隔大多在 40 分钟以内的，就保活 40 分钟）。

### 6.2 重建代价与保留分（“越耗时越要发挥价值”）

资源紧张时，工作台要选先回收谁。每个环境算一个**保留分**，分低的先回收：

```
保留分 = 重建耗时（秒） × 使用频率 ÷ 占用 × 老化系数
```

- **重建耗时**：回收这一级之后再用要多久。运行中的看启动耗时；停止的看归档后重建的耗时；
  常驻环境没有快照、数据重建不出来时记为“无穷大”，**不会被自动归档**，只会被停止，并通知管理员。
- **使用频率**：近 7 天的调用次数加 1。
- **占用**：运行中的看内存（GB），停止的看磁盘（GB）。
- **老化系数**：每空闲 7 天减半，免得很久以前很贵的环境永远占着资源（GreedyDual-Size 的“老化”）。

“越耗时越要发挥价值”还落在这几处：
- 模板镜像按同样的分数清理：构建越慢、用得越多、越小的镜像越晚清理；当前版本的镜像只在磁盘告急时才清。
- 启动慢的环境停得晚（6.1）。
- 先复用再新建（4.1）；可以共享给项目成员（第 7 节的 3 号）。
- 一个环境初始化很慢、又被反复重建，页面提示管理员“做成模板”：把它当前的文件系统存成新的模板版本（`docker commit`），以后建出来就带着这些东西。

### 6.3 删除条件（“删除回调”）

建环境时登记一个或多个条件，任何一个满足，环境进入“待删除”：

| 条件 | 例子 |
|---|---|
| `run_finished` | 这次运行结束（一次性的默认值） |
| `task_done:<任务>` | 任务完成或关闭 |
| `issue_closed:<Issue>` | 评估 Issue 关闭 |
| `project_archived:<项目>` | 项目归档 |
| `at:<时间>` | 到某个时间 |
| `idle:<时长>` | 空闲多久（比类别默认更短时才有意义） |
| `released` | 创建者调用 `env_release` |
| 总是生效 | 创建者实例被停用或删除；运行服务器被移除 |

- 条件挂在“拥有者”上（Kubernetes ownerReferences 的思路）：任务、Issue、项目由谁结束都算。
  比如 2 号建环境时登记了 `issue_closed:#12`，3 号评估完关闭了 #12，2 号的环境就会被回收——这就是“其他智能体创建时设置的删除回调，一旦触发也可以删除”。
- 判断方式：相关事件发生时立即检查，另外每 5 分钟对账一次，防止漏掉（与工作台“事件 + 周期对账”的一贯做法相同）。
- **宽限期**：一次性、会话的待删除 5 分钟后删除；常驻的 24 小时后删除，期间通知创建者（IM）和管理员，可以撤销。
  常驻环境删除前先做快照，快照保留 30 天，可以从页面恢复。
- 正在执行运行的环境，等这次运行结束（或超时）再删。
- 谁能改条件：创建者和管理员。其他智能体不能删别人的环境，只能对共享给它的环境调用 `env_release`（表示“我不用了”）。

### 6.4 资源紧张时

| 水位 | 动作 |
|---|---|
| 内存预留 > 85% 或磁盘 > 80% | 按保留分从低到高回收：先停止运行中的空闲环境，再归档停止的环境，再清理镜像，直到内存 < 70%、磁盘 < 65% |
| 新建或启动时资源不够 | 先按上一行回收；仍然不够就排队（最多 10 分钟），返回“排队中，第 N 位”，开始后用 IM 唤醒智能体 |
| 磁盘 > 95% | 紧急：拒绝新建，停止一次性运行，通知管理员（runner-agent 本地执行，不依赖工作台在线） |

不会被自动回收：管理员“保护”的环境、正在执行运行的环境。被保护的环境计入限额。

### 6.5 配置记录与快速重建（“删了也能快速建回来”）

环境归档或删除时，工作台保留它的**配置记录**：

- 模板版本（含镜像 digest）、资源、网络策略与放行域名、密钥名称（不含值）、共享范围、复用键、删除条件；
- 环境自己的**初始化步骤**：智能体用 `env_setup` 登记的命令（如 `git clone …`、`npm ci`），重建时按顺序重放；
- 常驻环境的**快照**：模板里声明的“要保存的目录”（如浏览器配置、抓取进度、代码目录）打包加密，存到工作台现有的对象存储，单个上限 5 GB（可调）。

重建 = 用模板镜像建容器 → 恢复快照 → 重放初始化步骤 → 启动命令 → 就绪检查。
页面和 `env_find` 都显示预计耗时；镜像已被清理的，会先在后台重新构建模板。

## 7. 三个例子

**1 号：抓取小红书特定博主的内容**
1. 1 号自己用 `runner_template_save` 建模板 `xhs-browser`：Playwright + Chromium 镜像；网络放行小红书相关域名（或全部外网）；
   要保存的目录 `profile`（登录态）与 `data`（抓取进度和结果，都在 `/workspace` 下）；默认类别常驻；内存 4 GB。
   如果 1 号判断要用安卓 App，就选安卓模拟器镜像和 `kvm` 运行时（运行服务器要开启硬件虚拟化，没有 `/dev/kvm` 时返回原因）。
2. 1 号 `env_create(template="xhs-browser", lifetime="persistent", reuse_key="xhs:博主A", delete_when=["project_archived:<项目>"])`，
   第一次在环境里完成登录（扫码等需要人参与的步骤由管理员配合）。
3. 每天用 `schedule_wakeup` 叫醒自己，`env_exec` 跑抓取脚本，结果用 `env_files` 取回，写进知识库或附到 Issue。
4. 两次抓取之间空闲 30 分钟就停止（释放内存，登录态还在）；第二天调用时几秒内启动。
5. 14 天没用就归档：登录态和抓取进度做快照，删容器和数据卷；下次用同一个 `reuse_key` 调用时，从快照建回来，不用重新登录（只要登录态还有效）。

用网页版还是安卓 App 由 1 号按任务决定（第 14 节 D11）；运行服务器只负责提供它要的运行时与设备。
抓取对象、频率与用途要符合平台条款和法律法规（如个人信息保护），由管理员在任务里说明。

**2 号：写了一个项目，要跑测试流程**
1. 2 号的开发环境是常驻的（`reuse_key="project:<项目>:dev"`，模板 `node22` 或 `python312`），代码就在它的数据卷里，同时推到 Git。
2. 跑测试用一次性环境：`env_create(template="node22-test", lifetime="once", from_environment=<开发环境>, command="npm ci && npm test")`。
   工作台把开发环境的工作目录复制进一个全新的容器（干净环境，GitHub 一次性 runner 的做法），跑完取回输出和测试报告就删除。
3. 依赖下载慢时，模板可以给每个智能体配一个**缓存卷**（npm / pip 缓存），一次性环境挂上它，只属于这个智能体，不跨智能体共享（防止缓存被别人投毒）。
4. 需要数据库的测试，在模板里声明附属服务（如 `postgres:16` 的锁定 digest），和测试容器在同一个独立网络里一起启动、一起删除。

**3 号：把 2 号的项目实际跑一遍并评估**
1. 2 号把开发环境共享给项目成员（`share=project`，权限“复制”）。
2. 3 号 `env_create(lifetime="session", from_environment=<2 号的开发环境>, reuse_key="eval:<项目>", delete_when=["issue_closed:<评估 Issue>"])`，
   得到一份复制出来的环境：怎么折腾都不影响 2 号。
3. 3 号启动服务、跑多轮评估命令、看日志，把评估结论写进 Issue。
4. 评估 Issue 关闭 → 删除条件触发 → 5 分钟后删除。中途空闲 15 分钟会先停止，再用时几秒恢复。

## 8. 隔离与安全

### 8.1 智能体决定什么，哪些不变

**智能体决定**（工作台照做、记下来，不拒绝；没说的用默认值）：

| 项 | 可选 | 默认 |
|---|---|---|
| 镜像 | 任何能拉到的镜像，或自己写安装步骤构建（拉取后锁定 digest，记进配置记录） | — |
| 运行时 | `gvisor`（用户态内核，隔离最强）/ `runc`（普通容器，兼容最好）/ `kvm`（runc 加 `/dev/kvm`，给安卓模拟器、虚拟机类程序） | `gvisor` |
| 用户 | `user`（uid 1000，去掉全部 capability）/ `root`（root，Docker 默认的 capability，用来装软件） | `user` |
| 网络 | `none` / `allowlist`（只放行指定域名）/ `all`（全部外网） | `none` |
| 资源 | 内存、CPU、进程数、磁盘 | 模板或系统默认，不超过限额（8.4） |
| 类别与回收 | 第 4、6 节 | 模板默认 |

**不变的宿主保护**（保护运行服务器本身和别的智能体的环境，任何选项都不打开）：
- 不用特权模式（`--privileged`），不加 Docker 默认之外的 capability，始终 `no-new-privileges`；
- 不挂 Docker socket，不挂宿主目录，只用工作台建的命名数据卷；不用宿主网络、宿主 PID；
- 网络出口只经运行服务器上的出口代理，私有网段、本机、云厂商元数据地址（如 `169.254.169.254`）、工作台和 OpenClaw 服务器永远到不了；
- 每个环境一个独立网络，环境之间不通；资源按限额，超过就排队或回收（第 6.4 节），不超卖内存。

运行服务器做不到的（没有 `/dev/kvm`、镜像拉不到、构建失败）返回 Docker 的原因，智能体可以换做法。
runner-agent 只执行工作台下发的固定指令；容器参数由 runner-agent 按上表生成，指令里不能直接带任意 Docker 参数。
运行服务器专用：不放其他业务数据，不和工作台、OpenClaw 共用一台机器。runner-agent 挂着本机的 Docker socket，
等同于这台机器的 root，所以这台机器要当成可以随时重装的。

### 8.2 容器参数（runner-agent 按选项生成，已在 Docker 29.9 上实测，第 9.1 节）

| 项 | 做法 |
|---|---|
| 运行时 | `HostConfig.Runtime` = `runsc` / `runc`；`kvm` 另加 `Devices: /dev/kvm` |
| 用户 | `user`：`User=1000:1000`、`CapDrop=[ALL]`；`root`：`User=0:0`，Docker 默认 capability；两者都 `SecurityOpt=[no-new-privileges:true]`、`Init=true` |
| 资源 | `Memory` 与 `MemorySwap` 相同（不用 swap）、`NanoCpus`、`PidsLimit`；磁盘按定期测量（`/system/df`），超限停止（XFS `pquota` 限额以后再做） |
| 文件系统 | 数据卷挂 `/workspace`，`HOME=/workspace/.home`；`/tmp` 用 tmpfs；密钥放 `/run/secrets`（tmpfs） |
| 工作目录 | 容器本身**不设** `WorkingDir`，每次 exec 才设 `/workspace`：镜像里没有这个目录时 Docker 会按 root 创建并把属主复制到空数据卷上（实测），非 root 用户就写不进去 |
| 常驻进程 | 没有启动命令时用 `sh -c` 的等待循环保持运行；有启动命令（服务）就用它 |
| 日志 | json-file，单个 10 MB、保留 2 个 |
| 标签 | `myworkspace.runner`、`myworkspace.env`、`myworkspace.workspace`：对账只认带标签的，**不碰没有标签的容器** |

### 8.3 网络

- 每个环境一个 `internal` Docker 网络：直连外网不通（实测 `Network is unreachable`）；runner-agent 以别名 `egress` 连进这个网络，
  环境里的 `HTTP_PROXY` / `HTTPS_PROXY` 指向它（实测同一网络里按别名可达）。
- 出口代理按环境的网络选项判断：`none` 全部拒绝；`allowlist` 只放行列表里的域名（支持 `*.example.com`）；`all` 放行任何公网地址。
  无论哪种，代理先解析域名，**只连已经检查过的公网 IP**（防止 DNS 重绑定），私有网段一律拒绝。访问记录（域名、端口、字节数、放行与否）上报工作台。
- V1 只支持经代理的 HTTP / HTTPS（`CONNECT`）；pip、npm、apt、git over https、浏览器、安卓模拟器（`-http-proxy`）都能用。
  原始 TCP / UDP 直连外网以后再做（要在运行服务器上加防火墙规则，见第 17 节）。

### 8.4 限额（管理员按实例设，下面是默认值）

| 项 | 默认 |
|---|---|
| 同时运行的环境 | 3 个（常驻最多 2 个） |
| 内存合计 / CPU 合计 / 磁盘合计 | 16 GB / 8 核 / 100 GB |
| 每小时 `env_exec` | 120 次 |
| 每天运行总时长 | 8 小时 |

整台服务器：内存按上限累计，不超卖（留出系统预留）；CPU 可以超卖到 2 倍；磁盘按水位（6.4）。
限额管的是共用一台服务器的公平，不管智能体做什么：超过时先回收空闲的、再排队，仍不够才返回原因。

### 8.5 密钥

- 工作台密钥库里的密钥，只有管理员已授权给这个实例的（密钥库的实例授权，实例卡片的运行环境权限里列出），才能被这个实例的模板与环境引用（`secrets: [名称]`）；
  启动时以文件形式注入到 tmpfs（`/run/secrets/<名称>`），不进镜像、不进日志、不进快照。
- **容器里的程序能读到注入的密钥**，所以只给专用、权限最小的密钥。输出按已知密钥值精确匹配脱敏，再过一遍现有的密钥扫描；
  挡不住有意编码后带出，这是已知风险，靠出口记录和审计发现。
- 快照里可能有登录态，按密钥对待：加密保存（工作台现有的加密），页面上不能下载原文。

### 8.6 记录与通知

- 每次建、启动、停止、归档、删除、`env_exec`、模板保存与构建都留执行记录（“AI 工具执行”，标明直接执行）和审计；命令原文脱敏后记录。
- 选了 `runc` / `kvm` / `root` / `all` 的环境在页面上标出来，并通知管理员一次（不是审批，只是让管理员知道）。
- 输出：工具最多返回最后 16 KB；完整输出最多 1 MB，存在运行记录里 7 天。
- 通知管理员：新建常驻环境、常驻环境将被归档或删除、资源告急、限额用满、发现记录外的容器或丢失的容器。

## 9. 运行服务器与工作台怎么连（runner-agent）

- **添加**：管理员在页面上添加运行服务器，走现有的 SSH 自动部署流程（T-0089：先显示主机指纹、确认后安装；密码只用一次，换成专用密钥）。
  工作台装好锁定版本的 Docker（`install-docker.sh`，29.9.1）、gVisor（release-20261019.0，官方 tarball，校验 sha512，`runsc install`）
  和 runner-agent，并签发运行服务器凭证（`mwr_` 开头，工作台只存哈希）；外网再加客户端证书（沿用实例的内部 CA）。用户不需要在终端里做任何事。
- **runner-agent**：只用 Python 标准库，跑在锁定 digest 的 `python:3.12.15-slim-trixie` 里，代码随接入包下发（`app/runner_agent/`）。
- **连接**：主动连工作台的接入入口（新增 `/runner-api/v1/*` 路径），长轮询领指令（GitHub runner 的做法）；运行服务器不需要开入站端口。
- **指令**：`pull_image`、`build_template`、`create_env`、`start_env`、`stop_env`、`exec`、`put_files`、`get_files`、`snapshot`、`restore`、`delete_env`、`prune_images`。
  每条指令有 id，runner-agent 按 id 去重（重复下发不会执行两次）。`exec` 是写操作：超时或断线时记为“结果未知”，不自动重跑，由对账确认；
  单个 exec 无法单独终止，超时后停止这个容器（数据卷保留）。
- **文件进出**：用只创建、不启动的助手容器挂同一个数据卷，经 Docker 的 archive 接口读写（实测可行，与环境用哪种运行时无关）；
  新数据卷先用一次性助手容器把属主改成 1000。
- **对账**：每分钟上报本机所有带工作台标签的容器、数据卷、网络、镜像及占用；工作台比对：
  记录里有、实际没有 → 标为丢失并通知；实际有、记录里没有 → 先停止，24 小时后删除。**没有工作台标签的一律不碰**。
- **断线保护**：运行超时、一次性环境的最长存活、磁盘告急，由 runner-agent 在本机执行，工作台掉线也守得住；但断线时不会自己归档或删除常驻环境。
- **指标**：上报 CPU、内存、磁盘与每个容器的用量。
- **升级**：页面上一键重新部署 runner-agent，容器和数据卷不受影响。

### 9.1 已实测的 Docker 行为（Docker 29.9.2，API 1.56，runc）

资源与安全参数按值生效；exec 的多路复用流能拆出 stdout + stderr，退出码正确，uid 1000、CapEff 为 0；
未启动的助手容器能读写数据卷里的文件，属主正确；`internal` 网络直连外网不通，同一网络里按别名能访问出口代理；
exec 超时按时返回；输出超过上限保留开头与结尾；进程数上限生效（`Cannot fork`）；stats 一次性读到内存与 CPU；`/system/df` 给出数据卷占用；
按标签列出与删除干净；镜像不存在时 404；没有 `/dev/kvm` 时返回 `no such file or directory`。gVisor 下的同一套行为在 CI 里实测（T-0141）。

## 10. 智能体的工具（MCP）

| 工具 | 读 / 写 | 做什么 |
|---|---|---|
| `runner_templates` | 读 | 能用的模板（自己的、管理员建的、共享的）：用途、默认类别、运行时、网络、资源、预计启动耗时 |
| `runner_template_save` | 写 | 新建或修改自己的模板：基础镜像、安装步骤、启动命令、运行时、用户、网络与域名、资源、要保存的目录、密钥名称；保存后在运行服务器上构建，返回构建结果 |
| `env_find` | 读 | 按模板、`reuse_key`、用途找自己的和共享给自己的环境；返回状态、上次使用、预计唤起耗时 |
| `env_create` | 写 | 第 4.1 节的必填参数；`template` 或直接给 `image`（加可选的运行时、用户、网络）；先复用；`lifetime=once` 时必须带 `command`，建好就跑，跑完就删；可选 `from_environment`（复制工作目录）、`files`（初始文件） |
| `env_exec` | 写 | 在环境里执行命令（参数数组，或者一段 shell 脚本）；60 秒内结束的直接返回退出码和输出；更久的返回运行编号，结束后用唤醒叫醒智能体 |
| `env_run` | 读 | 查一次运行的状态和输出 |
| `env_files` | 读 / 写 | 列目录、上传、下载 `/workspace` 下的文件（单个文件上限 20 MB） |
| `env_setup` | 写 | 登记或修改这个环境的初始化步骤（重建时重放） |
| `env_update` | 写 | 改删除条件、共享范围、用途（只有创建者） |
| `env_stop` | 写 | 主动停止（释放内存，保留数据） |
| `env_release` | 写 | “我不用了”：创建者调用会触发 `released` 条件；别人调用只是不再使用共享的环境 |

- 没打开“运行环境权限”的实例看不到这些工具（与例外三、六、七相同）。
- `env_*` 只作用于自己的环境或共享给自己的环境；模板只能改自己建的；工作台按工作空间、实例和共享关系校验。

## 11. 页面

入口：**智能体 → 运行服务器**（`/runner`）。只有 owner / admin 能看；手机宽度可用、不横向滚动。

| 标签 | 内容 | 操作 |
|---|---|---|
| **总览** | 服务器在线状态、Docker / gVisor 版本、有没有 `/dev/kvm`；CPU、内存、磁盘的用量；磁盘分成镜像 / 容器 / 数据卷；按类别和状态的环境数；每个智能体的用量与限额；告警；最近的回收记录（回收了什么、为什么：空闲 / 条件 / 资源紧张 / 手动，释放了多少） | 立即对账、清理无用镜像 |
| **环境** | 列表，按智能体、模板、类别、状态筛选。每行：用途、智能体、模板、类别、运行时 / 用户 / 网络（非默认的标出来）、状态、当前用量 / 上限、上次使用、**下一步**（如“18 分钟后停止”“3 天后归档”）、删除条件、预计唤起耗时、保留分 | 启动、停止、归档、删除、保护、改删除条件、查看运行与输出 |
| **模板** | 模板与版本：谁建的（智能体 / 管理员）、镜像 digest、运行时、网络、构建状态与日志、构建耗时、镜像大小、使用次数 | 新建、修改、重新构建、停用 |
| **运行记录** | 每次运行：命令（脱敏）、智能体、环境、退出码、耗时、输出 | 查看输出 |
| **设置** | 运行服务器（添加、重新部署、移除）、回收策略（各类别时长、水位、快照上限） | 保存（带版本号，防止两个人同时改） |

## 13. 与现有规则的关系

- `docs/AGENTS.md` 第 8 节：“不得放宽 OpenClaw 智能体的工具限制（只开工作台工具和 IM 发消息工具），不得开启 exec 或挂载 Docker socket”。
  OpenClaw 服务器上这条不变；在运行服务器上执行命令是人类 2026-11-06 新增的**例外八**：
  > 例外八：管理员按实例打开“运行环境权限”后，智能体经工作台在运行服务器上建、用、停、删自己的容器环境，在里面执行命令，并自己定义环境模板（镜像、安装步骤、运行时、用户、网络、设备）（`runner_*` / `env_*` 工具），直接执行、不审批；工作台按智能体的决定配合，不预先限定场景。它们仍必须经过权限范围、角色、限额、执行记录、审计与通知管理员的保护，并且不得使用特权模式、挂载 Docker socket 或宿主目录、使用宿主网络，不得访问私有网段、工作台与 OpenClaw 服务器；只能注入管理员给这个实例勾选的密钥；OpenClaw 服务器本身仍然不开 exec、不挂 Docker socket（人类 2026-11-06 决定；见 `docs/v2/RUNNER_PLAN.md`）。
- 工作台是唯一的权限来源：runner-agent 只执行工作台下发的指令，不接受智能体直连。
- 外部 HTTP 与写操作：runner-agent 与工作台之间有超时、重试上限；`exec` 结果未知时不自动重跑，靠对账确认。
- 第三方接口核验：Docker Engine API 与 gVisor 在锁定版本上核验（第 9.1 节、核验记录），不按名称猜接口。
- 设置放在网页上：添加运行服务器、开权限、改限额和回收策略都在页面上完成；部署指南只写“准备一台装好 Linux、能 SSH 登录的服务器”。

## 14. 决定（人类 2026-11-06）

| # | 事项 | 决定 |
|---|---|---|
| D1 | 智能体用运行环境要不要审批 | **人类决定**：只要管理员给实例打开一个“运行环境权限”，智能体就能直接执行命令、操作容器、自己定义模板；不逐项审批（例外八） |
| D2 | 工作台怎么控制运行服务器 | 按推荐：**runner-agent 主动连工作台** |
| D3 | 隔离方式 | 按推荐并依 D1、D11 调整：**默认 gVisor**；智能体可以自己选 runc 或带 KVM 的 runc，记下来并通知管理员 |
| D4 | 默认网络 | 按推荐并依 D1 调整：**默认没有网络**；智能体可以选指定域名或全部外网；私有网段永远禁止 |
| D5 | 回收默认值 | 按推荐：**第 6.1 节的表** |
| D6 | 常驻环境归档时做不做快照 | 按推荐：**做**，加密存对象存储，单个上限 5 GB，最后使用 30 天后清理 |
| D7 | 跨智能体共享 | 按推荐：**默认不共享**；创建者可以共享给项目成员，权限分“使用”和“复制” |
| D8 | 谁能删环境 | 按推荐：**创建者和管理员**；其他智能体只能 `env_release`，或者触发创建者登记的条件 |
| D9 | 模板从哪来 | 依 D1 调整：**智能体直接建、改自己的模板**，管理员也可以建；不需要批准 |
| D10 | 运行服务器归属 | 按推荐：**一台属于一个工作空间** |
| D11 | 安卓等特殊场景 | **人类决定**：不预先设计，由智能体按任务决定；运行服务器提供 `kvm` 运行时等配合，做不到时返回原因 |
| D12 | 容器里跑 Docker | 按推荐：V1 不提供（需要特权模式，会让环境接管整台运行服务器）；测试要的数据库等用模板的附属服务或同一网络里的另一个环境 |

## 16. 风险

| 风险 | 对策 |
|---|---|
| 智能体选了 runc / root / 全部外网，隔离变弱 | 人类的决定（D1、D11）；宿主保护不变（第 8.1 节）；页面标出非默认选项并通知管理员；运行服务器专用、可重装 |
| 容器逃逸，拿下运行服务器 | 默认 gVisor；不开特权、不挂 socket 和宿主目录；runner-agent 的身份只能调 `/runner-api/v1/*`，拿不到工作台别的接口 |
| 工作台被攻破，用来在运行服务器上乱建容器 | runner-agent 只接受固定指令，宿主保护在本机生成参数时强制，不看指令里的值 |
| 智能体滥用算力（挖矿、刷接口） | 限额、CPU 监控告警、出口记录、执行记录；管理员一键关掉权限，环境全部停止 |
| 注入的密钥被带出 | 只注入管理员勾选的专用最小权限密钥；出口记录；审计 |
| 抓取被平台封号或有法律风险 | 管理员在任务里说明对象和频率；不抓个人隐私信息 |
| 磁盘被镜像、数据卷、快照塞满 | 水位回收、镜像清理、快照过期 |
| gVisor 不兼容某些程序 | 智能体可以换 runc；构建后跑一次自检 |
| 回收太狠，智能体反复重建 | 启动越慢停得越晚；回收记录可查；V2 按使用间隔自动调整 |

## 17. 以后再做

- 多台运行服务器的调度（按剩余资源和镜像是否已缓存选机器）。
- 原始 TCP / UDP 直连外网（运行服务器上加防火墙规则，仍然挡住私有网段）。
- 按每个环境的使用间隔自动调保活时长（《Serverless in the Wild》的直方图策略）、预热。
- 挂起（保留内存）：等 Docker checkpoint 或 gVisor 的 checkpoint 稳定后再评估。
- XFS `pquota` 磁盘限额、Kata / Firecracker、GPU、本地镜像仓库（清理后的镜像从仓库拉回，不用重建）、容器里跑 Docker（Sysbox 或 gVisor 内的 Docker）。
