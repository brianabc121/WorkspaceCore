# 大模型聚合聊天页面：开发文档

> 人类 2026-11-13 要求：给“大模型客户端管理”加一个查看页面，可以像大模型客户端一样浏览每个大模型的全部会话、向大模型提问；
> 参考业内做法做成聚合聊天页面，先出效果图。效果图确认后（2026-11-13 回复“可以”），要求写开发文档并全面落实。
>
> 效果图（5 张，可缩放画布）：<https://claude.ai/artifact/CfPBeadzJS6Q89wvA6Ehxk>
> 前置：`docs/v2/LLM_BRIDGE_PLAN.md`（会话桥方案；第 19 节是“大模型客户端管理”）。本文只写聊天页面新增的部分。

## 1. 人类定下来的三件事

| 问题 | 决定 |
|---|---|
| 谁能用聊天页 | 只有 owner 和 admin。成员用的话花的是 owner 的账号额度，先不开放 |
| 能不能接着智能体的会话继续发 | 可以看；继续发之前要确认一次“这是某个智能体的会话”，后端也要求带上确认标记 |
| 多模型同问 | 第一步做单会话聊天，第二步做同问（并排对比） |

## 2. 参考了什么

- Open WebUI：侧栏会话列表、按标题和内容搜索；模型选择器里的 Compare 开关，两个模型并排回答。
- ChatHub / ChatALL：同一个问题同时发给多个模型，单栏、两栏、三栏、2×2 布局。
- LobeChat、Cherry Studio：把接入的模型放进同一个选择器（来自第三方对比文章）。

和这些产品不一样的地方由我们的做法决定：

- 会话属于某个 MCP 管理器（一套账号），所以多了“管理器”和“平台”两层筛选。
- 每个会话是平台官方程序里的一个原生会话：**模型在新建会话时选，中途不换**。
- 人和智能体共用同一套账号，所以每个会话标出是谁建的（我、别的管理员、某个智能体、官方程序里已有）。
- 开发会话可以展开“过程”：读了哪些文件、执行了哪些命令。

## 3. 页面

入口还是侧栏的“大模型客户端”（路由 `/llm_bridge`），页面顶部两个标签：

- **聊天**（默认）：`/llm_bridge`，选中的管理器和会话放在查询参数里（`?m=<管理器>&s=<会话>`，新建是 `?m=…&new=1`）。
- **管理器与账号**：`/llm_bridge?view=manage`，就是原来的管理页面。

没有任何管理器时，聊天页显示说明和“去添加 MCP 管理器”的入口。

### 3.1 聊天主界面（效果图 1）

- **左栏：会话列表**
  - 管理器下拉（名字 + 它控制的平台）；“新建会话”；按标题搜索；按平台筛选（带是否已登录的标记）。
  - 会话按“今天 / 昨天 / 更早”分组；每行：平台标记、标题、用法（对话 / 开发）、谁建的、时间；正在回答的标出来。
  - 可以切换看“已归档”；“同步官方程序里的会话”。
- **中间：对话**
  - 标题、平台、模型、用法与环境、管理器；“改标题”“归档”。
  - 我发的在右，回答在左；回答按纯文字显示，三个反引号围起来的部分显示成代码块（不执行、不当 HTML）。
  - 回答分段陆续出现（平台每给出一段就显示一段，不是逐字）；开发会话的“过程”可以展开。
  - 失败、结果未知、已取消的回合如实显示原因。
  - 输入框：Enter 发送，Shift + Enter 换行；正在回答时显示“停止”；同一个会话上一条没答完时，下一条排队。
- **右栏：会话信息**：平台、模型、用法、环境、管理器、谁建的、开始时间、回合列表。窄屏时收起。

### 3.2 新建会话（效果图 3）

依次选：管理器 → 平台（只列这个管理器控制的；没登录的不能选，给出“去登录”）→ 用法（对话 / 开发）→ 模型、推理强度（平台支持时）→ 开发环境（只有“开发”要选）→ 第一条消息。

### 3.3 手机宽度（效果图 4、5）

列表和对话分成两屏：点会话进入对话，左上角返回列表；会话信息从右上角打开。

### 3.4 多模型同问（效果图 2，第二步）

选几个“管理器 + 平台 + 模型”，同一个问题同时发出；每个模型各开一个会话，并排显示，各自可以停止、可以点“在这个会话里继续”回到单会话。可以跨管理器。

- 入口：左栏的“多模型同问”（地址 `?compare=1`）。打开时先把当前管理器上已登录、能对话的平台加进来；
  “添加一个模型”里可以换管理器、平台、用法、模型（开发会话要选开发环境）。2 ~ 6 个。
- 一组的地址是 `?g=<分组>`；左栏最上面的“同问”列出各组（可以跨管理器，所以不随选中的管理器变）。
- 每个模型一栏：平台、模型、管理器、状态、这个会话的消息；“停止这一个”“在这个会话里继续”“复制回答”。
  某个目标没建成（没登录、限额）时这一栏写明原因，其余照常。
- 下面的输入框向每一栏继续发；别人建的一组，接着发之前确认一次。
- 归档一组只是不再并排显示：每个模型的会话不受影响，还在各自管理器的会话列表里，可以单独继续。
- 手机宽度下一次看一栏，用上面的标签切换。

## 4. 做法

```
浏览器 ──（会话 Cookie + CSRF）──> 工作台后端 /api/v1/llm_bridge/bridges/{id}/chat/…
                                      │  owner / admin；代表“这个人”去调用
                                      ▼
                               MCP 管理器（会话桥）
                                 ├─ /mcp 工具：新建、发送、取消、归档、模型、环境（带调用方）
                                 └─ /admin：会话列表、会话内容、回合进度、改标题
```

- **人也是一个调用方**。工作台代表登录的人调用会话桥，调用方编号是 `user:<用户 id>`，名字是这个人的显示名，
  权限范围是 write、account、takeover。会话桥原有的规则照常生效：会话归属、每个调用方每小时的发送次数、
  同一个会话串行、幂等号、密钥拦截、账号一致性、只能用管理器控制的平台。
- **浏览器不直连会话桥**，也拿不到管理令牌。
- **回答怎么陆续显示**：会话桥在回合进行中把平台给出的每一段回答、每条命令、改动的文件记成事件。
  页面在有回合进行时反复请求“这个会话在某个事件之后的新事件”，会话桥最多挂起 25 秒等新事件（长轮询）。
  不新开推送通道。回合结束后页面重新读一次会话内容。
- **接手别人的会话**：发送到不是自己建的会话时，请求里必须带 `takeover: true`，否则 `409 TAKEOVER_REQUIRED`；页面先弹确认。
- **停用的管理器**：可以看，不能新建和发送（`409`）。

### 4.1 会话桥新增（`services/llm-bridge`，只加管理接口，工具不变）

| 接口 | 说明 |
|---|---|
| `GET /admin/sessions` 加参数 | `q`（标题包含）、`platform`、`status`（`active` / `archived` / `all`，默认 `all`）；每个会话多 `owner_id`、`busy`（有排队或进行中的回合） |
| `GET /admin/sessions/{id}` | 会话信息（含环境、`owner_id`、`busy`）和消息：会话桥建的按回合拼（谁发的、回答、过程、失败原因、进行中已经给出的部分）；官方程序里已有的读官方程序的记录 |
| `GET /admin/sessions/{id}/events?after=&wait_seconds=` | 这个会话在 `after` 之后的事件；没有新事件且还有回合在进行时最多等 `wait_seconds`（0 ~ 25）秒 |
| `PATCH /admin/sessions/{id}` | 改标题（1 ~ 120 个字，照常拦截密钥） |

不改表结构：发送人的名字取自回合的“排队”事件。

### 4.2 工作台后端新增（模块 `llm_bridge`，都要 owner / admin，写操作带 CSRF）

前缀 `/api/v1/llm_bridge/bridges/{bridge_id}/chat`：

| 接口 | 说明 |
|---|---|
| `GET /sessions?q&platform&status&limit&offset` | 会话列表；每个会话带 `owner_kind`：`me` / `user` / `agent` / `external` |
| `GET /sessions/{session_id}` | 会话信息与消息 |
| `GET /sessions/{session_id}/events?after&wait_seconds` | 新事件（长轮询） |
| `GET /options?platform&mode` | 可选的模型（含推理强度）和开发环境 |
| `POST /sessions` | 新建：`platform`、`mode`、`model?`、`effort?`、`environment?`、`title?`，可带第一条消息 `text` + `request_id` |
| `POST /sessions/{session_id}/messages` | 发送：`text`、`request_id`、`takeover?`；立刻返回回合（排队中 / 进行中），不等回答 |
| `POST /turns/{turn_id}/cancel` | 停止 |
| `PATCH /sessions/{session_id}` | 改标题 |
| `POST /sessions/{session_id}/archive` | 归档 |

审计（不记消息正文）：新建、发送、接手、停止、改标题、归档。

### 4.3 第二步：多模型同问

- 一组同问跨管理器，所以登记在工作台：表 `llm_bridge_chat_groups`（标题、谁建的、幂等号、状态）与
  `llm_bridge_chat_group_members`（位置、管理器、平台、用法、模型、会话编号或没建成的原因），迁移 `0069`。
  消息内容不进工作台的数据库：每个成员就是会话桥上的一个普通会话，内容和进度用 4.2 的接口读。
- 接口（都在 `/api/v1/llm_bridge/chat/groups` 下，owner / admin，写操作带 CSRF）：
  `GET`（列出）、`POST`（新建：2 ~ 6 个目标 + 问题）、`GET /{id}`、`POST /{id}/messages`（向每个成员继续发）、`POST /{id}/archive`。
- 几个目标同时建会话、同时发出（`asyncio.gather`），调会话桥之前先提交事务。某个目标失败（没登录、限额）只记在它自己那个成员的
  `error` 里；一个会话都没建成时 `409`，不留下空的一组；停用的管理器不能参加（`409 BRIDGE_DISABLED`）。
- 幂等：新建带 `request_id`，同一个人用同一个再建一次得到的是同一组；发给每个会话的幂等号是 `<request_id>.<会话编号的后 8 位>`
  （会话桥按“调用方 + 幂等号”去重）。
- 别人建的一组要带 `takeover=true` 才能继续发，否则 `409 TAKEOVER_REQUIRED`；管理器停用或登记被删除的成员这次不发，结果里给出原因。
- 审计：`chat_group_created` / `chat_group_sent` / `chat_group_takeover_sent` / `chat_group_archived`，不记问题的内容。
- 前端：会话的内容与进度抽成 `useLiveConversation`，单会话和同问的每一栏共用。

## 5. 权限与安全

- 所有接口校验工作空间和角色（owner / admin），不靠前端隐藏；模块停用时 404。
- 回答和智能体的消息是别人写的内容：按纯文字显示，不渲染 HTML，不自动打开链接。
- 密钥拦截、限额、账号一致性都在会话桥里，人发的消息同样经过。
- 人接手智能体的会话会被记进审计，并在会话的事件里留下是谁发的。
- 例外九（`docs/AGENTS.md`）不涉及：这里是人在操作，不是智能体的工具。
- **管理器不分工作空间**：它上面的会话属于“这一套账号”。拿着它的管理令牌把它登记到第二个工作空间，
  等于让两个工作空间共用这套账号——两边的管理员都能在聊天页看到它上面的全部会话（包括另一边的人和智能体建的）。
  要隔离就各部署一个管理器（`make llm-bridge-up N=2`）。这一点在 T-0227 的“会话”标签里就是这样，聊天页只是让它更显眼。
  **工作台不拦截重复登记（人类 2026-11-14 决定）**：登记要有管理令牌、只有 owner 能做，共用是登记的人自己的选择。

## 6. 测试与验收

- 会话桥：新增管理接口的测试（列表筛选、会话内容、长轮询事件、改标题）。
- 工作台后端：真实的会话桥应用（进程内）+ 测试驱动，覆盖新建、发送、陆续出现的事件、停止、接手要确认、admin 可用、member 403、停用的管理器不能发。
- 前端：列表、搜索、筛选、新建表单、发送与停止、接手确认、失败回合、手机宽度下的两屏。
- 浏览器验收（`tests/e2e/llm_chat_browser.cjs`）：CI 里多起一个“验收用”的管理器，里面的 Claude 程序换成仓库里的
  仿真命令行（`tests/e2e/llm-bridge-fake.compose.yaml`，只在 CI 里叠加，不进正式部署），在真实的工作台和真实的
  会话桥容器上走一遍：新建会话、问答、停止、改标题、搜索、归档、接手确认、管理器停用、审计、手机宽度。
- 多模型同问（T-0232）：后端覆盖跨两个管理器新建、某个目标失败、重试不重复、继续发、别的管理员要确认、管理器停用或删除、归档；
  前端覆盖分组列表、并排的每一栏、向一组继续发、新建一组；浏览器验收里验收用的管理器把 WorkBuddy 也换成仿真命令行，
  同一个问题发给 Claude 和 WorkBuddy 两栏。
- 各平台的真实问答仍然需要人类用真实账号验收。

## 8. 不做的

- 图片、附件、联网搜索开关：会话桥目前只传文字。
- 逐字显示：平台的官方程序按“段”给出回答，页面按段显示。
- chatgpt.com、claude.ai 网页上的对话：没有官方接口，看不到。
- 成员（member）使用聊天页：见第 1 节。
- 拦截“同一个 MCP 管理器登记到多个工作空间”：人类 2026-11-14 决定不拦截，见第 5 节最后一条。
