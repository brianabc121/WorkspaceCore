# Workspace 四页改造方案：任务、项目、日历、邮件

**用途：交给 Claude 实施的产品与设计规范。**
**代码核对基线：origin/main c2854e1（已包含 PR #176 插拔式模块）。开工时必须重新 fetch，并以最新主干为准。**
本次只编写方案和打包效果图，未修改业务代码，未执行部署。本文件中的新增字段和接口均为工作台自身的拟议契约，不表示目前已经存在。

## 1. 改造目标与范围

将四页统一到已展示的首页视觉风格，同时完成真实可用的交互，而非仅换色或复制静态数据。
用户明确要求：
- 首页及任务相关信息要突出待办、进行中、已完成待查看、阻塞、提醒。
- 邮件默认汇总全部已连接且有权限的邮箱，并可随时单独查看某个邮箱。
- 本次交给 Claude 落实的范围是任务、项目、日历、邮件四页；首页仅作为视觉参考，首页改造和 AI 新闻生成不在本轮。

视觉方案采用：任务列表＋详情侧栏；项目卡片网格＋动态；周日历＋日程详情；邮件聚合／单邮箱三栏视图。
这沿用已有功能结构，避免另建一套任务系统、邮件镜像或页面框架。全看板方案作为任务页保留视图，而不是强迫所有页面看板化。

## 3. 统一设计规范

- 沿用 Vue 3 / TypeScript / Vite / Pinia / TanStack Vue Query、Tailwind 与现有 shadcn-vue/reka-ui；不新增大型 UI/日历库，不重建全局壳。
- 沿用现有亮／暗主题 CSS 变量和 Lucide 图标；白底卡片、细边框、约 12px 圆角、蓝紫主色。状态同时有文字／图标，不只靠颜色。
- 内容正文 14–16px；标题 22–26px；次要信息保持可读对比度。主要操作每个区域只突出一个。
- 四页可选择宽版内容容器，保留现有侧栏、搜索、创建菜单、模块导航及角色限制；不改变其他页面的宽度。
- 桌面 1440/1920：宽版主内容，表格／列表和详情并列。1024–1439：详情改抽屉，减少次要栏。768 以下：单列或“列表→详情”逐级返回。
- 日历在 1024 以下默认日程列表，仍可选择周视图；不强塞三栏。验收覆盖 390、768、1280、1440、1920px。
- 不出现整页横向滚动；必要的宽表／日历画布只在其自身区域滚动。避免卡片套卡片和多个小滚动条。
- 键盘可完成筛选、打开／关闭详情和主要操作；焦点可见，关闭抽屉返回触发项。使用现有 Sheet、Tabs、Button、DropdownMenu。
- loading、真正 empty、error、stale、unauthorized 分开处理。未知数字为“—／未知”；缓存值注明更新时间；权限撤销后不继续显示旧数据。
- 每个数字都明确统计口径，来自服务端全量查询；不能用当前分页的数组长度冒充总数。

## 4. 任务页

### 4.1 布局与交互
- 标题＋新建任务；列表／看板／时间轴保留现有入口。
- 状态筛选：全部、待办、进行中、已完成待查看、阻塞、已完成。搜索、项目、执行者、优先级、截止时间、排序可组合。
- 表格显示标题、项目、执行者、状态、优先级、截止时间。选择任务时右侧详情同步；URL 可表达所选任务，刷新／分享后可恢复。
- 详情复用任务描述、README、执行记录、动态、项目 Issues、自由接取／指派等既有能力，不能因视觉改造丢失。
- 待查看项提供“查看结果”和“标为已查看”；阻塞项明确原因，并提供“修改原因／解除阻塞”。没有真实任务依赖关系时不用“查看依赖”假按钮。
- 查看结果能到达已有 README、执行记录或完成说明；空结果也要说明，不伪造报告链接。

### 4.2 状态定义：本方案的缺省建议
用户尚未选择“查看”是否等于正式验收。本期默认**已完成与已查看分离**，不引入强制人类验收流程：
- 待办：未完成、未明确阻塞、当前没有未结束的 TaskRun；暂停和中断不自动当作阻塞。
- 进行中：未完成、未明确阻塞，存在 ended_at 为空的 TaskRun；不能仅凭 started_at 非空判定。
- 阻塞：未完成且有人明确设置了阻塞原因。标记阻塞不等于停止远端进程，不自动终止 AI 或运行容器；解除阻塞也不自动重启任务。
- 已完成待查看：任务 done=true，属于新的完成轮次，当前用户尚未显式标记该轮结果为已查看。
- 已完成：done=true，当前用户已查看；历史迁移前已完成的任务也默认在此，避免上线时刷出全部历史“未读”。

状态判定优先级：done→按个人查看状态分组；未完成→阻塞优先于进行中；其余待办。所有列表、看板、统计、项目卡片使用同一服务端判定。
“全部”包含这五种互斥状态。查看状态按用户隔离；用户 A 已查看不应替用户 B 消掉提示。
本人手动完成时可在同一事务标记本人已查看；智能体或其他人完成时进入当前用户待查看。
重新打开后再完成产生新轮次，重新进入待查看。编辑优先级等无关字段不制造新轮次。
viewer 可读取并标记自己的结果已查看；设置阻塞／改任务仍沿用 member 以上及既有范围检查。

### 4.3 真实接口缺口与拟议数据
现有 TaskOut 只有 done/done_at、首次开始时间、执行者等，没有上述完整状态。需补：
- tasks：completion_seq（历史默认 0，每次未完成→完成加 1）、blocked_at、blocked_reason、blocked_by。
- task_result_reads：workspace_id、task_id、user_id、seen_completion_seq、viewed_at；同一用户同一任务唯一，使用复合约束防跨工作空间。
- TaskOut 增加 work_state、completion_seq、result_viewed、active_run 摘要、blocker 摘要。
- 补人类和智能体所有完成／重开入口的事务处理；已有部分完成路径并不统一写 completed 动态，不可只修一个入口。
- 标记阻塞后仍可查看执行记录；如正在运行，界面说明“标记阻塞不会停止当前执行”。完成任务同时清除有效阻塞标记，避免重开时带回旧原因。已完成任务不能再标阻塞；明确阻塞的任务不能被新领取／新启动，需先解除。
- 新增自己的 API 契约：任务统计、结果已查看、阻塞更新；保留旧 status=open/done/all 参数与现有客户端。详见实施计划。
- 明确新增的是工作台自有数据库，不改第三方数据库。迁移只能加列／表／约束；不得改历史迁移或删除现有任务。

## 5. 项目页

- 网格／列表切换，搜索，未归档／需要关注／已归档筛选，稳定排序。
- 卡片：项目名、简介、真实已完成/总任务数、进度条、进行中／待查看／阻塞数、已加入项目的智能体、最近更新时间。
- 进度=done_tasks/(done_tasks+open_tasks)。待查看仍是已完成任务，不能因当前用户还没看而倒扣完成进度。
- 无任务显示“尚无任务”，不显示 100%。分母为 0 时不用假数据。
- “需要关注”=本用户待查看数>0 或明确阻塞数>0；计数用与任务页一致的规则。
- 项目本身尚无独立生命周期时，“进行中项目”汇总改为准确的“未归档项目”；不把未归档自动等同正在执行。
- 效果图“我参与的”涉及人类项目成员关系，现有接口不足以准确支持，本期改为“未归档／需要关注／已归档”，不伪用创建者推断参与关系。
- 头像优先显示实际项目智能体；人类头像若显示，标明真实身份，例如项目创建者，不凭当前登录者推断项目成员。
- 保留项目 README、智能体成员、项目群、Issues、编辑／归档等入口。
- 最近动态只用真实任务／项目事件。动态加载失败不让全部项目卡片消失。
- “本周完成”按所选显示时区的周一 00:00 至下周一 00:00，以 done_at 统计当前已完成任务；需明示不是完整的历史完成事件总数。

## 6. 日历页

- 保留月／周／日程视图；桌面周视图：左侧小月历与显示筛选，中间七天时间轴，右侧选中日程／详情。
- 当前日期、选中日期分开标识；今天／前后周导航、显示时区、全天区域始终清楚。
- 日程和任务截止项使用不同图标／颜色。任务截止是只读派生，点击到任务页；不能在日历里冒充可编辑事件。
- 日程本身可经现有 CalendarForm 新建、编辑、删除，继续使用 version 乐观并发。
- 按区间 [start,end) 查询；所有分页都可继续加载，不能只画前 100 条任务／事件。
- 全天事件按其 IANA 时区的本地日期表示，结束日期不含。不能简单给 UTC 时间加 24 小时跨日；验证 DST 与跨月、跨年。
- 多个重叠事件要并排或折叠“另有N项”，不能彼此覆盖；跨日事件按每天区间裁剪显示。
- 右侧详情显示标题、时间、位置、备注。当前 CalendarEventOut 没有 project_id，因此**无真实关联时不显示“查看关联项目”按钮**；不从标题猜项目。
- 本轮“提醒”指已有日程／任务截止的临近提示展示，不新增邮件、短信、桌面通知或重复日程规则。效果图里的提醒开关若无数据来源，改成实际存在的日程／任务截止／全天筛选。
- 新建位置、时间冲突和只读状态都能说明；只读用户不出现可写按钮。

## 7. 邮件页：以最后两张图为准

### 7.1 默认与单邮箱
- 进入 /mail 时默认 scope=all，分类=全部邮件；不能默认选 accounts[0]。
- 默认包含所有当前用户有权读取、已连接的账号，按时间合并展示；“全部邮件”默认不包括垃圾／垃圾箱，只有显式选择分类才查询这些位置。
- 左侧始终保留“全部邮箱”＋各邮箱的显示名、地址、连接状态和有依据的未读数。
- 每封邮件标注所属账号。账号筛选、分类、搜索、翻页、刷新操作的作用域完全一致。
- 单个邮箱缺乏权限或已断开时明确说明，不能悄悄切到其他邮箱；“返回全部邮箱”入口清楚。
- 接口返回的是当前已加载批次，并在已加载集合中按 Gmail internalDate 倒序排序；相同时间按 account_id、message_id 稳定排序，未知时间放最后。
- 默认聚合所有账号不等于一次下载全部历史。采用“加载更多”，不伪造全量历史严格页码；有新批次时重新归并已加载集合。图片的“1–7/共28封”可改为“已加载N封，加载更多”。
- 正文、发件人、主题、摘要不得落入数据库、Redis、浏览器持久存储、全局搜索或日志；搜索q与分页token原文也不能进访问日志。当前页需要的数据仅驻留内存，离开邮件页／退出／权限撤销时清理。

### 7.2 账号绑定与发信
- 消息与会话 ID 仅在账号内唯一；前端选中键和详情请求必须携带 account_id+message_id／thread_id。
- 切换账号、搜索、分类或工作空间，取消旧请求并清空选择、分页状态和旧正文；迟到响应不能回填。
- 详情顶部显示所属邮箱；回复明确“将使用 xxx 回复”，并固定为该邮件所属邮箱。
- 全部邮箱视图点“写邮件”时必须显式选一个有发送权限的账号，不能静默使用第一个账号。
- 用户主动切换发信身份必须提示会改变发件人并清除原回复关联；不允许账号 A 的 reply_to_message_id 被发到账号 B 的 send API。
- 发信仍用既有幂等键、收件人数限制、密钥扫描、CSRF 和 unknown 不自动重发规则。
- 保留原有发件记录／结果未知提示、智能体邮箱分配等设置，不借改版改变授权。

### 7.3 聚合故障与计数
- 一个账号需重连／限流／超时，不得清空其他账号结果；返回每账号状态、partial、retry_at，界面显式“部分邮箱暂不可用”。
- 总体正常空结果、全部连接失败、全部无权限、部分失败必须区分。
- 数量未知显示“—”；估算显示“约N”，部分账号失败时不显示虚假的全量总数。可明确显示“已加载N封”。
- Gmail internalDate 用于排序；不能信任外部 Date 头决定顺序。跨账号不去掉同一封分别投递到不同邮箱的邮件。

### 7.4 图中尚未具备的操作
当前只申请 gmail.readonly + gmail.send。**本轮不增加 gmail.modify，不自动改 OAuth scope。**
- 不实现归档、删除、标星、标记已读／未读等 Gmail 写操作；对应工具按钮不展示，不能放空按钮。
- 仅凭阅读正文不会在 Gmail 标为已读。
- 星标／已发送可作为已有数据的只读分类；草稿同步／编辑不在本轮。“已删除”若无查询入口不展示。
- 回复全部／转发若要展示，先用已核验地址解析与现有 send 形成真实可发送草稿并测试；否则本轮只保留已支持的回复，不画假功能。
- 附件继续经后端下载、25MB 限额、纯文字正文、禁远程图片；不扩大浏览器权限。

## 8. 契约与安全总原则

- workspace scope、角色和资源权限必须服务端校验；前端隐藏不构成授权。
- 查询键包含 user、workspace、筛选和账号／任务 ID。退出或失权时清空敏感缓存。
- 最新模块机制必须保留，早报代码已迁到 apps/web/src/modules/news；四个核心页面不为改版重新迁成插件，不硬编码全量侧栏，不破坏模块停用。
- 第一方新增接口先写入后端模型／OpenAPI，并机械生成 schema.d.ts，禁止手改生成文件。
- 迁移编号由实施时最新 main 决定；本包不预占 T-xxxx 或 Alembic 编号。
- 技术和范围决定写 ADR；不更改协作协议、不推进 Sprint、不恢复 n8n、不部署真实服务。

## 9. 必须通过的体验验收

1. 任务开始、暂停、明确阻塞、完成、个人已查看、重开再完成，各状态和数字一致。
2. 两个用户的“待查看”互不干扰；工作空间切换无残留。
3. 项目 0 任务、含阻塞、含待查看、归档、大量分页场景正确。
4. 日历完整加载超过 100 条记录；全天、跨日、重叠、DST 无漏画／错日。
5. 默认不先点击账号即可见多个邮箱消息；单邮箱模式只见该账号，搜索和分类同范围。
6. 两个账号出现同 message_id／thread_id，阅读、附件和回复仍不会串号。
7. 一个邮箱失效仍显示其他邮箱；授权撤销立即清掉原正文；未知计数不伪装为 0。
8. 桌面、暗色、390px 手机与键盘操作完成关键流程。没有死按钮、示例数据、生产假值。
