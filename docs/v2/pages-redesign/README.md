# Workspace 四页改造：给 Claude 的交接包

本包是改造方案与效果图，**不是已实现版本**。由人类交给 Claude 按仓库协作协议实施。
范围：任务、项目、日历、邮件。首页仅作风格参考。邮件以“全部邮箱聚合”和“单邮箱”两张最终图为准，旧版单账号默认图不再采用。

## 阅读顺序

1. [改造方案与设计规范](docs/superpowers/specs/2026-11-08-workspace-four-pages-design.md)：需求、布局、状态定义、范围和验收。
2. [分阶段实施计划](docs/superpowers/plans/2026-11-08-workspace-four-pages-redesign.md)：六阶段、真实文件位置、拟议接口、测试与交付步骤。
3. assets 中的六张图：四页共五张最终图，另加首页风格参考。

方案核对的主干是 c2854e1，包含最新模块机制；Claude 开工仍须重新读取 origin/main。
本包没有占用任务或迁移编号，没有修改仓库业务文件，没有运行开发测试或部署。

## 必须记住的五件事

- 已完成待查看不等于强制验收；缺省是每用户、每完成轮次的“标为已查看”记录。旧已完成任务不上线刷成全部未读。
- 阻塞有明确原因；不把暂停、离线自动当阻塞，也不把标记阻塞当停止远端执行。
- 项目卡片使用真实统计；没有任务不能显示100%，没有成员关系不能假造“我参与”。
- 多邮箱默认scope=all；任何消息／会话／附件／回复都绑定account_id。默认不能选第一个邮箱。
- 当前Gmail是readonly+send；图中的归档／删除／标已读等超范围写操作不在本轮实现，也不能摆成可点的空按钮。

## 可直接复制给 Claude

请按附件中的 Workspace 四页改造方案落实任务、项目、日历和邮件页面。
先读 README、设计规范、实施计划，再读仓库最新 AGENTS.md/docs/AGENTS.md 和 .collab。
以最新 origin/main 为准，确认没有重复执行或冲突任务，保护现有未提交工作，按仓库协议创建／接手自己的任务和分支。
这不是旧 T-0149 的继续任务；旧n8n移除已经合并，不要恢复旧分支或旧生成类型。
以本包的最终效果图为视觉方向，业务和权限以设计规范为准。
尤其保证任务状态与个人查看闭环真实、多邮箱默认聚合、账号切换无数据串号、回复身份正确。
按六阶段逐项实现和测试；契约和生成类型随同提交；别只改静态样式或用示例数据填页面。
首页、新闻生成、自动通知推送、任务依赖图和新增 Gmail 写 scope 不在本轮。
完成后按实际T编号创建PR，附真实命令输出和亮暗／手机／桌面截图；未完成的如实保留进度，不标成done。
是否合并、部署和推进Sprint，继续遵守仓库决策，不因本方案自动执行。
