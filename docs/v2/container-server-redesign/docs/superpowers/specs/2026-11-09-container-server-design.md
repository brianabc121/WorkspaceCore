## 1. 需求与范围

用户要求将“运行服务器”更名为“容器服务器”，直观看到各OpenClaw申请的运行容器及每个容器的负载。本方案将“负债”按运行负载理解；先前效果图已据此生成。

- 首屏以容器环境为主，按申请智能体查看CPU实际用量／配额、内存占用／限额、数据卷占用、运行状态、用途和生命周期。
- 选中容器在右侧详情查看资源、配置、执行记录与回收规则，提供现有管理动作。
- 保留模板、智能体用量、执行记录、服务器设置与回收策略；不把已有完整功能缩成静态表格。
- 本期沿用V1“每个工作空间一台容器服务器，供多个OpenClaw申请环境”，不扩展多服务器调度。

## 3. 页面结构

### 3.1 名称与导航
- 侧栏、标题、面包屑、页签辅助文案、设置／通知中的用户可见名称统一“容器服务器”。
- **URL仍为/runner，API仍为/api/v1/runner，工具env_*／runner_*及数据库命名保持。** 不为改名重命名全部模型／接口／脚本。
- 新默认页签`overview`为“容器总览”，包含主机条、统计、筛选与容器表。
- `instances`为“智能体用量”（新增独立展示现有实例用量）；`templates`为“环境模板”；`runs`为“执行记录”；`settings`为“服务器设置”。
- 旧`?tab=environments`使用replace映射到容器总览并保留有效筛选／environment_id；旧overview/runs/templates/settings继续有效。刷新、通知、后退不丢选中详情。
- /agents或前一份智能体服务器方案如已迁移，以最新主干入口为准；本期只链接原有“运行环境权限”，不重做OpenClaw部署页。

### 3.2 首屏
- 标题“容器服务器”，副标题说明由OpenClaw申请容器；操作为刷新和管理申请权限，无通用“新建容器”或交互终端。
- 主机条展示当前唯一主机名称、在线／离线／待接入／已停用、CPU核数／内存容量、磁盘已用／总量、可用运行时与最近心跳（host.last_seen_at），入口到服务器设置。若展示完整报告时间，读取host.report.at，不把poll时间称为指标更新时间。
- 未配置主机时展示接入引导；admin与owner动作按既有权限分别可用，不因新页面让admin执行owner的SSH部署。
- 统计卡为“容器环境总数”“运行中”“已停止”“需关注”。范围为当前空间、未删除环境记录；总数包括归档等状态，不是此刻Docker物理容器数量。需关注本轮仅计failed，不凭空增加CPU告警规则。
- 统计为工作空间全量，筛选区说明“筛选结果N／工作空间M”；不把局部列表数量误称全局总量。

### 3.3 主表与筛选
- 搜索用途／环境ID，按申请智能体、类别、状态筛选；ID选择及详情始终用完整UUID，同名用途不能串行。
- 列：用途＋短ID、申请智能体、类别、状态、CPU已用／配置上限、内存已用／配置上限、数据卷占用、详情／更多。
- 类别沿用once／session／persistent，显示一次性／会话／常驻；状态沿用creating/running/stopped/archived/pending_delete/deleted/failed。
- 正在创建、归档、待删除、失败和停止各自显示真实状态；失败可看state_reason。归档记录是环境配置／快照记录，不伪装为活容器。
- 现有接口硬截断500条，本轮补服务端搜索／排序／分页和匹配总数。主表每页默认50条，统计卡仍读全空间overview；不能在前500条或当前页内搜索后声称覆盖全量。
- 默认稳定排序最近使用优先、UUID破同分；可选按CPU／内存实际用量降序，未知／过期最后，不把配额拿来排序“负载”。

## 4. 资源含义与采集

### 4.1 CPU
- 新增实际CPU使用核数，来自同一容器两个累计CPU时间样本与单调时钟间隔的差分；是最近采样窗口的平均核数，不是瞬时占用。
- 展示“0.42／2核”，配额占用为21%；大于1核是合法值。不能把Docker全机CPU百分比、负载平均值或配置的2核当实测。
- 首样本、容器重建／重启、计数器回退、无有效采样窗均显示未知；有效零增量才显示0。
- 保持现有报告默认60秒、页面默认30秒读取。文案按实际上报时间显示，不承诺10秒实时，不为小部件新增高频Docker轮询。
- 本期只做当前值与实际采样窗口，不增加历史曲线、时序库、IO／网络新指标。

### 4.2 内存与数据卷
- 内存沿现有Docker memory_stats.usage口径（含缓存），单位字节；memory_mb配置实际按MiB换算。tooltip可说明统计口径，不改成RSS或静默扣缓存。
- 数据卷占用复用env.disk_bytes；效果图“磁盘占用”在产品中改为“数据卷占用”，说明不含镜像与可写层。
- data_volume字节不能与spec.disk_gb组合成“硬磁盘配额百分比”；主机磁盘已用=总量−空闲，单独展示，不与容器数据卷相加。
- 停止／失败／非running环境不显示实时CPU、内存；数据卷仍存在且有新报告时可显示占用。归档／删除后显示未知／快照信息，不沿用旧卷大小假装仍占用。
- 数据缺失、负数哨兵、采集失败为未知，不能自动补0。

### 4.3 新鲜度
- CPU、内存、数据卷分别有平台接收时间；主机还在poll不表示容器指标已更新。
- 默认180秒为指标过期阈值；主机offline／disabled也使已有数字标过期。旧合法数据可显示但必须带“已过期／上报时间”，不显示绿色实时状态。
- 单项失败只影响单项；失权清掉全部相关缓存，不继续显示前工作空间或已无权限的内容。

## 5. 详情与操作

- URL的environment_id定位详情；桌面右侧面板，手机抽屉，关闭归还焦点。环境不在当前筛选中时仍可按ID读详情；404／失权立即清旧详情。
- 显示申请智能体、用途、类别、运行时／用户／网络、资源读数和上限、最近使用、next_step、delete_after、保护状态／快照等。
- 当前执行来自现有按environment_id查询的运行记录；同时多条执行则展示真实列表／计数，不只挑一条当全部。排队、超时、结果未知与执行失败不冒充容器停止。
- 程序输出、命令、用途是外部文本，只按数据安全渲染，不执行指令、HTML或泄漏密钥；完整输出继续走既有受限接口。
- 保留start/stop/archive/delete/keep/restore/pin/unpin，按服务端允许状态显示。PUT/PATCH语义不改，动作仍用现有POST＋version＋CSRF／幂等。
- 停止、归档、删除不是同一行为：一次性／会话归档清容器与卷、留配置；常驻快照／恢复按现有规则。永久丢数据的动作继续给既有准确确认，不因改版弱化。
- 保护沿原规则约束自动回收；明确删除条件／到期等实际行为，不承诺无条件永久保留。图片中重复出现的保护按钮／开关实现时合成一个操作。
- 不因打开面板／刷新而启动、停止、归档或删除。WRITE_UNKNOWN先查询最新状态，不盲目重复动作，不用成功toast提前宣布异步操作完成。

## 6. 智能体用量与功能保留

- 智能体用量保留现有权限开关、运行数量／上限、常驻数量、已分配CPU／内存及限额。现有RunnerInstanceUsage.memory_mb/cpus为分配额度，不改标签冒充实测。
- 如需汇总实际用量，必须另有明确字段／口径与缺测标识；本期不要求新增该汇总。点击某智能体可筛选该智能体环境。
- 模板创建／构建／停用、运行记录／输出、服务器接入包／SSH、配额与回收设置均保留。
- 不改智能体运行环境权限，不新增审批，不开放Docker socket／宿主路径／privileged，不改变gVisor/runc/KVM支持与已有网络限制。
- 若另一份OpenClaw密码改造正在进行，共享Installer／SSH／导航文件须按任务占用串行；本轮不借改名改Runner认证。

- 复用Vue／既有UI和CSS变量；本页宽容器显式启用，不撑坏其他页面。不安装新的图表／容器控制台框架。
- 390/768/1280/1440/1920，亮暗主题，键盘／焦点，窄屏列折叠与详情抽屉，loading／空／error／stale／无主机／权限撤销均验收。
- 真实容器验收至少覆盖两个智能体各自的环境、CPU忙／闲和停止后的指标、旧agent无CPU、host在线但报告中断、归档／恢复／保护与未知完成状态。
