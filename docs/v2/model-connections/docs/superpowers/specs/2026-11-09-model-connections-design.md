# 中转站管理与 OpenClaw 模型连接设计

## 1. 用户目标与范围

用户明确要求：
1. 新增中转站管理，支持连接记录的增删改查，每条记录独立设置 URL、API Key、一个或多个模型。
2. 支持直接录入官方 API Key 与官方 URL；单 Key、多模型中转也适用。
3. 旧密钥库的 API Key 迁入新管理入口。
4. OpenClaw 的模型连接全部改为使用新页面的连接数据。
5. 沿用已经展示的浅色、紫色 Workspace 页面设计。

本方案决定：主入口统一叫“中转站管理”，记录统一叫“连接”；连接类型分官方直连、第三方中转。每个智能体本期选择一个主连接与主模型，同一连接可以供多个智能体使用。备用链、自动择价、负载均衡不是本期必需功能。

“一个 Key 支持全部模型”指服务商给这个 Key 的实际可用集合，不表示支持全球所有模型，不表示换任意模型名都能调用。

## 2. 当前代码事实

- 密钥库 /agents/secrets，由 owner 管理；支持 model_api_key、api_token、generic。
- AgentSecret / AgentSecretVersion 保存元数据和加密值；密文 context 绑定 secret_id、value_version。
- AgentSecretGrant 通过 ref_id 给实例授权；AgentSecretAccess 保留取用记录。
- SecretsWorkspace.vue 显示卡片、轮换、删除和取用记录，目前无列表搜索与类型筛选。
- openclaw.json.template 固定模型配置为 openai + openai_api_key；仅改前端不能完成多连接。
- 接入包 secret resolver 调用 /agent-api/v1/secrets/resolve，现有自动部署每 10 分钟 secrets reload。
- Runner 的 resolve_env_secrets 同样使用 AgentSecretGrant；旧表不能直接整体删除。
- OpenClaw 锁定镜像为 2026.9.36 + digest，不以历史 TRANSFORMATION_PLAN 的概念版本代替实际版本。
- 新闻模块有独立模型设置及 sealed 凭据，不在现有密钥库里，不能通过这次迁移默默覆盖。

## 3. 方案取舍（本包推荐，不是额外获得的用户决定）

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| 仅把旧密钥卡片改名 | 改动小 | 没有协议、URL、模型与配置下发，无法满足需求 | 不采用 |
| 新连接元数据 + 复用内部凭据存储 + OpenClaw 原生直连 | 保留授权/轮换/审计，官方 URL 可直用，无新增推理代理 | 需做配置应用、协议核验和兼容迁移 | 推荐 |
| 新建统一推理网关，OpenClaw 永远只连工作台 | 可集中流控 | 要处理流式、工具调用、多协议、计费与大规模代理 | 超出本期 |

新页面是模型业务事实来源；AgentSecret 仅作为内部凭据设施，不再由用户手工拼 ref_id 来配置模型。

## 4. 页面布局与交互

### 4.1 管理页

新路由 /settings/model-connections，侧栏管理组改为“中转站管理”，owner 可见且后端同样强制 owner。
旧 /agents/secrets 做路由兼容跳转，保留其有效筛选和记录深链接的映射；侧栏自定义导航中的旧 path 一并兼容，避免重复入口。

- 标题、说明、刷新、添加连接。
- 汇总：连接总数、检测通过、待完善、关联智能体。来自全工作空间统计，不能使用当前分页条数冒充总数。
- 页签：全部连接、官方直连、第三方中转；辅助入口“迁移与兼容凭据”。
- 搜索名称、URL 主机与模型 ID；按配置/启停状态、最近检测结果筛选。
- 表格：名称、类型、URL、模型范围、配置状态、检测结果、关联智能体数、最近更新、管理。
- 详情面板：连接配置、模型管理、智能体授权、活动记录。
- 操作：编辑、检测、同步模型、更换 Key、停用、删除；提供复制为新连接便于更换上游地址。
- 授权中的连接禁止直接删除；停用要明确影响范围，检测失败不等于用户停用。
- API Key 字段显示“已保存”，可更换，不显示原值，不提供取回或导出。
- 列表 URL 只保存安全的 base URL；不要把 Key 放在 query、userinfo 或路径参数中。

### 4.2 新建/编辑连接

必填：名称、类型、协议、base URL、API Key、模型范围。说明选填。
新建可保存为草稿；启用前必须配置完整。模型范围有：
- 指定模型：手动录入/从已同步列表勾选一个或多个模型 ID。
- 服务商全部可用模型：同步的明确模型 ID 集合作为可选范围，不能用无限 wildcard。
官方预设只填写经核验的协议与 URL，不代填 Key。OpenAI 官方示例为 https://api.openai.com/v1；其他官方预设由 MC-0 核实后写入。
指定官方预设后改到第三方主机，应切换为“第三方中转”，不能仍挂官方标识。
编辑名称/说明即时保存；Key 用独立更换操作。已完成配置且有授权或原生绑定时，修改 URL/协议必须复制为新连接并切换；旧导入草稿首次从空补齐允许保存且不自动改变旧运行时，避免把现有 Key 自动发送到另一目标，或让老进程拿到新地址配旧值。

### 4.3 OpenClaw 连接分配

- 管理页下方展示智能体、当前连接、主模型、配置应用状态、“更换连接”。
- OpenClaw 新部署抽屉增加“模型连接”“主模型”，创建态列owner可管理的已启用且配置完整连接；选择即授权给本次创建的新实例，实例/授权/绑定事务提交。已有实例按已有授权筛选。
- 智能体详情增加“模型连接”：目标连接、模型、已应用版本、待应用/失败原因，应用/重试按钮。
- 不再要求用户填写 openai_api_key 或 SecretRef JSON；迁移后的模型授权以连接为单位。
- 非模型 Token 的旧授权留在“高级凭据授权”，明确用途，不和主模型选择混在一起。
- 同一连接可授权多个实例；一台服务器上多个 OpenClaw 各有独立绑定、目录、配置和应用任务。
- 保存选择不等于运行时已生效；必须显示目标/已应用状态并记录真实确认。
- 手动接入实例通过更新接入包或受控配置助手应用；未应用显示“待手动应用”，不能假装平台已经改到远端。

### 4.4 展示状态

配置完整度、管理员启停、最近检测、实例应用状态分开显示。
429：显示“服务商限流中”和 retry_at，保留模型/连接数据。
401/403：显示“凭据失效或权限不足”，提示更换 Key；不把所有错误都归为 Key 无效。
模型列表接口不支持：显示“需手动配置模型”；保存已有模型，不显示空列表成功。
检测超过约定有效期：显示上次时间和“结果可能已过期”；不是实时健康承诺。
配置应用失败：保留旧已应用信息，显示可重试错误；未确认时显示“状态待确认”。

### 4.5 响应式与可访问性

桌面：主表 + 右侧详情面板；窄屏变抽屉，全屏移动表单。
复用 DrawerDetail、ModalPanel、现有按钮/表格/状态 tokens；支持暗色主题、键盘导航、Escape 关闭、焦点回位。
危险操作确认包含名称、影响实例及当前未应用状态；不要仅靠颜色传达状态。
图片只指导布局，文案/状态/验收以文字契约为准。无需制造 Key 的前缀/后缀来模仿脱敏，直接显示已保存。

## 5. 数据与权限架构

建议新增 ModelConnection、ModelConnectionModel、ModelConnectionGrant、AgentModelBinding、ConnectionCheck 与 ModelApplyJob（可复用已有任务设施，但接口语义保持一致）。
现有 AgentSecret/Version 作为内部唯一凭据源复用，不复制密文，不新增另一份明文或第二套 Key 编辑页面。

ModelConnection 与 AgentSecret 在同一 workspace，credential_secret_id 对应唯一受管模型连接。
对新连接创建内部 secret；旧记录挂接原 secret。原 secret_id、value_version、旧 ref_id 与取用记录保持可追溯。
连接更换 Key 统一调用已有加密和轮换逻辑；旧接口对已托管 secret 的写操作委托连接服务校验，不能形成绕过停用/版本校验的旁路。
未纳管前保持旧行为；纳管但待完善的旧连接仍只走 legacy 路径，不可用于新部署；导入时可保留 enabled=true 维持原取用，原生路径必须再满足 ready 与有效绑定。
归类非模型凭据时保留原记录、授权和 Runner 引用，放入新页面的兼容凭据管理。

所有列表、单项、子资源、异步任务、检测结果、授权与实例接口均检查 workspace + role。
智能体只可获取自己有效绑定的非敏感配置；取值仍需实例认证及对应连接授权。
不增加 MCP“读全部 Key”工具，不放宽 OpenClaw exec/文件/网络/审批策略。

## 6. OpenClaw 接入方式

业务流程：
管理员 → 连接配置与授权 → 实例绑定 connection_id/model_id → 后端生成经核验的 OpenClaw 配置 → 受控应用 → OpenClaw 使用受授权 SecretRef 取 Key → 直连配置的模型 URL。

无需工作台转发推理流量。官方直连不会绕到第三方中转域名。
provider 内部标识由连接 UUID 生成，名称改动不影响运行时，不直接拼用户名称为配置键。
更新配置只改工作台管理的模型/主模型字段；保留渠道、MCP、会话、工具限制等其他配置。
配置文件不含模型 Key 明文；受控 resolver 只在进程间协议中返回当前授权值，禁止日志打印。
保持旧 resolver 和旧 alias 的兼容适配，迁移结束前不删除。
模型 Key 轮换继续采用现有“旧值不再下发，下次取用新值”语义；这不表示撤销服务商原 Key，也不能承诺恢复已销毁的旧值。
每 10 分钟 secrets reload 只解决 Key 刷新，不能用它代替 URL、协议和主模型的配置应用。

## 7. 边界与兼容

- 不自动把 GitHub Token 判断为模型 Key；不把原 api_token/generic 强行指定给 OpenAI。
- 旧导入项没有 URL、协议、模型时，必须待完善；可以保留原模型服务运行，但不能新建有效绑定。
- 不自动读取、覆盖未知的远端自定义 OpenClaw 配置来猜模型；可提供显式预览导入，人工确认后保存。
- 旧绑定存在且新绑定未确认应用时保留可工作的旧配置；不能切换 UI 就清理 alias。
- 切换失败可恢复旧模型配置；如果 Key 已被轮换/外部撤销，只能提供新 Key 或新连接，不能假称恢复旧 Key。
- 新闻 AI、GitHub、邮件、SSH 等独立凭据的统一治理留给各自任务，本次不隐式扩大范围。

## 8. 本期完成标准

CRUD、搜索/分页/统计、官方与第三方连接、多模型、模型同步/手工模式、检测分级、Key 轮换、授权、迁移、OpenClaw 应用与真实 E2E 都交付，才可称本改造完成。
原有 Runner 密钥注入、IM、MCP、审批、跨 workspace 隔离、密码部署和一机多实例不得退化。
无法核验的协议/无法访问的测试服务如实记阻塞；隐藏不可用选项，不以 mock 成功替代真实 OpenClaw 验收。
