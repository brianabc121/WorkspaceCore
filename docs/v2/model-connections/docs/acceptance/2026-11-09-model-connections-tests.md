## 3. OpenClaw运行时

| ID | 场景 | 必须观察的结果 | 对应任务 |
|---|---|---|---|
| R01 | 新部署选择连接+模型 | 生成配置正确，无固定openai_api_key fallback | MC-4/5/7 |
| R02 | 改主模型/URL不同的新连接 | desired与applied分别展示；真正请求到目标服务和模型 | MC-4/5 |
| R03 | 老job/回报迟到 | 不覆盖新目标；相同apply幂等，不重复重启 | MC-4 |
| R04 | 远端离线/命令超时 | pending/failed/unknown准确，重试前可查真实状态 | MC-4/5 |
| R05 | 手动接入 | 新包与说明可用；未执行不能标已应用 | MC-5/7 |
| R06 | 一服务器两个OpenClaw | 切A不变B的配置、容器/cron、请求目标 | MC-5 |
| R07 | 自定义IM/MCP/工具限制 | 局部合并不丢字段，exec仍deny，审批不放宽 | MC-5 |
| R09 | 新实例授权与部署 | 无实例ID也可选择有效连接，实例/授权/绑定原子创建且幂等 | MC-4/7 |\n| R10 | A到B切换仍在途 | A已应用凭据继续可用，B确认后退休A；显式停用优先拒绝 | MC-4/5 |\n| R08 | 停用/撤权/解除绑定 | 后续Key和配置取用拒绝；缓存/已发请求边界如实展示 | MC-4/5 |

E2E至少用锁定的真实OpenClaw和两个可控假模型服务。假服务可以验证请求的目标、Authorization、model和Key轮换，但不能宣称已使用用户真实官方Key验证成功。
官方/原生协议适配另需MC-0的官方文档/源码证据；允许在受控测试transport内替换域名，不把测试localhost URL开放给生产表单。
在测试报告中分清：单元mock、真实OpenClaw+假上游、真实服务商可选冒烟。三者不能互相冒充。
