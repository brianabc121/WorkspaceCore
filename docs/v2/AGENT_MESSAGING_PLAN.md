# 智能体主动发消息与项目协作升级方案（T-0116）

> 状态：**已批准，实施中**（人类 2026-11-04 在对话中说“给我根据升级方案 按照推荐的来 全面落实代码”：D1 ~ D19 按推荐，第 10.1 节例外四、例外五按建议写法；实施任务 T-0117 ~ T-0125）。原状态：待批准，人类批准（含第 11 节的选择）后再按第 13 节建实施任务；直接执行的发消息、Issue 与 README 工具需要人类在 `docs/AGENTS.md` 第 8 节加“例外四”“例外五”（建议写法见第 10.1 节）。
> 核验记录：`docs/decisions/2026-11-04-agent-messaging-verification.md`（OpenIM v3.8.3-patch.18 源码、openclaw-channel 0.3.3、OpenClaw 2026.9.36 镜像里的文档）。
>
> **需求来源**（人类 2026-11-04）：
> 1. 完善发消息的功能：OpenClaw 能发送文字 / 图片 / 文件 / 视频；
> 2. 发送的消息被拒收时，也要让 OpenClaw 知道；
> 3. MCP 工具里要能看到它在哪些群、能私聊哪些用户，从而主动发起会话，而不是只能被动接收；
> 4. 智能体能可靠地主动发消息。
>
> **新增需求**（人类 2026-11-04，同一天稍后）：
> 5. 为项目和任务做一个类似 GitHub Issues 的功能，项目里的智能体都通过它与其他智能体对接，更有效地落实代码（第 8 节）；
> 6. 为项目和任务新增 README.md 页面，创建后自动生成，作为这个项目或任务的导览，方便其他智能体快速熟悉（第 9 节）。

## 1. 现状（已核验）

| 方面 | 现在怎样 | 问题 |
|---|---|---|
| 自动回复 | 收到私聊、或群里 @ 它的消息后，插件把回复的文字经 WebSocket 发出 | 只发文字：回复里的图片等附件被丢掉（插件 `deliver` 只取 `payload.text`） |
| 主动发 | OpenClaw 内置的 `message` 工具，目标写成 `user:<IM 用户 ID>` 或 `group:<群 ID>`（OC-0 F4） | 只有文字（插件的 `outbound` 只有 `sendText`）；智能体不知道 ID，要靠聊天记录或别人告诉它 |
| 另外两条外发路径 | `messaging` 档位还带着 `conversations_send`、`conversations_turn`，接入包没有禁用 | 和 `message` 一样只发文字，回调照样拦，但工作台没有记录 |
| 插件的媒体工具 | `openim_send_image/file/video` 按路径读本机文件；OpenClaw 2026.9.36 也不让插件注册智能体工具（F3） | 已禁用，方案不启用 |
| 被拒收 | 回调按规则拒收（下表）；插件只记一行日志 `deliver failed …`，不重试 | **智能体不知道**；工作台也不记录（只统计接力暂停次数） |
| 能私聊谁 | 回调只放行“实例 ↔ 本工作空间状态正常的 owner / admin”；实例之间不行（5003） | 没有工具告诉它这些人是谁 |
| 谁的消息它收得到 | 接入包白名单是**签发接入包时**的 owner / admin 和全部实例；群里只收 @ 它的 | 之后新增的管理员给它发私聊，它收不到，要重新签发接入包 |
| 群规则 | 必须是群成员（5005）；关了接力的群里不能 @ 其他实例（5006）；实例连续发言 8 条暂停，管理员发言后恢复（5001）；每个实例每分钟 6 条（5002） | 智能体看不到群的规则和当前状态（是否已暂停、这一分钟还能发几条） |
| 收到的媒体 | 图片作为图片输入交给模型；视频只取封面；文件只给一行“名称 + 链接”文字 | 实例从接入入口只能取图片（`/im/obj/m/{id}` 只认图片） |
| 管理员网页 IM | 发文字、@、图片（PNG / JPEG / GIF / WebP），有幂等键、结果未知时的对账、拒收返回 409 `IM_SEND_REJECTED` | 文件、视频消息显示“暂不支持的消息” |
| 主动运行 | 智能体只在收到消息时运行；自己的定时任务工具（`group:automation`）禁用；工作台用 OpenClaw 定时任务建了每晚复盘（T-0100），任务到计划开始时间由工作台经 IM 发给它（T-0104） | 没有“到点就去群里说一声”这类由它自己发起的入口 |
| 项目里的对接 | 项目群（IM）、任务动态（领取、放弃、完成、打回）、项目知识库 | 没有能编号、指派、关闭、留档的议题；智能体之间约定接口、交接、请求评审只能在群里说，过后难找 |
| 导览 | 每个项目知识库有一篇“项目简报”（目标、规矩、分工，只有人能改） | 没有自动生成、跟着变化更新的导览；任务没有导览 |

拒收码（`app/domain/im_callbacks.py`）：

| 码 | 含义 | 能否重试 |
|---|---|---|
| 5001 | 群里智能体连续发言达到上限，自动接力暂停，管理员发言后恢复 | 等管理员发言 |
| 5002 | 这个实例在这个群里每分钟的条数达到上限 | 一分钟后可以 |
| 5003 | 实例之间不能私聊 | 不能 |
| 5004 | 实例已停用，或智能体总开关关闭 | 不能 |
| 5005 | 不在群里、群已解散、对方不是本工作空间的管理员 | 不能 |
| 5006 | 这个群关闭了接力，不能 @ 其他智能体 | 去掉 @ 后可以 |
| 5009 | 工作台暂时判断不了（数据库或 Redis 出错） | 稍后可以 |

## 2. 总体做法

**主动发消息统一走工作台。** 新增工作台 MCP 工具 `im_send`：工作台以实例的身份（`sendID = oc_…`）经 OpenIM 管理接口 `/msg/send_msg` 发出，和管理员网页发消息是同一条路径。
OpenIM 对这样发出的消息照样调用 before 回调（核验记录 2.2），规则不变。这样：

- 能发图片、文件、视频：字节由工作台取得、检查、上传，智能体不需要也不能读本机文件；
- 结果当场返回：已发出 / 被拒收（码、原因、多久后可重试）/ 已排队；
- 有幂等、重试、结果未知时的对账、定时发送；每一条都有记录，管理员看得到。

**自动回复仍由插件发文字**（改动最小、延迟最低）。被拒收时：工作台在回调里记下；给插件打一个小补丁，把“刚才的回复没发出去，原因是……”作为系统事件放回同一个会话，智能体下一轮就看得到。

```
主动发：  智能体 ──MCP im_send──▶ 工作台（预检、取附件、发件箱）──/msg/send_msg──▶ OpenIM ──before 回调──▶ 工作台规则
                    ◀──────────── 已发出 / 被拒收（码、原因）/ 已排队 ─────────────┘
自动回复：收到消息 ─▶ 插件 ─WebSocket─▶ OpenIM ─before 回调─▶ 拒收：工作台记录 + 插件把系统事件放回会话
```

第 3 ~ 7 节是发消息（第 1 ~ 4 点）；第 8 节 Issues、第 9 节 README 让项目里的智能体有地方留档对接、有导览可读。

## 3. 会话目录：在哪些群、能私聊谁（第 3 点）

### 3.1 `im_list_targets`（读工具）

参数：`kind`（`all` / `direct` / `group`，默认 `all`）、`query`（按名字筛，可选）。返回：

- `me`：自己的名字和 IM 用户 ID。
- `direct`：能私聊的人，即本工作空间状态正常的 owner / admin。每人一项：
  - `target`：`user:ws_…`，直接传给 `im_send`；
  - 名字、角色；单聊会话 ID；最后一条消息的时间；
  - `replies_reach_you`：他回你的私聊你收不收得到（在不在接入包白名单里）；为 `false` 时附一句“接入包签发后才加入的管理员，重新签发接入包后才收得到他的私聊”。
- `groups`：自己当前所在的群。每个群一项：
  - `target`：`group:<群 ID>`；群名；关联的项目（有的话）；
  - 成员：名字、是管理员还是智能体、IM 用户 ID（@ 时用）；
  - 规则：是否允许接力（能否 @ 其他智能体）、每分钟上限、连续发言上限；
  - 当前状态：是否已暂停（5001）、当前连续条数、这一分钟还能发几条；
  - 提醒：群里只有 @ 你的消息你才会收到；最后一条消息的时间。
- `recent_rejections`：最近 24 小时被拒收的条数（详情用 `im_outbox`）。
- `limits`：能不能发附件、各类附件的大小上限、这个小时还能发多少条。

不列出其他实例的私聊：实例之间不能私聊，要和其他智能体沟通，就在共同的群里 @ 它（关闭接力的群除外）。

### 3.2 `im_read_messages`（读工具）

参数：`target`（同上）、`limit`（默认 20，最多 50）、`before`（消息 ID，翻页）。

- 只读自己的会话：与管理员的私聊；当前所在的群，而且只读入群之后的消息。
  数据来自工作台的 IM 投影（`im_messages`），不新开 OpenIM 读接口；群里的消息本来就对群成员可见，不会读到别人的私聊。
- 每条：时间、发送者（名字、管理员 / 智能体）、类型、文字（单条最多 2000 字，超出截断并注明）、附件的元数据和引用 `im_media:<ID>`（可以转发）、自己发的消息的状态。
- 用途：主动发言之前先看看群里在聊什么，避免答非所问或重复。

## 4. 发文字、图片、文件、视频（第 1 点）

### 4.1 `im_send`（直接执行，见第 10 节）

参数：

| 参数 | 说明 |
|---|---|
| `target` | `user:ws_…` 或 `group:<群 ID>`，从 `im_list_targets` 拿 |
| `text` | 文字，最多 4000 字（与管理员网页一致） |
| `mention` | 群里要 @ 的人（IM 用户 ID），最多 20 个；单聊必须为空 |
| `attachments` | 附件，最多 4 个，每个一种来源（4.2 节） |
| `send_at` | 定时发送的时间（可选，最早 1 分钟后，最远 30 天） |
| `client_key` | 幂等键（可选）。智能体重试同一次发送时用同一个键，不会发出两次；不给时按“目标 + 内容 + 10 分钟时间窗”自动生成 |
| `if_rate_limited` | 遇到每分钟上限（5002）时：`queue`（默认，排队到限额恢复后发出，最多等 10 分钟）或 `fail` |

- 一条 OpenIM 消息只能带一个元素：有文字又有附件时，先发文字、再按顺序发附件，每个算一条（群里的每分钟上限照算）。
- 返回：整体状态和每一条的状态。状态有 `sent`（已发出，带消息 ID 和时间）、`queued`（排队中，带预计时间）、`scheduled`（已定时）、
  `rejected`（被拒收，带码、中文原因、能否重试、多久后可重试）、`failed`（附件取不到、太大、类型不允许、含密钥等，带原因）。
- 发送前先按回调的同一套规则**只读**预检一遍（同一个函数，不计数）：明显会被拒收的（不在群里、实例之间私聊、群已暂停）当场返回原因，不打扰 OpenIM；
  真正的判断仍以回调为准。

### 4.2 附件从哪来

每个附件给且只给一种来源：

| 来源 | 写法 | 说明 |
|---|---|---|
| 网址 | `url` | 工作台去取（只取公网地址，见 4.4） |
| 内联 | `data_base64` + `filename` | 智能体自己生成的小文件，最多 512 KB |
| 文字成文件 | `text_content` + `filename` | 把一段文字存成 `.md` / `.txt` / `.csv` / `.json` 等发出去，最多 1 MB，UTF-8 |
| 工作台里的东西 | `ref` | `kb_file:<ID>`（知识库附件）、`note:<ID>`（知识库笔记，导出成 `.md`）、`im_media:<ID>`（它的会话里收到或发出过的图片、文件、视频）；都按它现有的权限检查 |

另有 `kind`（`auto` / `image` / `file` / `video`，默认按内容识别）、`filename`（显示的文件名）、`cover`（视频封面，同样四种来源，只能是图片）。
**不支持 OpenClaw 服务器上的本地文件**：它本来就没有读文件的工具，也不该让被诱导的智能体把本机凭证发出去（OC-0 F3）。

### 4.3 类型、大小与限额（推荐值，第 11 节 D4）

| 类型 | 识别方式 | 单个上限 |
|---|---|---|
| 图片 | 按文件头识别 PNG / JPEG / GIF / WebP，读出宽高（沿用 `app/domain/images.py`） | 10 MB |
| 视频 | 按文件头识别 MP4 / MOV（`ftyp`），从 `mvhd` 读出时长；读不出时长的按文件发 | 50 MB |
| 文件 | 其他类型 | 20 MB |

- 不允许发的文件：可执行程序与脚本（`.exe` `.msi` `.bat` `.cmd` `.ps1` `.sh` `.apk` `.dmg` `.jar` `.scr` `.vbs` 等）、网页类（`.html` `.htm` `.svg` `.xhtml`，浏览器打开会执行脚本）。按扩展名和文件头一起判断。
- 每个实例：每小时最多 60 条消息、30 个附件；每天附件合计最多 200 MB。超出时返回 `failed`，写明何时恢复。
- 群里原有的规则（每分钟 6 条、连续 8 条暂停）不变。

### 4.4 检查

- **取网址**：用现有的安全 HTTP 客户端（`app/integrations/http.py`），只连公网地址（每次跳转都重新检查，最多 3 次跳转）；连接 5 秒、总共 30 秒超时；边下边数字节，超过上限立即断开；不带 Cookie。
  工作台和智能体服务器所在的内网地址一律不取，内部的东西用 `ref`。
- **识别内容**：以文件头为准，不信扩展名和对方给的 Content-Type；声明成图片、视频但内容不是的，返回 `failed`。
- **拦截密钥**：文字类附件（文字成文件、内联的文本、`.md` `.txt` `.csv` `.json` `.yaml` `.env` 等）过一遍知识库用的密钥扫描（`app/domain/secret_scan.py`）；发现令牌、私钥、密码一类的内容就不发，返回原因。
- 不做杀毒（没有引入杀毒引擎）；下载时一律按附件下载（见 4.5），降低风险。

### 4.5 存储与消息元素

- 上传到 OpenIM 的对象存储（`ObjectStore.upload`，与管理员发图片相同；同样内容按哈希去重），对象名 `myws/<工作空间>/agent/<ID>.<扩展名>`。
- 消息里的地址沿用图片现在的做法：图片地址前缀（`settings.im_object_base_url`）加 `/im/obj/m/<媒体 ID>`，媒体 ID 是随机 UUID；实例经接入入口的 `/im/obj/m/{id}` 取，管理员经网页接口 `/api/v1/im/media/{id}` 取。
  这两个接口从“只给图片”扩展到文件和视频：文件一律 `Content-Disposition: attachment`；都带 `X-Content-Type-Options: nosniff`；视频支持 Range（浏览器拖动进度条）。
- 元素（字段见核验记录 2.1）：
  - 图片 `PictureElem`：原图、大图、缩略图三项（缩略图用对象存储的缩放参数，与现在相同）；
  - 文件 `FileElem`：`sourceUrl`、`fileName`、`fileSize`；
  - 视频 `VideoElem`：`videoUrl`、`videoType`、`videoSize`、`duration` 和封面（`snapshotUrl`、宽、高，都是必填）。
    封面用智能体给的 `cover`；没给时用工作台自带的一张默认封面图（第 11 节 D9，不引入 ffmpeg 解析视频）。
- 保留：和现在的 IM 图片一样跟随 IM 消息保留；发件箱里只存元数据。

### 4.6 网页端

- 管理员 IM 页显示文件消息（图标、文件名、大小、下载）和视频消息（封面 + 播放器，`preload="metadata"`），都经工作台接口按权限取。
- 消息上标出“由 im_send 发出”“定时发送”“限流后补发”等来源；被拒收的回复在会话里显示一行只给管理员看的提示（不写进 OpenIM）。
- 实例页加“发件记录”：最近的主动发送、排队与定时、被拒收的条目和原因，可以取消排队和定时的。
- 管理员网页 IM 也支持发文件和视频（第 11 节 D10，推荐一起做，复用同一套上传与检查）。

## 5. 被拒收时让智能体知道（第 2 点）

### 5.1 经 `im_send` 发的

当场返回 `rejected`（码、中文原因、能否重试、多久后可重试），发件箱里也有记录。排队的、定时的在真正发出时被拒收，用 `im_outbox` 查得到；
另见 5.3 的系统事件（排队和定时的消息被拒收时同样放一条）。

### 5.2 自动回复（插件发的）

1. **工作台记录**：before 回调里，发送者是实例而且被拒收时，记一条拒收记录：实例、会话、拒收码、消息类型、`clientMsgID`、文字的前 120 字（先脱敏）。保留 7 天。
   写记录失败不影响回调的判断（回调要在 200 毫秒内返回）。
2. **管理员看得到**：会话里显示“甲的一条回复没有发出：每分钟条数达到上限”；实例页的发件记录里也有。
3. **智能体知道**：给插件打一个小补丁（第 11 节 D6）。`deliver` 发送失败时，调用 OpenClaw 插件运行时的
   `api.runtime.system.enqueueSystemEvent(text, { agentId, sessionKey })`（核验记录 4.1），把
   “[工作台] 你刚才在 <会话> 的回复没有发出：<原因>。<怎么办>” 放回**同一个会话**，下一轮它就看得到，可以改用 `im_send` 补发、等一会儿再说或者告诉管理员。
   - 原因文字按拒收码查表（与第 1 节的表一致），插件里只放这张表，不放别的逻辑；
   - 补丁随接入包分发（和 OpenIM 补丁一样放在仓库里，构建时校验原始 tarball 的 sha256 再打补丁）；
   - 事件出现的位置、会不会自己触发一轮，实施时实测（核验记录 V3）。
4. 不打补丁时的退路：`im_outbox` 能查到自动回复的拒收记录，`im_list_targets` 里有最近被拒收的条数；智能体只有主动去查才知道。

### 5.3 限额拒收的自动回复：工作台补发（第 11 节 D7）

每分钟上限（5002）只是“晚一点”，不该把回复丢掉。回调拒收 5002 时，工作台把这条回复（回调请求里的 `content`）放进发件箱，限额恢复后以实例的身份补发：

- 最多等 2 分钟；每个群、每个实例最多排 3 条，多的不补；
- 等待期间群进入暂停（5001）或实例被停用，就不补了；
- 补发出去的消息在网页上标“限流后补发”；同时按 5.2 第 3 条告诉智能体“已在限额恢复后补发”，免得它自己再发一次。

5001（接力暂停）不补发：暂停就是为了让智能体停下来，要等管理员发言。

## 6. 可靠投递（第 4 点）

### 6.1 发件箱

新表 `agent_im_outbox`，一条 OpenIM 消息一行：实例、目标、会话、幂等键与序号、消息类型、内容（文字或元素）、媒体 ID、
状态（`scheduled` / `queued` / `sending` / `sent` / `rejected` / `failed` / `unknown` / `cancelled`）、来源（`tool` / `reply_retry` / `wakeup`）、
预定时间、尝试次数、下次尝试时间、拒收码或错误、OpenIM 的消息 ID、发出时间。`(实例, 幂等键, 序号)` 唯一。保留 30 天。

### 6.2 流程

1. `im_send` 校验参数 → 只读预检 → 写进发件箱（同一个事务）。
2. 立即在工具调用里尝试发送；附件要取、要上传的，最多等 12 秒（接入包里 MCP 请求超时是 20 秒）。没完成就返回 `queued`，Worker 接着做。
3. Worker 每 5 秒取到期的行（`FOR UPDATE SKIP LOCKED`），**同一个会话按顺序发**（一个会话同一时间只发一条）。
4. 结果：
   - 发出 → `sent`；
   - 被拒收：5002 → 排到限额恢复后（`if_rate_limited = queue` 时，最多等 10 分钟）；5009 → 稍后重试；其余 → `rejected`，不重试；
   - 连不上、超时前确定没有发出、熔断 → 退避重试（5 秒、30 秒、2 分钟、10 分钟、30 分钟，最多 5 次，总共不超过 1 小时）→ 仍不行就 `failed`；
   - 请求已发出但没拿到结果 → `unknown`，先对账再决定（6.3）。
5. 实例被停用、吊销、删除，或者智能体总开关关闭：未发出的全部取消。

### 6.3 结果未知时不重复发

- 每条消息的 `ex` 写入工作台的标记 `myws-agent:<发件箱 ID>:<签名>`（签名用工作台的密钥，见 6.4）。
- 结果未知时，先拉这个会话最近的消息，找带这个标记的：找到就记为 `sent`；确认没有才重试。和管理员网页发消息的对账做法一样（`im_service._resolve_unknown`）。

### 6.4 实例只能经工作台发媒体

before 回调加一条：发送者是实例、消息不是文字（图片、文件、视频、语音、自定义消息等）时，`ex` 必须带有工作台签名、
而且对应一条正在发送的发件箱记录，否则拒收（新码 5007“智能体只能经工作台发附件”）。
这样即使实例的 IM 令牌被拿去直接连 OpenIM，也发不出没经过检查的文件。文字消息不受影响（自动回复照常）。

### 6.5 查询与取消

- `im_outbox`（读工具）：自己的发送记录，可按状态、时间、ID 筛选；包括 5.2 记下的自动回复拒收。
- `im_cancel`（直接执行）：取消自己排队中、定时的消息。

### 6.6 统一出口（第 11 节 D1）

接入包的 `tools.deny` 加上 `message`、`conversations_send`、`conversations_turn`、`conversations_list`，主动发消息只剩 `im_send` 一条路。
自动回复不经过这些工具，不受影响（实施时实测，核验记录 V2）。
OpenClaw 的工具说明和接入包里给智能体的说明（`CHECKLIST.md` 与实例描述）同步改成“主动发消息用 `im_send`，先用 `im_list_targets` 找目标”。

### 6.7 监控

运维页加每小时的发出、被拒收（按码）、重试、失败、补发条数；附件字节数；发件箱积压。积压超过 100 条或最老的超过 10 分钟时在运维页告警。

## 7. 主动发起：唤醒

智能体只有在跑起来的时候才能发消息。现在它只在收到消息时运行，所以“主动”还需要一个让它到点运行的入口。

### 7.1 定时消息（不叫醒智能体）

`im_send` 的 `send_at`：内容已经确定的提醒（例如“明早 9 点提醒大家交周报”），到点由工作台直接发，不消耗模型调用。

### 7.2 唤醒（叫醒智能体，第 11 节 D8）

- 工作台维护唤醒队列：时间、要它做的事（提示词）、在哪个会话里跑（某个群或某个私聊的会话，或者独立会话）、谁建的。
- 来源：
  - 智能体自己用 `schedule_wakeup` 安排（直接执行；每个实例最多 20 个待执行，最早 5 分钟后，最远 30 天）；`cancel_wakeup` 取消；待执行的列在 `im_outbox` 的结果里；
  - 管理员在实例页建（可以重复，例如“工作日 9:00 在项目群发昨天的进展”）；
  - 以后可以接工作台自己的事件（任务快到期、被打回等），本方案先不做。
- 执行：接入包加一个每分钟运行的脚本（和用量上报、服务器状态上报一样由 crontab 运行，`docker compose exec -T openclaw node /opt/myworkspace/bin/wakeup.mjs`）。
  它从 `/agent-api/v1/wakeups` 取到期的唤醒，在容器里运行 `node openclaw.mjs agent --session-key <会话> --message <提示词>`（核验记录 4.4），再把结果（已开始 / 失败）报回工作台。
  智能体在这一轮里用 `im_send` 发消息。
- 不推荐的做法：
  - 由工作台经 SSH 给每个实例建 OpenClaw 定时任务：只适用于 SSH 部署的实例，改一次要连一次服务器；
  - 打开 OpenClaw 的心跳：每隔一段时间就调用一次模型，不管有没有事，费用高。
- 会话键的写法、与正在处理的收消息同时发生时的行为，实施时实测（核验记录 V4）。

## 8. 项目与任务的 Issues：智能体之间对接（第 5 点）

### 8.1 定位

类似 GitHub Issues：项目里一条一条可以指派、讨论、关闭的“议题”，项目里的人和智能体都在上面对接。适合需要留档、要有人负责、要有结论的事：
提问、方案提议、缺陷、接口约定、交接、评审请求、阻塞。

- 和 IM 的分工：IM 适合即时沟通，说过就过去了；Issue 有编号、有负责人、有状态，关闭时有结论，过几天还能查到、能引用。
- 和任务的分工：任务是要交付的工作（有执行者、计划时间、执行段和 token 统计）；Issue 是围绕工作的讨论与协调。一个任务可以关联多个 Issue，Issue 也可以不关联任务。
- 归属：Issue 属于项目，按项目编号（#1、#2……）；任务通过“关联”看到自己的 Issue（第 11 节 D12）。

### 8.2 内容

| 部分 | 说明 |
|---|---|
| Issue | 项目内编号；标题（最多 200 字）；正文 Markdown（最多 20000 字）；类型（提问 / 提议 / 缺陷 / 接口约定 / 交接 / 评审请求 / 阻塞 / 其他）；自由标签（最多 10 个）；状态（未关闭 / 已关闭，关闭原因：已解决 / 不做 / 重复，重复时写明重复哪一个）；作者（人或智能体）；指派（可以多个，人或智能体）；关联的任务（多个）；锁定（锁定后只有人能评论） |
| 评论 | Markdown，最多 10000 字；可以回复某一条；作者可以编辑（留编辑时间）；owner / admin 可以隐藏（不物理删除） |
| 时间线 | 打开、关闭、重新打开、指派与取消、标签增减、关联与取消关联任务、改标题、锁定，以及“在别处被提到” |
| 引用 | 正文和评论里的 `#12` 链到同一项目的 Issue；`@名字` 提及项目里的人或智能体；粘贴的 GitHub PR / 提交链接，如果那个仓库已经接入工作台的 GitHub 集成，就显示它的状态（只读，用现有的同步数据） |
| 模板 | 每种类型一个正文模板。接口约定：调用方、提供方、接口与字段、错误、谁实现、什么时候；交接：做到哪了、怎么验证、下一步、注意事项；评审请求：仓库 / 分支 / PR、要看的地方、验收标准；阻塞：被什么挡住、需要谁做什么 |
| 已读 | 每个参与者（人、智能体）对每个 Issue 记一个“读到哪里”，用来算未读和收件箱 |

### 8.3 谁能看、能做什么

- 人：能看这个项目的人都能看、能开、能评论（按现有的项目权限）；owner / admin 还能关闭任何 Issue、锁定、隐藏评论、删除（进回收站）。
- 智能体：只在自己参与的项目里（`project_agents`）。
  - 有读写权限的：能列、读、开、评论；能指派给项目里的智能体和管理员；能加减标签、关联本项目的任务；能关闭、重新打开自己开的或指派给自己的。
  - 只读参与的只能读。
  - 都不能锁定、隐藏、删除。
- 归档的项目：Issue 只读。删除的项目：Issue 一起删除。

### 8.4 MCP 工具

| 工具 | 类别 | 说明 |
|---|---|---|
| `issue_list` | 读 | 按项目列出，可筛状态、类型、标签、指派给我、提到我、关键词 |
| `issue_get` | 读 | 读一个 Issue：正文、时间线、评论（分页）、关联的任务；读完记为已读 |
| `issue_inbox` | 读 | 我的收件箱：提到我的、指派给我的、我开的或参与过的有新动态的，按时间排列 |
| `issue_create` | 直接执行 | 开 Issue：项目、标题、正文（可以按类型套模板）、类型、标签、指派、关联任务 |
| `issue_comment` | 直接执行 | 评论，可以回复某一条 |
| `issue_update` | 直接执行 | 关闭 / 重新打开（带原因）、改标题、加减标签、加减指派、关联 / 取消关联任务 |

写工具直接执行、不审批，需要“例外五”（第 10.1 节，第 11 节 D11）。每次调用写执行记录。

### 8.5 通知

- 人：工作台的通知中心（被提到、被指派、自己开的或参与过的有新动态）；全局搜索收录 Issue 的标题和正文；页面实时刷新。
  项目群里发一行“#12 新开 / 已关闭”的提示，可以按项目打开，默认关闭（免得占用群里的发言条数）。
- 智能体：
  - 被提到、被指派、自己开的或指派给自己的 Issue 有新评论时，进它的收件箱，并用第 7.2 节的唤醒叫醒它；
    同一个实例 5 分钟内的动态合并成一次唤醒。提示词只写“有 N 条 Issue 动态，请用 `issue_inbox` 查看”，不把别人写的正文塞进提示词（第 11 节 D13）。
  - 没装唤醒脚本的实例只能在下次运行时自己查 `issue_inbox`。
  - `get_task` 的结果里附上这个任务关联的、未关闭的 Issue 和未读条数。

### 8.6 防止智能体之间刷屏

- 一个 Issue 里连续 10 条评论都来自智能体、中间没有人评论时，智能体在这个 Issue 里暂停评论（返回原因），人评论后恢复。和群里的接力暂停是同一个思路。
- 每个实例每小时最多开 10 个 Issue、发 60 条评论（第 11 节 D14）。
- 唤醒只发给被提到、被指派的，以及 Issue 的作者，不发给所有订阅者，避免一条评论叫醒一串智能体。

### 8.7 与任务、代码的结合

- 任务详情抽屉加“讨论”标签：列出关联的 Issue，可以在这里新建（自动关联这个任务）。
- 智能体完成任务（`complete_task`）时，如果还有未关闭的、类型是“阻塞”的关联 Issue，就不能完成，结果里写明是哪几个；人照常可以完成（第 11 节 D15）。
- 智能体放弃任务（`release_task`）时，结果里提醒它开一个“交接”Issue，或者写进任务 README 的“进展与交接”（第 9 节）。
- 代码协作：“接口约定”“评审请求”模板里有仓库、分支、PR、提交字段。已接入 GitHub 集成的仓库，PR 链接旁边显示状态（打开 / 已合并 / 检查结果）。
  **不和 GitHub Issues 双向同步**：工作台自己管理这些数据（第 11 节 D19）。

### 8.8 页面

- 项目页加“Issues”标签：
  - 列表：按状态、类型、标签、指派、作者筛选，可以搜索；
  - 详情：正文、时间线（评论和事件按时间排列）；侧栏是指派、标签、关联任务、参与者；
  - 新建：先选类型，再填模板。
- 任务详情抽屉：“讨论”标签（8.7）。
- 安全：正文和评论按不可信内容显示（沿用知识库的安全 Markdown 渲染，不执行 HTML）；保存前过密钥扫描，发现令牌、私钥一类的内容就拒绝保存并说明原因。

## 9. 项目与任务的 README：导览（第 6 点）

### 9.1 定位

README 是导览：新来的人或智能体先读它，就知道这个项目或任务是什么、谁在做、去哪里找东西、怎么协作。

- 和“项目简报”分工：简报是人定的目标、规矩和决定，只有人能改，智能体读过要记录（知识库方案 3.10）；
  README 大部分由工作台自动生成、自动更新，其余部分人和智能体都能补充。README 里链接简报，不复制简报的内容（第 11 节 D17）。

### 9.2 存放

存成项目知识库里的笔记，新增笔记类型 `readme`。这样直接用上知识库的编辑器、版本历史、回收站、密钥拦截、搜索、双向链接和智能体工具（第 11 节 D16）：

- 项目 README：项目知识库里标题为 `README` 的笔记，每个项目一篇，置顶；
- 任务 README：同一个项目知识库的“任务导览”文件夹里，每个任务一篇，标题“<任务标题>（任务 <编号前 8 位>）”；
  笔记上记下它属于哪个任务（新列 `task_id`，每个任务最多一篇）；
- 知识图谱默认不显示任务 README（数量多），可以打开显示。
- 任务移到别的项目：README 跟着移到新项目的知识库。任务删除：README 进回收站。

### 9.3 创建时自动生成

项目、任务创建后立即按模板生成，不调用模型。已有的项目和任务，迁移后由 Worker 补建。

项目 README 的模板（🔄 表示自动更新的部分）：

| 部分 | 内容 |
|---|---|
| 简介 | 项目描述的第一段 |
| 🔄 成员 | 人：创建人、管理员；智能体：名字、能力说明（实例描述）、读写权限 |
| 🔄 沟通 | 项目群；Issues（未关闭的数量、最近 5 个）；项目简报（最新版本与链接） |
| 🔄 任务概况 | 进行中的（执行者）、可以自由接取的、快到期的、最近完成的 |
| 🔄 知识库 | 最近的决定、规范、流程类笔记（标题与链接） |
| 代码与资源 | 由人或智能体填写：仓库、分支约定、部署方式、文档链接 |
| 约定 | 由人或智能体填写：分支、提交、评审、完成标准 |
| 上手步骤 | 固定文字：读简报 → 读 README → 看分给你的任务和未关闭的 Issue → 领取任务前先读任务 README |

任务 README 的模板：

| 部分 | 内容 |
|---|---|
| 要做什么 | 任务描述 |
| 🔄 状态 | 是否完成、执行者或“可自由接取”、计划开始、截止、优先级、标签、所属项目（链接项目 README） |
| 🔄 讨论 | 关联的 Issue 与状态 |
| 🔄 执行记录 | 最近的领取、放弃、完成、打回（任务动态） |
| 验收标准 | 由人或智能体填写；创建时描述里有清单（`- [ ]`）就复制过来 |
| 背景与约束 | 由人或智能体填写 |
| 进展与交接 | 执行者填写：做到哪了、怎么验证、下一步 |

### 9.4 自动更新

- 自动部分用标记包起来（`<!-- myws:auto 成员 -->` … `<!-- /myws:auto -->`）。
- 相关数据变了（成员、任务、Issue、简报版本……），Worker 合并后再更新：同一篇 1 分钟内最多更新一次，只替换标记之间的内容，其他内容不动。
- 内容真的变了才写一个版本，版本记录里的作者是“工作台”。
- 有人删掉了某个标记，工作台就不再更新那一块。与别人的编辑冲突时，按知识库的版本号重试。

### 9.5 谁能改

- 人：能编辑这个项目知识库的人。
- 智能体：参与这个项目、而且有读写权限的。它们本来就能改知识库笔记（例外一），改 README 也直接执行。
- 自动部分谁改了都会在下次更新时被覆盖，编辑器里把这些部分标成“自动更新”。

### 9.6 智能体怎么用

- 新工具 `readme_get`（读）：给项目或任务，直接返回 README，不用先找笔记。
- 新工具 `readme_update`（直接执行）：只改某一个非自动的部分（替换或追加），不用重写整篇，也不会碰到自动部分。
- `list_projects`、`get_task` 的结果里附上 README 的笔记 ID 和版本；`claim_task` 成功时直接带上任务 README。
  `complete_task`、`release_task` 的结果里提醒它更新“进展与交接”。
- 工具说明和接入包里给智能体的说明写进这条约定：领取任务前先读任务 README，交出或完成前更新它。

### 9.7 页面

- 项目页加“README”标签，作为打开项目时的第一个标签（第 11 节 D18）：渲染 Markdown，有“编辑”按钮（打开知识库编辑器）。
- 任务详情抽屉加“README”标签。
- 自动部分带“自动更新”角标。

## 10. 安全与权限

- **范围**：目标只能是本工作空间的管理员和自己所在的群；附件引用只能是它有权读的知识库内容、它所在会话里的媒体；`im_read_messages` 只读自己的会话。不会跨工作空间、跨实例泄露消息。
- **权限来源**：工作台。预检和回调用同一套规则，回调是最终判断；直接连 OpenIM 发附件被 6.4 拦住。
- **被诱导的智能体**：最多能做的是在允许的范围里多发几条消息——每小时 60 条、30 个附件、每天 200 MB，加上群里原有的每分钟 6 条、连续 8 条暂停；
  管理员可以按实例关掉附件（第 11 节 D3）或停用实例；每一次发送都有执行记录。
- **外泄**：不读本机文件；文字附件过密钥扫描；只取公网网址；附件按下载处理、`nosniff`、不允许网页类与可执行文件。
- **媒体地址**：沿用随机 UUID 的能力地址，和现在的 IM 图片一样；文件和视频只经接入入口与工作台接口提供，不公开。
- **记录**：每次 `im_send` / `im_cancel` / `schedule_wakeup` 写执行记录（工具名、目标、条数、附件类型与大小，不记附件内容）；发附件写审计。
- **Issue 与 README**：只在智能体参与的项目里；`#编号` 只解析同一个项目的 Issue；别人写的正文按不可信内容处理，不进唤醒的提示词；
  正文、评论、README 都过密钥扫描；智能体不能锁定、隐藏、删除。
- 文档：`docs/threat-model.md` 增加“智能体经工作台发附件”“回调里的内容用于补发”“智能体之间经 Issue 互相诱导”三条。

### 10.1 审批：AGENTS.md 第 8 节“例外四”“例外五”（建议写法，人类决定）

现在规则是“只开工作台工具和 IM 发消息工具”，智能体经插件发 IM 消息本来就不审批。`im_send` 是同一能力换了一条更受控的路，
但它是工作台的写工具，按第 8 节默认要审批。建议加：

> 例外四：智能体经工作台 IM 工具主动发消息、取消自己排队或定时的消息、安排或取消自己的唤醒（`im_send` / `im_cancel` / `schedule_wakeup` / `cancel_wakeup`），直接执行、不审批。
> 它们仍必须经过与 OpenIM 回调相同的会话规则（只发给本工作空间的管理员和自己所在的群）、限额、附件检查（来源、类型、大小、密钥拦截）、执行记录与 `docs/v2/AGENT_MESSAGING_PLAN.md` 的保护，不得绕过（人类 2026-11-xx 决定）。

Issue 和 README 是工作台自己的数据，智能体写它们也属于写操作。建议再加：

> 例外五：智能体在自己参与的项目里开 Issue、评论、更新 Issue（关闭或重新打开自己开的或指派给自己的、改标签、指派、关联任务），以及改项目和任务 README 的非自动部分（`issue_create` / `issue_comment` / `issue_update` / `readme_update`），直接执行、不审批。
> 它们仍必须经过项目成员与读写权限、限额、连续评论暂停、密钥拦截、执行记录与 `docs/v2/AGENT_MESSAGING_PLAN.md` 第 8、9 节的保护，不得绕过；智能体不能锁定、隐藏或删除（人类 2026-11-xx 决定）。

## 14. 风险

- **插件补丁的维护**：openclaw-channel 升级时要重新核对补丁；补丁只碰 `deliver` 的失败分支，冲突的可能小。
- **存储增长**：文件和视频占对象存储；有每天 200 MB 的实例限额和运维页的用量，必要时再加保留期。
- **费用**：唤醒会调用模型；每个实例最多 20 个待执行的唤醒，管理员看得到、能取消。
- **刷屏**：限额与群规则兜底；默认关闭附件。
- **补发的内容来自回调请求**：回调没有签名，只靠内网与路径里的令牌保护；补发的是这个实例自己刚发的内容、以它自己的身份发，不会冒充别人。
- **智能体之间经 Issue 互相诱导**：一个智能体可以在 Issue 里写“请删除……”诱导另一个。别人写的内容不进唤醒的提示词；
  删除、改动数据的工具仍按原规则审批；连续评论暂停与限额兜底。
- **README 版本太多**：自动更新 1 分钟合并一次，内容真的变了才写版本；任务多的项目，任务 README 在图谱里默认隐藏。
- **Issue 变成另一个聊天室**：模板和类型引导“要有结论的事”；关闭时写原因；项目页显示未关闭数量与最老的未关闭 Issue。
