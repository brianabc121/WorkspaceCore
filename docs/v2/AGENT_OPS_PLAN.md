# 智能体能力补齐与 OpenClaw 服务器运维升级方案（T-0109）

> 状态：**待批准**。人类 2026-11-04 要求核对部署好 OpenClaw 后九项能力是否具备，核对后说“可以，先给我一份升级方案”。
> 第 9 节列出要人类决定的事项（每项都有推荐做法）。核验记录见 `docs/decisions/2026-11-04-agent-ops-verification.md`。
>
> **需求来源**（人类 2026-11-04 列出的九项）：
> 1. 智能体与工作台之间的连接；2. 增删改查知识库；3. 用 OpenIM 进行任务沟通和项目对接；4. 接取和完成任务；
> 5. 建立新任务；6. 新建项目；7. 在日历上新增待办；
> 8. OpenClaw 运行环境的信息（内存、硬盘的已用和可用，当前上传下载速率，CPU 核心数和当前负载，最近 30 天的负载）；
> 9. 通过工作台远程 SSH 连接到 OpenClaw 服务器进行运维操作。

## 2. 任务与项目（第 4、5、6 项）

### 2.1 智能体能看到“分给我的”任务（只读）

- `list_tasks` 加参数 `assigned_to_me: bool`；
- `list_tasks`、`get_task` 的任务加字段：
  - `assignee`：`{kind: "me" | "member" | "instance" | "none", name}`。成员只给显示名，不给邮箱；
  - `planned_start_at`、`started_at`、`running`（有一段正在执行）。
- 工具说明里写：领到任务后先读 `get_task`（项目有简报时先读简报），做完用 `complete_task`。

### 2.2 领取任务 `claim_task`（写，需审批）

- 参数：`task_id`。批准后把执行者设为这个实例，并开一段执行。这段和“交给它执行”开的一样，在时间轴上显示。
- 这些情况返回错误：任务已经完成、已经有执行者（领取不覆盖别人）、这个实例停用了。
- 审批卡片写明“领取任务《标题》并开始执行”。批准后，完成照旧用 `complete_task`。
- 管理员“交给它执行”的流程不变。

### 2.3 新建项目 `create_project`（写，需审批）

- 参数与网页上新建项目一样（标题、描述）。批准后建项目，并照现有逻辑自动建项目知识库。
- 发起的实例自动获得这个项目知识库的读写权限，管理员可以在知识库设置里收回（D3）。
- 不提供改项目、归档、删项目的工具。这些只在网页上做。

### 2.4 新建任务

`create_task` 已有，不改。新建后要领取，就再调 `claim_task`。

## 3. 日历待办（第 7 项）

- 不新增“待办”类型。待办用两种方式表示：
  - 带截止时间的任务（`create_task` 加 `due_at`）。日历页已经显示它们；
  - 全天日程（`create_calendar_event` 的 `all_day`）。
- `calendar_agenda` 的输出加 `due_tasks`：这段时间里有截止时间、还没完成的任务（标题、截止时间、所属项目、是否分给我）。
- 工具说明里写明这两种用法。

## 4. 项目群（第 3 项）

- 项目页加“项目群”按钮，一键建一个 OpenIM 群：
  - 群名是项目名，群公告是项目描述的前 200 字；
  - 成员是发起的管理员，加上参与这个项目的实例（在项目知识库里有权限的实例，以及项目里任务的执行者）。
- 之后有实例开始参与这个项目时（被加进项目知识库，或领取、被分到项目里的任务），自动拉进群。
- 项目归档时，群保留，在群公告里标注“项目已归档”。项目删除时，解散群。
- 群的规则照旧：连续 8 条实例消息自动暂停、管理员发言后恢复；实例之间仍然不能私聊。
- “交给它执行”默认仍发到管理员与实例的单聊；同时在项目群里发一条“已交给 @甲 执行《任务》”的通知（D4）。
- 数据：`im_groups.project_id`，可空，每个项目最多一个群。这一项需要迁移。

## 5. 服务器状态（第 8 项）

### 5.1 采集（接入包）

- 新脚本 `bin/host-report.mjs`。crontab 每分钟在 OpenClaw 容器里运行一次，与用量上报的做法相同：
  - SSH 部署自动写进 crontab；
  - 手动接入的按 CHECKLIST 加一行；
  - 旧接入包重新部署后才有。
- 读的都是容器里的 `/proc` 与文件系统统计。已在锁定镜像上实测：`node` 用户、host 网络、去掉全部 capability 时，读到的值与宿主机一致（核验 ADR 第 1 节）。
  - **CPU**：核心数、型号；1 / 5 / 15 分钟负载（`/proc/loadavg`）；使用率由 `/proc/stat` 的累计值算出（工作台用两次上报之差计算）。
  - **内存**：`MemTotal`、`MemAvailable`，已用 = 总量 − 可用；另报 Swap 的总量与已用。
  - **磁盘**：两个分区的总量、已用、可用。一个是接入包目录所在的分区，OpenClaw 的会话和记忆在这里；另一个是 Docker 数据目录所在的分区（容器根目录），镜像在这里。
  - **网络**：默认路由那块网卡（从 `/proc/net/route` 取）的收、发累计字节。工作台用两次之差算每秒上传、下载速率。
  - **开机时长**。
- 只报数字，不报进程、文件名、环境变量、IP 地址。

### 5.2 接口与存储

- `POST /agent-api/v1/host-metrics`：用实例凭证，每个实例每分钟最多 2 次，严格校验（多余字段返回 422，数值有上下限）。
- 工作台保存两样东西：
  - **每分钟一条样本**：CPU 使用率、三个负载值、核心数、内存与 Swap、两个分区、上下行速率。保留 30 天，每个实例约 4.3 万条。
  - **每个实例上一次的累计值**：用来算 CPU 使用率和网速。计数器变小（重启或回绕）时，这一分钟记为空。
- 每天的清理任务删除 30 天前的样本。这一项需要迁移。

### 5.3 界面（实例页“服务器状态”）

- **当前值卡片**：
  - CPU：核心数、使用率、1 / 5 / 15 分钟负载；
  - 内存：已用 / 总量 / 可用；
  - 两个分区：已用 / 总量 / 可用，配占用条；
  - 网络：当前上传、下载速率；
  - 开机时长、最后上报时间。超过 3 分钟没上报，显示“数据过期”。
- **趋势图**：最近 24 小时、7 天、30 天可切换。四张图分别是负载与 CPU 使用率、内存、磁盘、网络上下行，每小时取平均和峰值；有悬停提示，也有表格视图。
- **实例列表**：每个实例显示 CPU、内存、磁盘三个小指示，超过阈值标红。
- 手机宽度可用。

### 5.4 告警

以下情况通知 owner / admin。同一实例同一类告警恢复前只提醒一次，恢复后再出现时再提醒：

- 磁盘可用低于 10%；
- 内存可用低于 5%；
- 15 分钟负载持续 15 分钟超过核心数的 2 倍；
- 30 分钟没有上报指标（与离线提醒合并，不重复）。

阈值先用这些默认值（D5）。

### 5.5 智能体读自己的服务器状态

新增只读工具 `get_host_status`，只返回调用它的实例自己的当前值与 24 小时概况，帮助它判断磁盘满、负载高这类问题（D3）。不提供看别的实例的工具。

## 6. 远程运维（第 9 项）

### 6.1 推荐：固定的运维动作（D1 选 A）

走现有的 SSH 通道：工作台密钥库里的专用密钥，加上部署时确认过的主机指纹。命令写死在工作台里，不拼接任何用户输入；在接入包目录里执行，只作用于这个实例的 Compose 项目。

| 动作 | 做什么 | 二次认证 |
|---|---|---|
| 查看状态 | 容器状态（`docker compose ps`）、本项目容器的 CPU / 内存（`docker stats --no-stream`）、磁盘（`df`）、开机时长与负载 | 不需要 |
| 查看日志 | OpenClaw 容器最近 200 行日志；也可以选隧道、取图代理的日志 | 不需要（日志可能含对话片段，只给 owner / admin，并写审计） |
| 重启 OpenClaw | `docker compose restart openclaw` | 需要 |
| 重新拉起全部服务 | `docker compose up -d` | 需要 |
| 清理无用镜像 | `docker image prune -f`（只删没在用的镜像，回收磁盘） | 需要 |
| 立即上报一次 | 在容器里运行用量与服务器指标两个上报脚本 | 不需要 |
| 重新部署 / 卸载 / 吊销 | 已有，不变 | 已有规则 |

- **权限**：只有 owner / admin。二次认证是再输一次自己的登录密码，与审批高危操作相同。
- **执行**：同一实例同一时间只跑一个动作。超时 60 秒，重新拉起是 180 秒。
- **输出**：最多保留 64 KB，先脱敏（令牌、密钥、`Authorization`、私钥块）再存，实例页显示，保留 7 天。
- **审计**：谁、什么时候、对哪个实例、做了什么动作、退出码。不记输出原文。
- **适用范围**：只适用于用 SSH 部署过的实例。手动接入的实例，先在实例页做一次 SSH 部署（会原样重装接入包，会话和记忆在 `state/` 里保留）。

### 6.2 不推荐：网页终端（D1 选 B）

在浏览器里打开一个能执行任意命令的 SSH 终端。部署账号在 docker 组，等同于 root；浏览器会话一旦被盗用，就能完全控制这台服务器。

如果确实需要，单独决定，并至少做到：每次打开都二次认证、会话录像进审计、10 分钟无操作断开、只允许 owner。

## 7. 安全与权限

- **智能体的工具限制不放宽**：
  - `claim_task`、`create_project` 都走审批；
  - `get_host_status` 只读，只能看自己；
  - 仍然不开 exec，不挂 Docker socket，运维动作只在工作台发起。
- **服务器指标**：只收数字，按实例凭证归到实例所在的工作空间；外网入口照旧需要客户端证书。
- **运维动作**：命令固定、只在接入包目录执行；SSH 私钥只在工作台的密钥库里，用于连接时解密，不进日志和响应。
- **项目群**：成员只从本工作空间的实例和管理员里选；智能体之间不能私聊的规则不变。

## 8. 核验

- 容器里读主机指标：已在锁定镜像 `openclaw/openclaw:2026.9.36` 上实测（核验 ADR 第 1 节）。
- OpenClaw 的 MCP 客户端会拿结构化内容对照工具的输出格式校验（T-0108 已处理）：新工具的错误照样只用文字内容返回。
- Docker Compose 子命令（`ps`、`logs --tail`、`restart`、`up -d`、`stats --no-stream`、`image prune -f`）：在 agents CI 的 SSH 部署验收里，用真实的部署账号逐个跑一遍。按 `install-docker.sh` 安装的版本核对输出格式，不按记忆写解析。

## 11. 风险

- **指标是整台机器的数字**：服务器上还跑着别的程序时，负载和内存也算在内。界面写明“整台服务器”，另外在运维动作“查看状态”里给出本项目容器自己的占用。
- **容器看到的不一定是整台机器**：宿主机装了 lxcfs 或用 rootless Docker 时，`/proc` 可能是容器自己的视图。脚本同时上报 `/sys/fs/cgroup` 里的内存上限；有上限时界面标注“受容器限制”。
- **旧接入包没有指标**：要重新部署。实例页显示“未上报，重新部署后可用”。
- **运维动作依赖 SSH**：服务器的 SSH 不通时，运维动作不可用；指标上报不受影响，走的是接入入口。
