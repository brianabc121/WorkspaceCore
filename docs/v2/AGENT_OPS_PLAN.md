# 智能体能力补齐与 OpenClaw 服务器运维升级方案（T-0109）

> 状态：**已批准，实施中**（人类 2026-11-04 在对话中说“给我根据这份方案 全部落实”；D1 ~ D7 按推荐执行，见第 9 节）。
> 批准前的说明：人类 2026-11-04 要求核对部署好 OpenClaw 后九项能力是否具备，核对后说“可以，先给我一份升级方案”。
> 同日看过第一版后做了三处调整（见下面“调整”），本版已按调整改写第 2、3、7、9、10 节。
> 第 9 节列出已定和仍要人类决定的事项（未定的都有推荐做法）。核验记录见 `docs/decisions/2026-11-04-agent-ops-verification.md`。
>
> **需求来源**（人类 2026-11-04 列出的九项）：
> 1. 智能体与工作台之间的连接；2. 增删改查知识库；3. 用 OpenIM 进行任务沟通和项目对接；4. 接取和完成任务；
> 5. 建立新任务；6. 新建项目；7. 在日历上新增待办；
> 8. OpenClaw 运行环境的信息（内存、硬盘的已用和可用，当前上传下载速率，CPU 核心数和当前负载，最近 30 天的负载）；
> 9. 通过工作台远程 SSH 连接到 OpenClaw 服务器进行运维操作。
>
> **调整**（人类 2026-11-04，看过第一版后）：
> 1. 新建项目时可以勾选要加入的 OpenClaw 智能体；同时在 IM 里为用户建一个项目群，把勾选的智能体拉进群。
> 2. 任务可以由管理员指派，也可以设为“自由接取”：空闲的智能体根据任务描述判断是否符合自己的能力，符合就自主接取；
>    智能体完成后可以把任务设为完成；管理员觉得还有问题，可以把任务打回到进行中。
> 3. 智能体可以新建项目、把其他智能体拉进这个项目，但这是管理员设置的开关，管理员按实例分配；没有分配的智能体不能建项目。

## 2. 项目：成员、项目群与智能体建项目（第 3、6 项）

### 2.1 项目成员（智能体）

- “智能体加入项目”沿用现有的定义：在项目知识库里有读写权限（`docs/v2/KNOWLEDGE_PLAN.md` 的“参与的项目库”）。
  加入后，它能读写项目知识库、读项目简报，也会被拉进项目群。
- 项目页加“成员”区：列出加入的智能体，owner / admin 可以加入或移出。
  - 加入或移出时同步项目知识库的权限和项目群的成员。
  - 移出不影响它已经领取的任务，那些任务由管理员处理（改派或打回自由接取）。

### 2.2 网页上新建项目：勾选智能体、自动建项目群

- 新建项目的表单多一栏“加入的智能体”：列出本工作空间启用的实例，可以多选，显示名字、能力说明（实例的“描述”）、在线状态。
  这一栏和项目群只给 owner / admin。IM 只开放给 owner / admin；member 新建项目照旧，没有这一栏。
- 创建时一次完成四件事：
  - 建项目；
  - 建项目知识库（现有逻辑）；
  - 让勾选的智能体加入项目；
  - 建 IM 项目群：群名是项目名，群主是创建项目的人，成员是创建人和勾选的智能体，群公告是项目描述的前 200 字。
- OpenIM 暂时不可用时，项目照常建好，项目页显示“项目群还没建好”。Worker 每分钟重试；也可以手动点“重试”。
  建群用固定的幂等键，重试不会建出两个群。
- 以前建的项目，项目页有“建项目群”按钮，成员是点按钮的人和已加入的智能体。
- 项目归档时，群保留，群公告里标注“项目已归档”；项目删除时，解散群。
- 群里照旧：连续 8 条实例消息自动暂停、管理员发言后恢复；实例之间仍然不能私聊，项目沟通在项目群里进行。
- 数据：`im_groups.project_id`，可空，每个项目最多一个群；还有项目群的建群状态。需要迁移。

### 2.3 智能体建项目：管理员按实例开权限

- 实例页加开关“允许它新建项目、拉智能体进项目”，默认关。只有 owner / admin 能开或关，每次都写审计，并记下是谁开的。
- 没开的实例：
  - 它的工具列表里没有下面三个工具；
  - 直接调用也会被拒绝（`FORBIDDEN_CAPABILITY`），并留下一条“拒绝”记录。
- 开了的实例多出三个工具，都**直接执行、不审批**。开权限就是管理员事先授权，每次操作都有记录，并通知管理员：
  - `create_project`：标题、描述，以及一开始就拉进来的智能体（可选）。
    - 建出来的项目和网页上建的一样：有项目知识库、有项目群。
    - 它自己自动加入项目。
    - 群主是给它开权限的那位管理员（那位已经不在工作空间时，改为 owner）；成员是那位管理员、它自己和它拉进来的智能体。
  - `add_project_agents`：把其他智能体拉进项目。
    - 只能拉进它自己建的项目；
    - 只能拉本工作空间里启用的实例；
    - 被拉进来的智能体得到项目知识库的读写权限，并被拉进项目群。
  - `list_agents`：列出本工作空间的智能体（名字、能力说明、在线、是否空闲），用来决定拉谁。
- 限额：每个实例每小时最多建 5 个项目、拉人 20 次，超出返回 `RATE_LIMITED`。
- 关掉开关后，它已经建的项目和拉进来的成员都保留，只是不能再建、再拉。
- 智能体不能改、归档或删除项目，也不能把智能体移出项目，这些都在网页上做。

## 3. 任务：指派、自由接取、完成与打回（第 4、5 项）

### 3.1 两种接取方式

| 方式 | 谁来定 | 怎么开始 |
|---|---|---|
| 管理员指派 | owner / admin 把执行者设成某个实例，点“交给它执行”（现有） | 用管理员的 IM 把任务发给它，同时开一段执行 |
| 自由接取 | owner / admin 把任务设为“可自由接取”，可以选范围：全部智能体（默认），或只限项目成员 | 空闲的智能体自己判断能不能做，能做就用 `claim_task` 领取 |

- 任务列表、看板、时间轴、任务详情上都显示“可自由接取”标记；时间轴上，还没人领的自由任务放在“未分配”一行。
- 设为可自由接取的条件：任务没有完成、没有执行者。已经有执行者的，要先改回“未分配”。
- 数据：任务的接取方式（指派 / 自由接取）和自由接取的范围。需要迁移。

### 3.2 空闲的智能体怎么知道有任务

- 任务被设为可自由接取（或被放弃、被打回自由接取）时，工作台用设置人的 IM 账号，给符合条件的智能体各发一条消息，内容包括任务标题、`task_id`、所属项目、截止时间，以及这段说明：“先用 `get_task` 看描述，符合你的能力就用 `claim_task` 领取；不符合不用回复。”
  - 用管理员的 IM 账号，是因为接入包的 IM 渠道只放行管理员，和“交给它执行”一样。
  - 符合条件是指：在线、空闲、有写权限（scope 为 `read_write`）、在范围内。
- **空闲**：这个智能体现在没有正在执行的任务。一个智能体同一时间只做一个任务。
- 智能体也可以随时用 `list_tasks` 加 `claimable: true` 查，结果只含它能领取的任务。

### 3.3 领取：`claim_task`（直接执行，不审批）

- 条件：
  - 任务可自由接取、没有执行者、没有完成、在它的范围内；
  - 智能体空闲、启用、scope 为 `read_write`。
- 先到先得：工作台用一条带条件的更新（“执行者为空”才更新）完成领取，晚到的返回 `TASK_ALREADY_CLAIMED`。
- 领取后：
  - 执行者设为它，开一段执行，时间轴上从这时开始画；
  - 它还不是项目成员的话，自动加入项目，得到项目知识库读写权限并被拉进项目群（D3）；
  - 通知管理员（通知中心），项目群里发一条“甲领取了《任务》”。
- 限额：每个实例每小时最多领取 10 次。
- 不满足条件时返回明确的错误码：`TASK_NOT_CLAIMABLE`、`TASK_ALREADY_CLAIMED`、`AGENT_BUSY`、`FORBIDDEN_SCOPE`。

### 3.4 放弃：`release_task`（直接执行）

- 只能放弃自己领取的、还没完成的任务。要写原因，原因记进任务的动态。
- 这段执行结束，记为暂停。执行者清空，任务回到可自由接取，并按第 3.2 节重新通知。
- 管理员指派的任务不能用这个工具放弃，要在单聊里跟管理员说。

### 3.5 完成：`complete_task` 改为直接执行

- 智能体只能完成执行者是自己的任务，管理员指派的和自己领取的都算。
- 完成后：任务标为完成，这段结束（`done`），通知管理员，项目群里发一条“甲完成了《任务》”。
  智能体可以附一段完成说明（可选），写进任务的动态。
- 不设“待验收”队列，管理员不必逐个确认。这与取消知识库“人已确认”的考虑一致；有问题时用打回。

### 3.6 打回

- 已完成的任务，owner / admin 可以“打回”，必须写原因。
  - 任务回到进行中：未完成、执行者不变，给原执行者开新的一段执行；
  - 时间轴上能看到打回的时刻。
  - 用管理员的 IM 把打回原因发给执行的智能体（“《任务》被打回：原因……请继续处理，做完再用 `complete_task`。”），原因同时写进任务的动态。
- 原执行者不在了（停用或删除）时，打回会把任务放回“未分配”。管理员可以重新指派，或设为可自由接取。

### 3.7 智能体能看到的任务信息（只读）

- `list_tasks` 加两个筛选：`assigned_to_me`（分给我的）、`claimable`（我能领取的）。
- `list_tasks`、`get_task` 的任务加这些字段：
  - `assignee`：`{kind: "me" | "member" | "instance" | "none", name}`。成员只给显示名，不给邮箱；
  - 接取方式和范围、`planned_start_at`、`started_at`、`running`；
  - 最近一次打回的原因。

### 3.8 新建任务

`create_task` 已有，照旧走审批。

## 4. 日历待办（第 7 项）

- 不新增“待办”类型。待办用两种方式表示：
  - 带截止时间的任务（`create_task` 加 `due_at`），日历页已经显示它们；
  - 全天日程（`create_calendar_event` 的 `all_day`）。
- `calendar_agenda` 的输出加 `due_tasks`：这段时间里有截止时间、还没完成的任务，含标题、截止时间、所属项目、是否分给我、能否领取。
- 工具说明里写明这两种用法。

## 5. 服务器状态（第 8 项）

### 5.1 采集（接入包）

- 新脚本 `bin/host-report.mjs`。crontab 每分钟在 OpenClaw 容器里运行一次，与用量上报的做法相同：
  - SSH 部署自动写进 crontab；
  - 手动接入的按 CHECKLIST 加一行；
  - 旧接入包重新部署后才有。
- 读的都是容器里的 `/proc` 与文件系统统计。已在锁定镜像上实测：`node` 用户、host 网络、去掉全部 capability 时，读到的值与宿主机一致（核验 ADR 第 1 节）。
  - **CPU**：核心数、型号；1 / 5 / 15 分钟负载（`/proc/loadavg`）；使用率由 `/proc/stat` 的累计值算出（工作台用两次上报之差计算）。
  - **内存**：`MemTotal`、`MemAvailable`，已用 = 总量 − 可用；另报 Swap 的总量与已用。
  - **磁盘**：两个分区的总量、已用、可用。一个是接入包目录所在的分区，OpenClaw 的会话和记忆在这里；另一个是 Docker 数据目录所在的分区（容器根目录），镜像在这里。
  - **网络**：默认路由那块网卡（从 `/proc/net/route` 取）的收、发累计字节。工作台用两次之差算每秒上传、下载速率。
  - **开机时长**。
- 只报数字，不报进程、文件名、环境变量、IP 地址。

### 5.2 接口与存储

- `POST /agent-api/v1/host-metrics`：用实例凭证，每个实例每分钟最多 2 次，严格校验（多余字段返回 422，数值有上下限）。
- 工作台保存两样东西：
  - **每分钟一条样本**：CPU 使用率、三个负载值、核心数、内存与 Swap、两个分区、上下行速率。保留 30 天，每个实例约 4.3 万条。
  - **每个实例上一次的累计值**：用来算 CPU 使用率和网速。计数器变小（重启或回绕）时，这一分钟记为空。
- 每天的清理任务删除 30 天前的样本。这一项需要迁移。

### 5.3 界面（实例页“服务器状态”）

- **当前值卡片**：
  - CPU：核心数、使用率、1 / 5 / 15 分钟负载；
  - 内存：已用 / 总量 / 可用；
  - 两个分区：已用 / 总量 / 可用，配占用条；
  - 网络：当前上传、下载速率；
  - 开机时长、最后上报时间。超过 3 分钟没上报，显示“数据过期”。
- **趋势图**：最近 24 小时、7 天、30 天可切换。四张图分别是负载与 CPU 使用率、内存、磁盘、网络上下行，每小时取平均和峰值；有悬停提示，也有表格视图。
- **实例列表**：每个实例显示 CPU、内存、磁盘三个小指示，超过阈值标红。
- 手机宽度可用。

### 5.4 告警

以下情况通知 owner / admin。同一实例同一类告警恢复前只提醒一次，恢复后再出现时再提醒：

- 磁盘可用低于 10%；
- 内存可用低于 5%；
- 15 分钟负载持续 15 分钟超过核心数的 2 倍；
- 30 分钟没有上报指标（与离线提醒合并，不重复）。

阈值先用这些默认值（D7）。

### 5.5 智能体读自己的服务器状态

新增只读工具 `get_host_status`，只返回调用它的实例自己的当前值与 24 小时概况，帮助它判断磁盘满、负载高这类问题（D5）。不提供看别的实例的工具。

## 6. 远程运维（第 9 项）

### 6.1 推荐：固定的运维动作（D1 选 A）

走现有的 SSH 通道：工作台密钥库里的专用密钥，加上部署时确认过的主机指纹。命令写死在工作台里，不拼接任何用户输入；在接入包目录里执行，只作用于这个实例的 Compose 项目。

| 动作 | 做什么 | 二次认证 |
|---|---|---|
| 查看状态 | 容器状态（`docker compose ps`）、本项目容器的 CPU / 内存（`docker stats --no-stream`）、磁盘（`df`）、开机时长与负载 | 不需要 |
| 查看日志 | OpenClaw 容器最近 200 行日志；也可以选隧道、取图代理的日志 | 不需要（日志可能含对话片段，只给 owner / admin，并写审计） |
| 重启 OpenClaw | `docker compose restart openclaw` | 需要 |
| 重新拉起全部服务 | `docker compose up -d` | 需要 |
| 清理无用镜像 | `docker image prune -f`（只删没在用的镜像，回收磁盘） | 需要 |
| 立即上报一次 | 在容器里运行用量与服务器指标两个上报脚本 | 不需要 |
| 重新部署 / 卸载 / 吊销 | 已有，不变 | 已有规则 |

- **权限**：只有 owner / admin。二次认证是再输一次自己的登录密码，与审批高危操作相同。
- **执行**：同一实例同一时间只跑一个动作。超时 60 秒，重新拉起是 180 秒。
- **输出**：最多保留 64 KB，先脱敏（令牌、密钥、`Authorization`、私钥块）再存，实例页显示，保留 7 天。
- **审计**：谁、什么时候、对哪个实例、做了什么动作、退出码。不记输出原文。
- **适用范围**：只适用于用 SSH 部署过的实例。手动接入的实例，先在实例页做一次 SSH 部署（会原样重装接入包，会话和记忆在 `state/` 里保留）。

### 6.2 不推荐：网页终端（D1 选 B）

在浏览器里打开一个能执行任意命令的 SSH 终端。部署账号在 docker 组，等同于 root；浏览器会话一旦被盗用，就能完全控制这台服务器。

如果确实需要，单独决定，并至少做到：每次打开都二次认证、会话录像进审计、10 分钟无操作断开、只允许 owner。

## 7. 安全与权限

**审批的变化**（人类 2026-11-04 决定）：

| 操作 | 现在 | 改后 |
|---|---|---|

  建议的写法：
  - “例外二：智能体领取、放弃自由接取的任务，以及完成执行者是它自己的任务，直接执行、不审批；管理员可以打回（人类 2026-11-04 决定）。”
  - “例外三：管理员按实例开启‘项目管理’权限后，智能体新建项目、把智能体拉进它建的项目，直接执行（人类 2026-11-04 决定）。”
- 直接执行的保护措施：
  - 都留执行记录（与知识库工具一样记在“AI 工具执行”里，标明“直接执行”）；
  - 每小时限额（领取 10、建项目 5、拉人 20）；
  - 领取要求空闲，一次只做一个任务；
  - 每次领取、完成、建项目、拉人都通知管理员；
  - 管理员随时可以打回、改派、关闭权限、停用实例。
- 工具限制不放宽：
  - `get_host_status` 只读，只能看自己；
  - 仍然不开 exec，不挂 Docker socket，运维动作只在工作台发起。
- 服务器指标：只收数字，按实例凭证归到实例所在的工作空间；外网入口照旧需要客户端证书。
- 运维动作：命令固定、只在接入包目录执行；SSH 私钥只在工作台的密钥库里，用于连接时解密，不进日志和响应。
- 项目群：成员只从本工作空间的管理员和实例里选；智能体之间不能私聊的规则不变。

## 11. 风险

- **指标是整台机器的数字**：服务器上还跑着别的程序时，负载和内存也算在内。界面写明“整台服务器”，另外在运维动作“查看状态”里给出本项目容器自己的占用。
- **容器看到的不一定是整台机器**：宿主机装了 lxcfs 或用 rootless Docker 时，`/proc` 可能是容器自己的视图。脚本同时上报 `/sys/fs/cgroup` 里的内存上限；有上限时界面标注“受容器限制”。
- **旧接入包没有指标**：要重新部署。实例页显示“未上报，重新部署后可用”。
- **运维动作依赖 SSH**：服务器的 SSH 不通时，运维动作不可用；指标上报不受影响，走的是接入入口。
- **自由接取的通知会让每个空闲的智能体调用一次模型**：智能体多时有 token 开销。只通知符合条件的智能体，范围可以按任务收窄（D2）。
- **智能体直接完成任务后可能做得不对**：靠打回兜底。时间轴和通知中心能看到谁完成了什么，打回原因会写进任务的动态。
- **项目群依赖 OpenIM**：OpenIM 不可用时项目照常建，群稍后补建；在补建之前，“项目群里发一条通知”这类消息会跳过，不重放。
