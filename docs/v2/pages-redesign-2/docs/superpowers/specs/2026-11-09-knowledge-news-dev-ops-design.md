# Workspace 第二批四页改造方案：知识库、早报、开发者、运维

**用途：交给 Claude 实施的设计与产品规范。**
**核对基线：origin/main 5f5e9c8，已包含 PR #177 首页工作总览。实施时重新 fetch 最新主干。**
本包只包含方案、实施清单和效果图，不是已经开发完成的版本。不重复上一批任务／项目／日历／邮件改造，也不覆盖已实现首页。

## 1. 目标与视觉方向

- 知识库：空间导航、关联图谱、选中笔记、最近更新形成完整阅读工作区。
- 早报：优先阅读真实 AI 摘要和可核验来源，保留今天、往期、热榜、RSS、搜索、收藏。
- 开发者：在只读边界内看清仓库、Issues、PR、Actions 和同步状态。
- 运维：区分服务故障与指标采集状态，让异常可定位、数字可解释，保留预设指标与存储管理能力。
- 四页共用现有蓝紫色、亮暗主题、细边框卡片和字体层级；知识库保留独立沉浸工作区，其余三页沿用工作台壳。

## 2. 全局边界

- 沿用 Vue 3 / TypeScript / Vite / Pinia / TanStack Vue Query、Tailwind/shadcn-vue/reka-ui、Lucide 与现有 d3-force；不引入新的大型图谱、图表或阅读框架。
- 保留既有导航、搜索、创建、主题、角色、模块宿主、SSE 失效刷新和深链接。复用最新主干已有的共享 UI，不复制一套首页组件。
- 不重做首页，不修改上一批四页的数据规则，不改 AI 权限、第三方授权范围、部署拓扑或协作协议，不恢复 n8n。
- 新闻早报严格留在 apps/web/src/modules/news 与 services/api/app/modules/news；不能搬回旧 features/news 或 domain/news.py。
- 其余三页按当前核心路径改造；本期不夹带完整插件抽取。若最新主干已经迁移，沿用新目录，不能迁回去。
- 不编造第三方 API、Token 内容、操作记录、审查状态或来源。新增第一方聚合接口在实施清单中明确标为拟议契约。
- 无业务数据库迁移是本期目标：主要新增读侧聚合；GitHub 权限快照可放既有配置 JSON。若实施发现必须改表，另写 ADR 和加法迁移并附测试，不改历史迁移。

## 3. 统一界面与状态

- 使用现有 CSS 变量，卡片约12px圆角，正文14–16px，次要信息保持可读对比度；状态由文字、图标和颜色共同表达。
- 宽屏充分使用主区域；只为本批三页开启宽容器，知识库使用自己的布局，不把全局 main 的宽度规则改到所有页面。
- 1440/1920px：主区＋详情／信息侧栏；1024–1439px：次要栏折叠，详情用抽屉；390/768px：单列／列表后进详情。无整页横向滚动。
- 支持键盘打开、选择、关闭、焦点归还；图谱提供可访问的笔记列表替代，图表提供文字与数据表替代。
- loading、空数据、error、stale、unauthorized、not_configured、MODULE_DISABLED 分开处理。未知为“—／未知”，不能变0或绿色正常。
- 缓存数据标注 as_of／checked_at，不用“刚刚”掩盖旧数据；权限撤销后清空内容，而非继续显示旧缓存。
- 查询键包含用户、空间和实际筛选。快速切空间、选中项或时间范围时，迟到响应不能覆盖当前界面。
- 所有外部标题、摘要、错误类别按文本显示；Markdown 继续走已有安全渲染，禁止执行外部 HTML、脚本或远程图片。
- 一次刷新不应触发无关后台写操作；局部失败不清空其他正常区域。

## 4. 知识库

### 4.1 布局和保留能力
- 保留窄功能条＋知识空间导航＋主区；提供“返回工作台”，不套两层完整工作台侧栏。
- 空间区展示公共／项目／智能体知识库，显示真实计数；归档、写保护、人类与智能体权限沿用原规则。
- 主区新增“知识总览”：统计、当前笔记的局部关联、选中笔记、最近更新。
- 完整图谱、笔记列表／编辑、版本历史、冲突处理、回收站、项目／任务 README、图片与外部 AFFiNE 收藏均保留。
- 主区图谱预览优先选最近更新的一篇可读笔记，调用现有局部图谱 depth=1；点击另一篇再换。不能为了总览先下载全部正文或全量图谱。
- 右侧显示真实作者、更新时间、标签、摘要与关联；“打开笔记／编辑”按实际权限显示。404或失权时清掉该笔记，不显示上一个详情。
- 归档知识库对智能体的限制与人类编辑权限不同，不能仅凭 archived 就把所有人的编辑都关掉。
- 最近更新按笔记去重，以 updated_at 排序，不把 changes 第一页的事件数当笔记数或本周总量。

### 4.2 统计口径与拟议接口
现有 GraphOut 有 total_notes/truncated，但 nodes/edges 会截断，不能用其长度生成全局指标。
新增拟议 GET /api/v1/knowledge/overview：
- 可选 space_id（不填=全部当前可见空间）；updated_after 含／updated_before 不含，两者均必填、须带时区且前者小于后者；recent_limit 默认6，最大20。
- 返回 summary（note_count、space_count、link_count、updated_note_count）、recent_notes（复用 NoteSummary）、generated_at。
- 统计可见且未删除的笔记／空间；默认包含已有可见的归档空间，并按原界面标明归档，不改变读取权限。
- link_count 为两端均可见、未删除的笔记之间去重后的有向(source,target)关系；指定空间时至少一端在该空间。与任务／图片／外部文档的边不计入这个“笔记关联”数字。
- “本周更新笔记”是显示时区周一00:00到下周一00:00内 updated_at 命中的不同笔记数，不是修改事件总次数。前端把本地范围转成UTC参数。
- 统计和 recent_notes 应共享同一可见性条件，不泄漏其他空间／工作空间数据。统计不产生笔记版本或智能体阅读用量；空间初始化沿用现有机制。
- 若统计失败，显示未知；不能退化为当前第一页条数。

### 4.3 图谱和路由
- /knowledge 作为总览；/knowledge/graph 保留完整图谱；笔记、空间、变更、外部文档的原路径不变。
- 旧 /knowledge?focus=<id> 明确转到完整图谱并保留 focus，不丢弃旧深链接；/knowledge/graph?focus=... 仍可直达。
- 保留既有 TYPE_GROUPS、按类型／空间／作者着色、过滤和图谱截断提示。图片中混合“项目／规范／记录／智能体”的示意图例不能直接当成数据枚举。
- 局部预览明确“当前关联”；图例计数只表示当前显示集合。完整图谱 truncated 时保留提示，不伪称全量。
- 多空间同名笔记用 ID 选择，不能用标题作为唯一键；图谱隐藏或销毁时停止 simulation／事件监听。

## 5. 早报

### 5.1 布局与阅读
- 保留今天／往期／热榜／RSS／搜索／收藏六个标签、通知里的 briefing 深链接和设置页。
- 今天页左侧为真实早报阅读区，右侧为关注主题、当前条目概况、往期入口；相关资讯保留实际来源与阅读链接。
- 未结构化的 Markdown 原样安全渲染。若实际内容有标题可按真实章节排版；没有三段就不硬凑“3件事”，不新增AI请求重写正文。
- 正文内部的来源只能来自正文中的真实链接；相关资讯来源使用 NewsItemOut。不能把随机资讯的来源贴到不相关摘要段落上。
- 当前收藏／不感兴趣接口绑定真实资讯URL，不支持随意收藏一个AI段落。反馈按钮放在真实资讯条目；摘要没有明确对应URL就不显示假按钮。
- “关注主题”来自当前工作空间的实际主题。owner 可“管理兴趣”；admin 按现有规则只读设置；member/viewer 不为展示侧栏去调用受限设置接口。
- 往期使用真实早报列表、状态与游标；未授权或未部署也能展示已有可读早报时，要区分内容与数据源状态。

### 5.2 数据与状态
- 复用 GET /news/today、/briefings、/briefings/{id}、/status、/feedback 等现有模块接口，不新增生成接口。
- 顶部日期用 briefing.local_date/slot 和已有 briefingWhen，不用客户端UTC日期替换部署时区的早报日期。
- complete／receiving／pending／failed 分开；只有真实 complete 才显示“整理完成”；部分接收标明parts，不把已有片段当完整报告。
- TrendRadar不可用时，早报正文可以仍可读；主题资讯失败单独提示，不清空已保存的早报。
- 本期来源数、条目数若来自 topics.items，就明确“当前已加载”；去重按规范化URL／实际条目键，不把跨主题重复误称AI合并的同一事件。
- 图片里的“4组重复报道已合并”没有可靠字段时隐藏，不能凭空统计或用额外LLM猜出。
- 刷新只重新读取，不调用 generate、test-push 或修改设置。已有人工生成能力仍按owner权限、模式与幂等规则保留在原位置，不绑定刷新。
- 模块停用后导航／路由／小组件／事件处理保持宿主行为；不请求已停用模块、自动启用或迁回宿主硬编码导航。

## 6. 开发者

### 6.1 只读界面
- 保留仓库／Issues／Pull Requests／Actions 四标签与既有筛选、分页、source_url外链。
- 仓库视图采用统计＋仓库概览＋关注PR＋失败运行详情＋权限快照／最近更新。
- 所有主体读取本地 GitHub 投影，不能由浏览器直连 GitHub，也不能在总览GET里触发同步、测试连接、合并或重跑Actions。
- “刷新数据”只 refetch；真正“请求同步／测试连接”仍留在现有管理入口且受原角色和幂等限制。

### 6.2 统计、PR与失败摘要
新增拟议 GET /api/v1/developer/overview，从本地投影批量聚合，详见计划。
- 统计清楚标为“已同步范围”：仓库数、开放Issue数、开放PR数、近7天失败运行数；不可用数据为null，不能用第一页长度当总数。
- 失败运行按 completed 且 conclusion=failure/timed_out 计；cancelled/skipped/neutral不算失败。失败窗口采用 source_updated_at，文案说明“近7天更新的失败运行”；缺时间的记录标不完整，不猜完成时间。开放Issue/PR是当前状态，不混为同一“最近7天”统计。
- Repo.access=missing_permission/not_found 时对应子数据不可用；整体有不完整范围时标 partial，不能把缺权限解释成0个Issue。
- 图片“待审PR”本期改为“开放PR”。只有 requested_reviewers 等明确证据可标“已请求审查”；不能把全部open都当未审，也不能推断已通过审查。
- 未能按 repo_id＋同一commit head_sha建立可靠关联时，不给PR贴某个仓库最新Actions的“CI通过”标签。仅分支名相同不够；未知显示未关联或不显示。
- RunOut.failure_summary 已有 failed_jobs/failed_steps，可真实展示；缺失时写“失败步骤未同步，前往GitHub查看”，不凭空填 typecheck，不拉取和展示原始秘密日志。
- “最近动态”改为准确的“最近更新”：投影更新时间不等于操作事件；只有 synced_at 时标“同步于”，不编造“某人新建PR”的历史。

### 6.3 同步与权限证据
- sync.reason=rate_limited 时显示“GitHub限流中”及 retry_at，保留合法缓存与as_of，不能显示正常空列表。
- unauthorized 时提示重新连接并清掉不能再显示的投影／权限信息；not_configured、unavailable、stale分别处理。
- 四项权限使用现有 RepositoryPermissionCheck 枚举 metadata、issues、pull_requests、actions。
- Repo.access=ok不能证明四项都检查通过。必须读取明确的逐仓库测试快照；没有证据就显示“尚未核验”，管理者可去连接设置，不自动执行测试。
- 在现有管理员“测试连接”流程保存非敏感的逐仓库检查结果和checked_at，利用已有配置JSON；凭证、仓库范围、集成启停变化时清除旧快照。
- 开发者总览只读该快照，不返回Token、请求头或内部地址；显示“上次核验时间”，不把旧结果伪装成当前实时权限。metadata失败导致其他项未执行时，未执行项显示“未核验”，不能补成通过或失败。

## 7. 运维

### 7.1 健康状态与异常
- 复用 /operations/services、/metrics、/storage，不另建监控系统、告警规则或服务控制台。
- 服务表按当前角色与启用模块动态返回；不硬编码8个服务，不把停用的TrendRadar算故障，不向viewer暴露owner/admin专有实例或存储详情。
- 汇总正常=ok，需关注=degraded/down；unknown单列“未检查”，not_configured单列“未配置”，不混入故障数。计数基于完整返回服务列表。
- 优先显示异常表格行和选中异常详情，状态、reason、checked_at都来自接口。
- Grafana不可用但Prometheus正常时，指标仍可读；Prometheus失败但有缓存时标stale及as_of，没有缓存时为不可用。
- 图中的“上次成功10分钟前”没有现成逐服务历史字段时，不显示，改用真实最近检查时间；本期不顺带建服务历史库。
- 外链仅使用经过校验的 grafana_url；未配置不显示可点击空按钮。打开Grafana失败不影响其他区域。
- 普通刷新只做GET读取／健康检查，不重启服务、运行Shell、回收容器或触发存储探测写入。

### 7.2 指标
- 复用 request_rate、latency_p50/p95/p99、error_rate、services_up 预设及1h/6h/24h/7d时间范围，不接受浏览器PromQL。
- req/s、seconds、ratio、count分别格式化；seconds→ms仅转换一次，ratio→百分比仅乘100一次，服务在线数量不变成百分比。
- 值为null就是缺测，曲线断开，不补0或插出虚假数据；最新点缺测时当前值显示“—”。
- 多序列保留各自label，不把多个服务P95直接平均；只有数据明确对应API时才写“API P95”，否则使用真实视图标题。
- 坐标轴带单位，范围与采样步长使用API返回信息；图例、tooltip和数据表可访问，范围切换取消旧请求，不显示旧范围覆盖新范围。

### 7.3 存储
- 复用现有 StoragePanel，显示主存储／可选副本、实际自检结果、用量／配额和复制状态；无副本不显示“副本正常”。
- POST /operations/storage/check 会写、读、删探测对象，**不是普通只读重试**；仅有权限管理者显式触发，文案说明该行为，不在进入页面、定时刷新或切范围时自动执行。
- 不把对象存储配置详情、桶凭据、内部地址或探测原始错误泄漏到无权角色。

## 8. 验收与范围外内容

必须验证：
1. 知识统计不受图谱截断或分页影响，同名笔记不串详情，局部图谱可回到完整图谱，旧focus深链仍有效。
2. 早报缺三段／无来源／生成中／接收中／失败／模块停用都如实显示；刷新不新增生成、推送或反馈请求。
3. 开发者限流保留缓存与retry_at，失权清理缓存；PR不会误贴别的commit的CI状态；权限快照不会因Repo.access=ok被伪造。
4. 运维unknown与未配置不报假故障，null不补0，单位与多序列正确；刷新不触发存储写自检。
5. 390/768/1280/1440/1920、亮暗主题、键盘、跨用户／空间、迟到响应、局部失败都通过。
