# 一键部署 MCP 管理器：使用说明

MCP 管理器是一个单独的容器，里面装着 ChatGPT / Codex、Claude、WorkBuddy 的官方程序。各平台账号的登录保存在它里面，
智能体和你都经它向这些平台发消息。这篇说明教你在页面上把它部署到一台服务器上，全程不用到服务器上敲命令。

设计细节见 `docs/v2/LLM_BRIDGE_DEPLOY_PLAN.md`；手动部署见 `docs/deployment.md` 第 25.1 节。

## 1. 开始之前

| 要准备的 | 怎么确认 |
|---|---|
| 你是工作空间的 **owner** | admin 只能看，不能部署 |
| 启用了“大模型客户端” | “设置 → 应用中心”里启用 |
| 有一台工作台登录得上的服务器 | 见下面两种 |
| 那台服务器能联网 | 第一次部署要在服务器上构建镜像（下载各平台的官方程序） |

服务器从两个地方选，任选其一：

- **智能体服务器**（“智能体服务器”页）：已经保存了登录密码、确认过主机公钥指纹、点过“初始化服务器”。
- **容器服务器**（“容器服务器”页）：已经在“设置”里用 SSH 部署过一次。

同一台服务器可以部署多个 MCP 管理器，每个管理器是独立的一套账号。

## 2. 部署

1. 打开“应用 → 大模型客户端”，右上角点“管理器与账号”。
2. 点“添加 MCP 管理器”，选“一键部署到服务器”。
3. 选**服务器类型**，再选**服务器**。置灰的服务器现在不能部署，旁边写着原因（例如“还没有确认主机公钥指纹”），按提示到对应的服务器页面处理。
4. 填**名字**（例如“2 号”；智能体用这个名字指定用哪个管理器），勾选它**控制的平台**。
5. 如果出现“登录密码”一栏（容器服务器，登录账号不是 root）：这台服务器上用 Docker 要 `sudo` 密码时在这里填。
   密码只用这一次，不保存。免密 `sudo` 的服务器可以不填；没填而服务器确实要密码时，页面会提示你填了再部署一次。
6. 点“开始部署”。页面显示每一步的进度：连接 → 检查 → 上传 → 构建 → 启动 → 安装转发密钥 → 验证 → 登记。
   第一次构建通常要几分钟。
7. 看到“部署完成，已经登记到工作台”后，在下面的“平台与账号”里登录各平台的账号。

也可以从服务器页面进来：“智能体服务器”的服务器详情、“容器服务器 → 设置”里都有一个“MCP 管理器”区块，
点“在这台服务器上部署 MCP 管理器”，表单会替你选好这台服务器。

## 3. 部署之后在哪里看

- **大模型客户端 → 管理器与账号**：每个管理器一张卡片，写着部署在哪台服务器、用哪种网络方式、控制哪些平台、各账号是否已登录。
- **两个服务器页面的“MCP 管理器”区块**：这台服务器上的管理器、是否在线、部署时间、已登录的账号，以及“打开聊天”“管理”两个链接。
  这个区块只用来查看和跳转：管理器的容器**不受**那两个页面的重启、清理、回收、卸载影响；把服务器从工作台移除、改登录密码、
  吊销容器服务器的专用密钥之后，管理器也照常能用。

## 4. 日常操作（都在管理器的卡片上）

| 操作 | 什么时候用 | 会发生什么 |
|---|---|---|
| 重新部署 | 工作台升级后，卡片提示“工作台带的版本比它新” | 重新构建并启动；登录状态、会话记录、地址都保留。进行中的回合会中断 |
| 重启 | 管理器不响应 | 只重启这一个容器，再确认工作台连得上 |
| 停用 / 启用 | 暂时不让智能体和聊天页用它 | 容器照常运行，只是工作台不再调用 |
| 改名 | — | 只改名字 |
| 卸载 | 不再需要 | 停掉并删除容器、删除服务器上的部署目录和转发密钥、去掉登记。数据卷默认保留；勾选“同时删除数据卷”会连登录状态和会话记录一起删，不能恢复 |

容器服务器上部署的管理器，重新部署、重启、卸载时同样可能要再填一次登录密码。

## 5. 网络是怎么接的（不用你配置）

- 选的服务器就是工作台自己所在的服务器：管理器加入工作台的内部网络，不对外开端口。
- 其他服务器：管理器只监听那台服务器的本机地址（`127.0.0.1`，端口从 18787 起）。工作台经一条专用的 SSH 通道访问它——
  部署时会在登录账号的 `authorized_keys` 里加一行密钥，这把密钥只能转发这一个端口，不能执行命令。
  所以不用开防火墙端口，两台服务器也不用在同一个内网。

## 6. 出了问题

| 页面上的提示 | 原因 | 怎么办 |
|---|---|---|
| “这个工作台不能一键部署” | 工作台镜像里没有管理器的构建文件（很旧的镜像） | 升级工作台（`make up`），或按部署指南手动部署后“手动添加” |
| 服务器置灰，写着原因 | 工作台现在登录不上它 | 到对应的服务器页面：保存密码、确认指纹、初始化（智能体服务器）或用 SSH 部署一次（容器服务器） |
| “登录账号用 Docker 要 sudo 密码” | 容器服务器的账号不在 docker 组 | 在表单里填登录密码再部署一次 |
| “这个账号不能使用 sudo（或密码不对）” | 密码错了，或账号没有 sudo 权限 | 核对密码；账号没有 sudo 时换一个账号登记服务器 |
| “构建镜像失败” | 多半是那台服务器访问不了外网，或磁盘满了 | 展开“命令输出”看最后几行；解决后再部署一次 |
| “这台服务器的 SSH 不允许端口转发” | sshd 配置里关了 `AllowTcpForwarding` | 在那台服务器的 sshd 配置里打开它（可以只对这个登录账号打开），再部署一次 |
| “容器启动了，但工作台连不上它” | 服务器上 18787 起的端口被别的程序占了、或容器启动后退出了 | 展开“命令输出”；再部署一次会自动换下一个空闲端口 |
| “这台服务器上有一个 MCP 管理器的任务还在进行” | 同一台服务器同时只跑一个部署类任务 | 等它结束 |
| 卡片上写“服务器已从工作台移除” | 那台服务器不在工作台里了，工作台登录不上去管理它 | 管理器照常能用。要去掉它：点“卸载（只删除登记）”，页面会列出服务器上还留着什么，再到服务器上手动删除 |
| 任务显示“已中断” | 部署过程中工作台重启了 | 再点一次 |

部署失败时，服务器上已经上传的文件、已经启动的容器和已经装上的转发密钥都会自动撤回，可以放心重试。

## 7. 部署出来的东西在服务器上的位置

| 东西 | 位置 |
|---|---|
| 部署目录（构建文件、`compose.yaml`、权限 600 的令牌文件） | 登录账号主目录下的 `myworkspace-llm-bridge/<编号>/` |
| 容器 | Compose 项目 `mw-mcp-<编号>`，带标签 `myworkspace.mcp-manager=<编号>` |
| 数据卷（登录状态、会话记录、附件） | `mw-mcp-<编号>_llm-bridge-data` |
| 转发密钥 | 登录账号 `~/.ssh/authorized_keys` 里备注是 `myworkspace-mcp-<编号>` 的那一行 |

备份：`make backup` 不包含管理器的数据卷。要保留会话记录就自己备份这个卷，注意里面有各平台的登录凭据。
