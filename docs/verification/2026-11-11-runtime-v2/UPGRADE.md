# T-0222 预发布升级与回退

PR #193 仍为开发草稿。本文记录已经实现部分的升级依赖，不表示跨节点网络已验收；正式发布必须先关闭 PROGRESS.md 中的未完成项。

## 升级顺序

1. 按项目现有流程备份数据库和配置，保留可恢复的旧发布版本。本任务没有执行生产备份、生产迁移或远程安装。
2. 在验证环境升级到 0064。0060–0064 保留旧实例、卷、快照与执行记录，不自动修改历史无限资源设置，不迁移旧 Docker 环境。0064 添加全局物理身份登记；不是按用户填写的 IP 判断是否同机。
3. 前后端使用同一提交的 OpenAPI / 生成类型。`RUNNER_NETWORK_VERIFIED=false` 保持关闭；Kubernetes 服务器仍不参与调度。
4. 更新容器服务器接入包到 runner-agent **0.2.0**，并使用新包的 Compose 配置：宿主 `/etc/machine-id` 固定只读绑定到 `/run/host-machine-id`，禁止自动创建不存在的宿主路径。仅换 Python 代码而保留旧 Compose 会缺少身份，不能调度。新 agent 每 30 秒采样前调用 `/runner-api/v1/report/start`，再携带票据和身份摘要提交 `/report`。两次请求均使用现有 mwr 凭证与可信入口，不增加用户密钥；原始 machine-id 不上传。
5. 等待每台服务器的完整可信采样。管理响应中的 `report.capacity_sampled_at` 是平台签发的采样起始时间，`report.at` 是收到请求的时间。采样缺失或超过 60 秒时拒绝新增自动/指定分配，不按空闲处理。
6. 智能体服务器经保存的密码和固定主机指纹执行只读探测，OpenClaw 无需获得宿主权限。历史已安装实例没有可信承诺时，由 owner 在资源面板选择“核对已部署资源”。此操作不修改运行容器或用户的期望上限；实际无限资源仍需明确设置有限资源，不能按 0 入账。

旧 runner-agent 的报告仍可作为界面遥测接收，但不能证明新预约之后已经停止，也不能用作调度容量样本。请先更新接入包并确认采样；指定宿主同样不能绕过容量与健康检查。

## 物理身份与删除

智能体服务器通过保存的密码及已确认指纹执行固定只读 Linux 身份探测；容器服务器由受信 agent 使用固定宿主挂载读取。同一个标准化 machine-id 使用相同 SHA256 摘要，只能归属一条服务器登记，不允许跨角色或跨 workspace 重复计容量。SSH 初始化/安装在任何远程修改之前原子占位；冲突时拒绝，不自动覆盖先前登记。

旧数据不按 IP 自动补登记，首次可信探测竞争成功者建立归属。缺失身份、机器重装导致身份变化或克隆机器拥有相同身份时保守拒绝；需要操作者核实实际机器和保有资源后显式处理登记，不能直接改数据库换归属。删除仅在无保有/未知环境、快照和运行 SSH 作业时允许，并级联释放身份；安装失败但结果未知不自动释放。

没有资源指标的控制器可以继续认证和领取已有指令。心跳字段为 null 时只维持在线状态，不把历史读数当新采样；必须有新完整可信报告才能重新参与调度。

## 容量与未知状态

- 停止、失败残留、待删除仍占默认 5 个保有名额。数量豁免不放宽 CPU、内存、磁盘，也不授予通信权限。
- 内存总承诺不超过宿主 90%；实时可用量也保留总内存 10% 的余量。因此 32 GiB 宿主只剩 3 GiB 时，不再接受新的 2 GiB 预约。
- 已运行容器尚未使用的内存上限继续保留。只有可信采样中已计入实际占用的工作集可抵扣，既不重复扣已用部分，也不把未知用量算成 0。可回收缓存不能抵扣。
- 票据绑定宿主、90 秒有效、单次使用。只有预约之后开始的完整采样可以改变新预约的计算停止状态。迟到的旧报告、超时、容器缺失均不自动解除预约。
- 暂停、重启中、移除中和未知状态不是已确认停止；继续保留计算预约。恢复时仍在原宿主重新准入，不换机双建。
- 磁盘没有可信逐分配字节抵扣时，所有保有预算均从当前空闲盘中保守预留，另留 10% 总盘余量。Docker disk_gb 仍是调度预算；不能代替文件系统强制配额，也不阻止外部进程事后写满盘。

## 尚未提供的运行能力

独立生命周期控制器入口 `python -m app.runtime_v2` 已实现，默认 exit 2 拒绝启动；预览配置与未安装的 systemd 模板见 `infra/runtime-v2/README.md`。只覆盖 create/start/stop/delete 和持久恢复，不能作为完整 Runner 替代。启用需要操作者核验集群；当前没有启用。

每个 host 使用同一份持久 journal，并保留当前 allocation/generation 的全部原始 UID 收据。未知写入不重放；没有原 UID 的 create 不能靠同名对象补认。对象 UID 改变、新指令试图接管替换对象、完成回调丢失后 Pod UID/IP 改变，均保持未确认。独立复审已验证这些边界；不是实际集群可用证明。

Kubernetes/Cilium 双节点验证、完整 exec/文件/快照与可信遥测、正式集群安装、身份网关、DNS/受控出口/公网回流限制与连接撤销尚未完成。公网入口、跨实例权限不能因为数据库批准就显示有效；保持关闭。

两种服务器角色不自动互换。全局物理身份防重已实现，但这不能证明尚未部署的数据面可用；仍须完成独立审查及实际环境验收。

## 回退

暂停新增部署，先核对在途操作，保留实际宿主、未知预约、容器、卷与快照。应用回退优先保留增量数据库结构；0064 先取得身份账本排他锁，非空则拒绝 downgrade，防止并发登记被删除。存在多宿主记录时 0061 downgrade 会拒绝恢复旧唯一约束，不能自动删数据来强行回退。旧 Docker 环境不在本分支切换后端，未来真实迁移另行演练。

具体实际命令见 PROGRESS.md 和 logs/。本地 Docker 28.4 的只读格式测试、官方 kubectl v1.35.10 的 SHA256 校验均不能代替真实双节点网络验收。
