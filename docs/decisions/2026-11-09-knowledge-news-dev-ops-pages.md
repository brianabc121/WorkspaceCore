# 2026-11-09 二批四页改造：知识库、早报、开发者、运维

- 状态：accepted（claude，T-0172 ~ T-0177；人类在对话中要求按 codex 的方案“根据效果图和开发文档进行全面落实”）
- 方案：`docs/v2/pages-redesign-2/`（规范、实施计划、效果图）

## 背景

方案要求四页“统计可核验、失败可解释”：页面上的数字要么来自服务端的全量统计，要么明确写“当前已加载 / 已同步范围”；
不知道的显示未知，不用 0 冒充；效果图里没有数据来源的元素不做。本记录写下实现时定下的口径与有意的差异，
接口细节见 `docs/api-contract.md`，风险与缓解见 `docs/threat-model.md`。

## 决定

### 知识库（T-0172 / T-0173）

- 新增 `GET /api/v1/knowledge/overview`：笔记、知识库、关联、本周更新四个数都是全量统计（批量聚合 SQL，不受图谱 2000 篇上限与分页影响）。
  - 关联按有向 (源, 目标) 去重，两端都要是未删除的笔记；选了知识库时至少一端在库里；任务、项目、书签、图片不算。
  - 本周按界面显示时区的周一 00:00 到下周一 00:00，由前端算好传 UTC；页面打开期间跨过周一不自动换周。
  - 只读：不写版本、审计、智能体阅读用量。唯一的写入是首次访问时补建知识库（与 `/spaces` 相同的机制）。
- 前端路由：`/knowledge` 改为知识总览，完整图谱移到 `/knowledge/graph`；旧链接 `/knowledge?focus=<id>` 转到完整图谱，其余查询参数照带。
- 局部关联图复用现有 `KbForceGraph`（圆点加标题），不引入效果图里的标签框画法；卸载时停止力模拟、移除监听。

### 早报（T-0174）

- 只改前端模块 `apps/web/src/modules/news`；不新增接口、不改生成流程，刷新只重新读取（GET），不生成、不推送。
- 正文先整篇安全渲染，再按真实标题分节；至少两节才编号。没有标题就显示整段正文，**不硬凑“今天值得关注的 3 件事”**。
- 每节的来源只取这一节正文里的 http(s) 链接；收藏 / 不感兴趣只放在真实资讯条目上，不放在正文段落上。
- 侧栏“本期概况”只数当前已加载的条目与来源（标“当前已加载”）；**不显示“重复报道已合并”**（没有对应字段）。
- 早报四种状态分开显示，只有 complete 写“整理完成”；TrendRadar 故障只影响“相关资讯”，正文照常显示。

### 开发者（T-0175 / T-0176）

- 新增 `GET /api/v1/developer/overview` 与 `GET /api/v1/developer/repos/{id}/permissions`，只读本地投影，不访问 GitHub、不触发同步或测试连接。
- 统计标题为“已同步范围”；不能确定时为 `null` 并标 `partial`，页面显示“—”，不拿已知子集冒充全量。
  - 开放 PR 排除 merged / closed；**“待审 PR”改为“开放 PR”**，只有 `requested_reviewers` 非空才标“已请求审查”，不推断审查结果。
  - 失败运行只算 `completed` 且 `failure / timed_out`，按 `source_updated_at` 归窗，同一个 run 只计一次。
  - 同步时在仓库投影里记下被拒的资源类型（`denied_kinds`），只缺 Actions 的仓库不会把 Issue / PR 数也变成未知；没有这个字段的旧数据三类都按未知处理。
- **PR 不显示 CI 状态**：投影里没有每个 PR 与 Actions 运行的可靠关联（只有 run 的 head_sha），不伪造“CI 通过”。
- 最近更新标明时间依据：`source_updated_at` 写“更新于”，只有同步时间时写“同步于”；不编造“新建 / 已完成”等动作。
- 权限快照存在 `Integration.settings_json['github_permission_evidence']`（不新增表）：只存管理员测试连接时实际执行的检查结果与时间，没执行的是“未核验”；
  Token、仓库清单、启停变化或 Token 被拒时清除；限流时保留之前的合法结果与时间。不存 Token、请求头或错误原文。

### 运维（T-0177）

- 只用现有接口；服务分正常 / 需关注 / 未检查 / 未配置四组计数，停用的模块不算故障，列表异常优先。
- `formatMetricValue`：null→“—”、req/s、秒→毫秒、比例→百分比、count 原样；缺测不补 0，折线断开；多序列各自绘制，不跨序列平均 P95。
- 存储读写自检只在有权用户显式点击时调用，进页、刷新、切范围、定时刷新都不调用；无副本显示“未配置副本”。
- **没有 last_success 字段就不显示“上次成功”**；效果图里“查看检查结果”“查看存储设置”没有对应能力，没做。

### 宽版内容区

开发者、运维加入宽版内容区（`router.ts` 的 `WIDE_PAGES`）；早报是模块，在模块路由的 `meta.wide` 里声明；知识库是独立页面，用自己的布局。

## 不做 / 留待以后

- 1024–1439px 宽度下知识库详情、开发者侧栏、运维服务详情排在主区下方，没有做成规范里的抽屉。
- 每个 PR 的 CI 关联、GitHub 侧的审查结论：需要新的同步字段（head_sha 与 check runs），另立任务。
- 早报的事件去重、AI 摘要的结构化协议：需要改生成流程，不在本批范围。
