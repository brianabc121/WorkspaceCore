# 插拔式模块：清单、注册表、按工作空间启用（T-0158 ~ T-0161）

- 状态：accepted（人类 2026-11-08 在对话中要求「根据这份方案进行落实代码」，方案见 `docs/v2/MODULES_PLAN.md`）
- 范围：只影响 claude 自己任务范围内的代码组织；不改协作协议（`docs/AGENTS.md` 1~7 节）、不改项目规则（第 8 节）。
- 开发指南：`docs/modules/README.md`

## 背景

新闻早报（T-0153 ~ T-0155）除了自己的文件，还改了 29 个公共文件：路由列表、模型导入、工具清单与 if 判断、
worker 任务表、事件主题、小组件注册、导航、路由映射、事件映射、运维检查、凭证轮换、访问日志脱敏表……
移除 Vikunja（T-0082）和 n8n（T-0149）也各花了一整个任务去找这些引用。人类要求以后新增功能能“插拔”，
可以是插件，也可以是二级分类页。

## 决定

1. **模块 = 两个文件夹 + 一份清单**：后端 `services/api/app/modules/<key>/manifest.py`，前端 `apps/web/src/modules/<key>/index.ts`；
   后端 `app/modules/registry.py`、前端 `src/modules/registry.ts` 各登记一行。宿主只经注册表接线。
2. **清单是纯数据**：字段写名字、开关和 `"包.模块:属性"` 导入路径，宿主在需要某个扩展点时才解析（`app.modules.base.resolve`）。
   这样任何地方都能安全导入清单，避免了工具清单 ↔ 模块之间的循环导入（借 VS Code `contributes`、Backstage 扩展点的思路）。
3. **扩展点**：页面接口、内部接口、ORM 模型、智能体工具（ToolSpec + 读工具处理函数 + 额外可见条件）、定时任务、
   运维服务检查、凭证轮换的加密列、访问日志脱敏参数、事件主题、首页小组件。事件主题和小组件类型仍要写在宿主的静态类型里
   （它们进 OpenAPI，前端据此生成类型），清单再声明一次，由一致性测试保证一致。
4. **按工作空间启用**：新表 `workspace.workspace_modules`（迁移 0049）；没有记录时按清单的 `default_enabled`。
   只有 owner 能启用 / 停用（`PATCH /api/v1/modules/{key}`），写审计 `module.enabled` / `module.disabled`，发 `modules` 事件。
   有依赖关系时返回 409 `MODULE_DEPENDENCY`。
5. **停用时宿主统一拦截**：模块的每个页面接口自动加 `require_module(key)`，停用时 404 `MODULE_DISABLED`（先做成员检查，
   不是成员仍是 404 NOT_FOUND）；工具不列出、调用返回 NOT_FOUND；运维页不显示它的外部服务。内部接口、定时任务由模块自己检查
   （新闻早报在 `enabled_row()` 里检查，接收地址和 tick 都随之停止）。停用不删数据。模块可以声明 `on_toggle` 钩子：新闻早报停用后重新生成 TrendRadar 配置，不再往手机推送。
6. **部署前提只提示不阻止**：清单的 `requires` 是 Settings 属性名，为空时应用中心显示“需要先部署”；模块页面自己显示未部署状态。
   （方案文档原写“满足后才能启用”，改为只提示：新闻早报迁成模块前，没部署 TrendRadar 时早报页也能打开并提示未部署，
   保持这个行为。）
7. **迁移仍是一条链**：内置模块随版本一起发布，表在升级时就建好，启用只是开关；不用 Alembic 分支（CI 的单 head 检查、
   备份恢复都更简单）。从代码里移除模块要写删表迁移，不可逆，按 D-0004 第 3 节先问人类。
8. **不做运行时安装第三方代码**：插件代码仍经 PR 进仓库、跑 CI；外部应用协议（T-0162）等第一个真实需求再做。
9. **现有核心功能不强制迁移**：新闻早报作为试点迁成模块（`default_enabled=True`，行为不变）；其余功能改到时再顺手迁。

## 被否决的做法

- **按模块的 Alembic 分支**：只有模块单独安装时才有意义，现在只增加复杂度。
- **把注册表做成 Python entry points / 目录扫描**：显式列表更容易审查，也不会因为多放一个文件夹就悄悄启用。
- **微前端（Module Federation 等）**：一个人维护的自托管系统，复杂度不划算；前端模块用按需加载的路由即可。
- **启用记录放进每个模块自己的设置表**：每个模块各写一套开关正是现在的问题；新闻早报自己的“推送开关”仍保留在 `news_settings`，
  与模块启用是两层（模块停用时推送开关视为关闭）。

## 验证

- `services/api/tests/test_modules.py`：清单格式、接口 / 内部接口前缀、工具名与处理函数、事件主题、小组件类型、
  脱敏路径、定时任务与服务检查登记；所有模块接口在停用时都返回 `MODULE_DISABLED`；启用 / 停用的权限、审计、幂等、依赖；
  停用新闻早报后页面接口、工具、接收地址、定时任务都不再生效，再启用设置原样还在。
- 新闻早报原有的接口测试、配置测试、迁移测试全部照常通过。
