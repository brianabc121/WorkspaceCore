| **V2：实例凭证泄露** | 只存哈希、绑定入口、外网加双向证书、一键停用 | 实例令牌只存 SHA-256，绑定登记时的入口（内网 / 外网），用错入口一律 401；外网模式还要客户端证书（工作台内部 CA 签发，90 天），吊销按证书指纹立即生效、不依赖 CRL；重新生成接入包时旧凭证再保留 24 小时；停用实例或关掉工作空间的总开关后，认证立即失败并强制 IM 下线；最近使用时间与 IP 可查；外网入口按 IP 限制认证失败次数。端到端场景 6、7 |
| **V2：OpenClaw 主机被攻破** | 损失限定在授权范围 | 只能取到授权给这个实例的密钥（每次取用都记录，`agent_secret_accesses`），只能调它 `scope` 内的工具，写操作要人工审批；接入网关只放行白名单路由，校验请求体里的用户 / 会话属于这个实例；停用后 MCP、取密钥、IM 立即失效（场景 6） |
| **V2：工作台被攻破 / 密钥库泄露** | 加密存储、可轮换、管理员 API 不返回明文 | 密钥值只存 `enc:v1:<key_id>:` 密文（AES-256-GCM，用途绑定到密钥与版本），轮换后旧版本的密文立即销毁；凭证加密密钥可轮换（`rotate_credentials`，`docs/deployment.md` 第 6.1 节）；管理员接口只返回元数据；OpenIM 的 `secret` 与 imAdmin 令牌只在服务器端；内部 CA 私钥只以密文存在数据库 |
| **V2：OpenIM 接口的权限缺陷** | 实例的请求必须经接入网关；浏览器不直连 OpenIM | 使用打过补丁的 OpenIM 镜像（修复会话、搜索等接口不检查调用者，OC-0 ADR 第 4 节）；实例的 REST 请求经接入网关 `/im/api/*`：只放行 SDK 登录同步与收发要用的路由，并校验请求体里的用户 ID 等于令牌的用户、查询对象属于本工作空间或本群（T-0059 补了好友申请、好友资料、群成员三个查询的校验）；改会话、搜消息、管理接口、拉别人的消息一律 404（场景 8）；管理员的 IM 全部经工作台 API 代理 |
| **V2：OpenIM 回调伪造** | 内部网络、随机路径、限定来源 | 回调只从 `im` 内部网络到达，地址里有随机口令（日志记成 `***`），只接受 openim-server 固定地址的请求；处理时只信任回调里的 ID，消息内容以 `pull_msg_by_seq` 拉回的为准；周期对账（30 秒增量、每天全量）兜底，丢失的回调也能补回（场景 12） |
| **V2：实例之间串通 / 群聊刷屏** | 禁止实例单聊；群聊防刷屏 | before 回调拒收实例之间的单聊（场景 11）；群里只有被 @ 的实例回复；实例连续发言达到上限（默认 8 条）自动暂停接力，并通知管理员，管理员发言后恢复；每个实例每分钟条数有上限（默认 6 条，场景 3）；可关闭“实例 @ 实例”的接力；实例只在被 @ 时回复（`requireMention`），只接受接入包生成时的管理员与本工作空间实例的消息（`inboundWhitelist`）；群里诱导一个实例去让另一个实例删除数据，没有审批不会执行（场景 10） |
| **V2：删好友、越权建群** | 接入网关拦截，回调后补回 | 接入网关拦截删好友、建群等接口（场景 5，`test_im_gateway.py`）；绕过网关删除好友后，after 回调触发自动补回并告警管理员（`im_friend_restored`） |
| **V2：外链图片（SSRF、追踪）** | 服务器端不抓取；浏览器端不自动加载 | 工作台不抓取消息里的外部图片地址；浏览器只显示“外部图片未加载”和地址文字；工作台自己的图片经 API 代理读取（上传者本人或能看到会话的管理员），实例经接入入口读取已发出的图片 |
| **V2：跨工作空间泄露** | 会话、消息、密钥、工具结果不跨工作空间 | 实例、凭证、密钥授权用 `(workspace_id, …)` 复合外键绑定同一工作空间；IM 会话按管理员与工作空间分开；工具调用记录只在所属工作空间可见（`test_records_stay_in_their_workspace`）；接入网关只允许访问本工作空间的 IM 账号 |
| **V2：供应链（OpenClaw、插件、OpenIM）** | 镜像锁定 digest；插件锁定版本；只允许一个插件 | OpenClaw 与 OpenIM 镜像按 tag + digest 锁定；`@openim/openclaw-channel` 锁定 0.3.3 并核对 tarball 的 sha256，CI 的 deps 任务重新下载核对并扫描（`tests/e2e/openclaw_plugin_review.py`），升级前按 `infra/openclaw/README.md` 重新审查；`plugins.allow` 只有 `openclaw-channel`；ci-security 的镜像扫描覆盖 OpenIM 的依赖镜像、agent-gateway、OpenClaw 与 ghostunnel（第三方只报告），OpenIM 补丁镜像由 ci-openim 扫描（有修复的严重漏洞就失败） |
| **知识库：智能体直接读写删（不审批）** | 人类 2026-11-03 决定不审批；仍做工作台的权限与策略校验 | `knowledge_write` / `knowledge_delete` 的风险等级是 `knowledge`：不进审批，但照样经过 `AiToolService.check`（实例 `scope` 要 read_write、角色不低于 member）和知识库权限（公共库按 `agent_access`，项目库只有参与的智能体，别人的库最多只读），每次调用都有记录。每次写入留完整版本，删除进回收站 30 天，人可以一键撤销或恢复，撤销原因写回智能体的《收到的纠正》。每个实例每小时最多写 20 次、删 5 篇，删除超限自动暂停并通知管理员；单篇 20 KB、每库 5000 篇；项目简报只有人能改；管理员可以关掉某个智能体的写入（T-0098；真实 OpenClaw 验收是场景 15） |
| **知识库：笔记里的 Prompt Injection** | 内容是资料，不是指令 | 笔记标题与正文放在工具结果的 `untrusted` 里，工具描述与复盘提示词都写明只当资料；`notices` 只用工作台写的固定文字（例如简报提醒只带 `project_id` 和版本号，不带人填的项目名）；智能体的通用 `search` 工具不搜笔记；“人已确认”和“有冲突”标记帮助判断可信度（T-0098、T-0100） |
| **知识库：密钥写进知识库** | 拦截，不入库 | 人和智能体的写入都做密钥扫描（私钥、GitHub / AWS / 模型服务 / Slack 令牌、JWT、Bearer、URL 里的口令、`password=` 一类的赋值），命中就拒绝保存；原文不入库、不进日志，变更记录里的保护记录只写规则名（T-0098） |
| **知识库：跨工作空间、跨项目** | 按工作空间、角色与参与关系限定 | 所有接口按 `X-Workspace-Id` 与角色校验（viewer 只读，member 编辑，owner / admin 管理设置与彻底删除）；智能体只能访问公共库、参与的项目库、自己的库和允许它读的其他智能体的库，跨工作空间返回 `NOT_FOUND`（T-0098） |
| **知识库：每晚复盘定时任务** | 不放宽智能体的工具限制 | 定时任务由运维用 OpenClaw CLI 建（SSH 部署自动执行 `setup-reflection.sh`），智能体自己不能建（接入包的 `tools.deny` 禁用了 `group:automation`）。OpenClaw 给定时任务的 `toolsAllow` 是 `*`，但仍受接入包 `openclaw.json` 的工具限制；CI 验收检查复盘运行时模型拿到的工具只有 IM 发消息与工作台工具。任务在独立会话里运行，不投递到 IM（T-0100） |
| **知识库：浏览器渲染笔记（XSS、追踪）** | 消毒，不自动加载外部资源 | markdown-it 关闭原始 HTML，渲染结果再经独立的 DOMPurify 实例消毒，链接只放行站内地址与 http / https / mailto；外部图片只显示成链接，不自动加载（T-0099） |
| **知识库：提醒智能体读简报** | 不替管理员发消息 | “现在发给它”用已有的 IM 接口、以管理员自己的账号发（带 `Idempotency-Key`，重试不重复）；接入包的 IM 渠道只放行管理员，工作台不自动代发（T-0100） |
| **知识库图片：上传** | 只收图片，限大小与配额，去掉隐私元数据 | member 以上；类型按文件头判断（PNG / JPEG / GIF / WebP），不收 SVG 与伪装的文件；单张上限与每个工作空间的配额（`FILE_MAX_MB` / `FILE_QUOTA_MB`）；JPEG 去掉 EXIF（含定位）只留方向；按内容哈希去重；每个用户每分钟最多 30 张（T-0103） |
| **知识库图片：读取** | 按图片所属的工作空间校验 | 读取地址不带工作空间（`<img>` 带不了请求头），后端按图片所属的工作空间校验当前用户（viewer 以上），不是成员与不存在一样 404；会话 Cookie 是 SameSite=Lax，别的网站嵌入的图片请求不带会话；读到的内容先核对哈希再返回（T-0103） |

| **运行服务器：智能体在容器里执行（例外八）** | 被诱导的智能体逃出容器、打到宿主或别的环境、扫描内网、打到工作台与 OpenClaw、占满服务器 | 默认关闭，owner / admin 按实例打开（审计、通知管理员），关掉时停止它的全部环境；打开后直接执行（`AGENTS.md` 第 8 节例外八），镜像、运行时、用户、网络由智能体决定，非默认选项（`runc` / `kvm` / `root` / 全部外网 / 常驻）通知管理员一次。**宿主保护在 runner-agent 本机强制**（`app/runner_agent/containers.py`，与指令内容无关）：不开特权、不加默认之外的 capability、`no-new-privileges`、`Init`；只挂工作台建的命名数据卷（不挂 socket 与宿主目录）；不用宿主网络 / PID / IPC；内存与 swap 相同、CPU、进程数上限；`user` 是 uid 1000 去掉全部 capability。每个环境一个 `internal` 网络（直连外网不通，实测），出口只经 runner-agent 在这个网络里的地址上的代理（按监听口区分环境，不靠来源地址）：先解析、所有地址都是公网才连、只连检查过的地址（防 DNS 重绑定），私有网段、本机、链路本地（含 169.254.169.254）、工作台与 OpenClaw 地址一律拒绝，不转发 25 端口；模板构建同样连在 internal 网络上经代理，带网址的 `ADD` 与私有地址的镜像仓库拒绝。限额：同时运行的环境数、内存 / CPU / 磁盘合计、每小时 exec、每天运行时长；整台服务器内存不超卖。运行服务器专用、runner-agent 等同 root，按随时可重装对待 |
| **运行服务器：凭证与指令** | 凭证泄露后冒充运行服务器领走密钥、伪造结果、重放指令 | 凭证 `mwr_` 只在接入包里出现一次，工作台只存 SHA-256，重新下载即作废；入口请求头只在请求直接来自接入入口时采用，外网另要客户端证书指纹一致，失败一律 401、外网限速。指令按 `id` 去重、重复回报只认第一次；只能回报自己这台服务器的指令。runner-agent 只执行固定的几种指令，容器参数由它自己按选项生成，指令里不能带任意 Docker 参数；没有工作台标签的容器一律不碰 |
| **运行服务器：密钥注入与输出** | 密钥进日志或数据库、命令输出把密钥带回智能体、注入别人的密钥 | 只能引用密钥库里已授权给这个实例的名称（建模板、建环境时检查，下发时按创建者的授权再解密，授权撤销后不再给）；值不写进 `runner_commands`，只在长轮询响应里出现（`no-store`），每次写取密钥记录；在容器里写到 tmpfs 的 `/run/secrets/<名称>`（0600，属主是环境用户，经 exec 的环境变量传入，不在命令行里）。输出按已知密钥值精确替换后再过密钥扫描，最多存 1 MB、工具只返回最后 16 KB，放在 `untrusted` 里；执行记录里命令截断脱敏、文件只记路径与大小。**容器里的程序能读到注入的密钥**：只给专用、最小权限的密钥；有意编码后带出挡不住，靠出口记录与审计发现 |
| **运行服务器：快照与回收** | 快照里带着登录态、密钥文件，存储被读走就泄露；伪造的运行服务器读写别人的快照；回收把正在用的环境删掉、删掉后数据找不回 | 快照只存“要保存的目录”，**按密钥对待**：每份快照一个随机数据密钥（AES-256-GCM，附加数据“快照 ID:块号”，防换块），数据密钥用凭证密钥封存（用途绑定快照 ID），对象存储里只有密文（测试检查落盘内容里找不到明文、改一个字节解密失败）；读写块的接口只认这台运行服务器自己的环境的快照，上传只在上传中、下载只在就绪时，`no-store`；页面不提供下载。回收不碰被保护的环境与正在执行运行的环境；常驻环境归档、删除前先做快照，快照失败就不归档也不删除（保持停止，通知管理员），数据超过快照上限的只停止不归档；待删除有宽限期（常驻 24 小时，通知管理员并叫醒创建者，可以撤销）；删除后快照再保留 30 天，可以从页面恢复；过期快照、失败或卡住的上传由每分钟检查删掉对象存储里的块 |
