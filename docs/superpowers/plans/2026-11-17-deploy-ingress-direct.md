# 一键部署的智能体直连接入修复

> 执行：按 superpowers:executing-plans 在当前隔离分支完成；人类已要求直接全部完成，不再重复方案确认。

**Goal:** 从一键部署收集、校验并保存智能体访问工作台的真实地址，网站经 Cloudflare 时也能生成直连接入配置。

**Architecture:** 保留现有 Bash 前台提问、回答文件和后台执行结构。域名负责 TLS 身份，`AGENT_PUBLIC_ADDRESS` 负责实际连接；复用现有后端初始化与接入包的 IP 映射，不放宽双向证书。

**Tech Stack:** Bash、Python 标准库、pytest、现有 Docker Compose 配置。

**Spec:** 当前人类要求完善一键部署并重装测试；已核对 `verify.sh`、`agent_ssh_install._verify`、接入包 `_tunnel_hosts`，以及 Cloudflare 官方 network-ports 文档源码。Cloudflare 普通代理不支持 9443。

## 约束

- 不自动从代理后的 DNS 取源站 IP，不把网卡私网地址默认为公网 IP；需要的地址在安装问题中收集，不要求手改 `.env`。
- 已保存的 IP 在再次 connect 时保留；域名模式只有明确输入 `-` 才改用 DNS。无域名模式必须给 IP。
- IP 必须格式正确且非回环、未指定、链路本地或组播；私网 IP 可显式用于已连通的私有网络。
- 后台不提问；老回答缺少必需地址时保留配置并写明待办，不盲目清空地址或声称接入成功。
- 组件仍由原有选择控制，手动证书入口保持不变；不更改业务权限、证书校验、数据、依赖或 workflow。
- 本机 TLS 成功只证明本机入口正常；云安全组及真正远端可达性不可从本机检查推断。
- 正式任务号已向 #235 的登记集成者申请；不自行抢号，不接管 Claude 的集成会话。

## Review Focus

- 已有域名 + 已保存直连地址：重跑不能清空或重签仍有效证书。
- 前台与后台回答一致：域名模式的地址必须随回答文件传入，后台不补问。
- 无域名、显式 DNS、IPv6 与不可用 IP：有效配置保留，错误输入在写入前拒绝。
- 入口启动或 TLS 失败：明确待办，不能先报就绪；成功也不能冒充外网测试。
- 部署的 `.env` 保留 HTTPS 的 Compose 文件设置及其他密钥，日志不输出私钥。
