## 4. 如何验证当前状态
建议用一个独立的 Compose 项目（全新数据卷，不影响已有数据），按 CI 的顺序运行：
```bash
export COMPOSE_PROJECT_NAME=ws-accept HTTP_PORT=18080 CORS_ALLOWED_ORIGINS=http://127.0.0.1:18080 RECONCILE_INTERVAL_MINUTES=1
docker compose up -d --wait && make migrate && make vikunja-up
python3 tests/e2e/sprint1_acceptance.py --base-url http://127.0.0.1:18080   # 需要空库，先跑
python3 tests/e2e/sprint3_acceptance.py --base-url http://127.0.0.1:18080
cd tests/e2e && npm ci && npm run browser:install && node sprint3_browser.cjs http://127.0.0.1:18080
```
预期：每个脚本最后一行都是“全部通过”。`RECONCILE_INTERVAL_MINUTES=1` 让 A09 很快看到结果，不设时最长要等 5 分钟。

日常使用：
1. `make up && make migrate && make vikunja-up && make vikunja-user`
2. 在 Vikunja（http://localhost:3456）的设置里创建 API Token，权限见核验 ADR 第 3 节，再加上 `projects_webhooks`。
3. 在工作台“集成设置”里填服务地址 `http://vikunja:3456` 和这个 Token，保存后测试连接；之后任务页就是 Vikunja 的任务。
