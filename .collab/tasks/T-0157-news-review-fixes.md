# T-0157 新闻早报审查修复：接收地址令牌脱敏、地址解析检查、偏好下限、游标、方案 B 去重、反馈并发

## 目标
人类要求再检查一遍新闻早报。对合并的 brianabc121/WorkspaceCore#173 做了代码审查，逐条核实后修复确认的问题：
接收地址的 token 写进了访问日志；设置里的地址可用 IPv4 简写或解析到内网的域名绕过检查，SMTP 服务器没检查；
存的渠道凭证解不开时保存设置 500；不感兴趣反而把条数很少的主题调多；乱写的游标 500；
方案 B“现在生成一份”与到点的定时可能各写一份；并发的同一条反馈会丢掉排除词。

## 验收标准
- [x] 访问日志里接收地址的 token 换成 `***`
- [x] IPv4 简写、解析到内网或解析不了的域名、指向内部服务的 SMTP 服务器都 422；保存时解析一遍主机名
- [x] 渠道凭证解不开时按未设置处理，重新填可以保存
- [x] 偏好学习：不感兴趣只会让条数变少或不变（不到 3 条的不往上调）
- [x] 不带时区或乱写的游标 422
- [x] “现在生成一份”算当前推送时间段的那一份；还有一份在写时定时不再另写
- [x] 收藏 / 不感兴趣的插入放在保存点里，并发时不影响排除词等其余修改
- [x] 今天、搜索两处对 TrendRadar 的两次查询改为同时进行
- [x] 测试覆盖以上各条；接口契约与威胁模型更新
