**Goal:** Finish Sprint 5 notifications, scoped event invalidation and safe whitelist automation UI.
**Architecture:** Existing Vue3/Pinia/Vue Query + typed BFF. Scoped header notification panel and dashboard card share queries/invalidation; a single app SSE lifecycle invalidates scoped query families. Automation forms and run records use explicit workspace headers and conservative mutation state.

**Spec:** `.collab/tasks/T-0039-sprint-5-frontend-notifications-automati.md`; Sprint 5 contract sections 4–8/10; n8n trigger verification ADR; DEVELOPMENT_SPEC 4/7.5/8.3/10/A16; current OpenAPI; issue #50 C-4.

## Global Constraints
- Only apps/web, optional ci-web and own task log; schema.d.ts untouched, Claude owns backend and tests/e2e.
- Notifications plain text, safe application paths only (reject //, backslashes/control characters and external URLs); unknown type treated normally. Viewer may mark own notifications.
- Notification count and overview summary converge after writes/events; all requests capture user/workspace; old responses must not mutate new scope.
- EventSource same origin workspace_id, native reconnect/Last-Event-ID; every open and visible-page return refreshes active scoped data; unknown topics ignored, reset refreshes all; operations topic includes page/cards.
- SSE failure/unavailability leaves manual refresh, no routine disconnect error. No persistent scheduler or shared Docker (D-0006).
- Automation viewer read only; admin-only connection/whitelist management; member+ trigger. Params enforce type/required/length/choices. Secrets write only and clear after submit/unmount.
- Fresh trigger UUID per confirmed submission; reuse original key+payload only for an explicit network recovery; unknown run never automatically re-triggered. Show fixed reason copy for policy denials.
- Loading/empty/error/unauthorized/stale with original successful timestamps; do not show denied cache; responsive/theme/accessibility.

## Review Focus
- Delayed events, reads and writes from workspace A must not alter workspace B; logout closes SSE and panels.
- First SSE open/reconnect must refresh changes missed before subscription; malformed/unrelated events do not fetch private data for another scope.
- Notification errors/denial cannot become zero unread or expose previous cache; all and single read operations update header/home consistently.
- Trigger timeout/reload must not create a fresh key or silently resubmit; sensitive parameter values never enter persistent storage, logs or run records.
- Permission/connection loss and version conflicts lock write controls until a fresh read; unknown execution status remains visible instead of success/empty.
